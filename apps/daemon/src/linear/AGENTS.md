# apps/daemon/src/linear

- `import.ts` (`createLinearImport`) is From Linear: `POST /projects/:id/integrations/linear/import` opens a Plan session on the project's account whose brief names no team or workspace ("Import Linear issues as tasks. Ask me which issues…"). A project is not linked to a Linear team: it uses its account's Linear sign-in (`docs/architecture/decisions/2026-11-22-linear-needs-no-link.md`). It refuses only on a definite `LinearVia.None` for the account (the row's hint); an unchecked account goes ahead. `GET /projects/:id/integrations` carries `linear: { on, note, blockedBy }` and `PUT` on the same path writes `linear-reporter.<projectId>` (off drops the project's pending rows). `bindings.ts` only reads a part 2 `linear.<projectId>` value (`linearBindingOf`) until the reporter stops asking for it; nothing writes it.
- `reporter-guard.ts` is the Linear reporter's rule, pure: `judgeReporterCall` allows its two report tools, `ToolSearch`, an exact list of Linear reads and a few Linear writes on the linked issue's own id (exact key lists, one `10db` link for the PR, every string through `scanSecrets`), and denies everything else; it never goes to a judge. Linear's tools are known by their server's prefix (`linearToolPrefixes`): `mcp__claude_ai_Linear__` for the claude.ai connector and `mcp__<server>__` (`mcpToolPrefix`) for each `mcp.linear.app` entry. Codex names a server's tool `mcp__<server>__<tool>` too (its hook name is split on `__` in `sessions/codex-refused-calls.ts`, and `test/codex.live.test.ts` calls `mcp__10db__commit`), so the same prefix applies; no signed-in Codex was checked.
- `reporter-events.ts` turns bus events into owed updates (`linear_posts` rows): `subscribeLinearEvents` reads what an event doesn't carry, `linearRowOf` (pure) maps it to rows with a dedupe key, and one `state.write` enqueues them for tasks whose `external` is a Linear link in a project where `reporterBlockedBy` is null (bound, `linear-reporter.<projectId>` on, Your MCP servers on). A run's start and end keys carry the number of Ended rows the workstream already has, so a re-entry dedupes and a Retry posts. A new row is due `REPORT_DELAY_MS` out, or later when the task has a pending row on backoff. `reporter-settings.ts` reads the setting (absent is off); `bindings.ts` writes `{ on: true, note }` on a link and drops the project's pending rows on unlink.
