# apps/daemon/src/linear

- `bindings.ts` (`createLinearBindings`) is a project's Linear binding: the workspace and team a session read through the builder's own sign-in, stored at the app setting `linear.<projectId>` (`LinearBinding`). Link (`POST /projects/:id/integrations/linear/check { teamKey }`) refuses when the project's account has no Linear (`LinearVia.None`, the row's hint) and otherwise opens a visible chat on that account titled "Link Linear team AMP" whose opening message asks the agent to read the workspace with Linear's tools and call 10db's `link_linear_team`. The one check per project is held in memory (a restart drops it); `link_linear_team` writes the binding only from that check's chat, or records a refusal naming the reached workspace when the team is null, then archives the chat shortly after its answer. Unlink is `DELETE /projects/:id/integrations/linear`. `GET /projects/:id/integrations` carries `linear: { binding, check }`.
- `reporter-guard.ts` is the Linear reporter's rule, pure: `judgeReporterCall` allows its report tool, `ToolSearch`, an exact list of Linear reads and a few Linear writes on the linked issue's own id (exact key lists, one `10db` link for the PR, every string through `scanSecrets`), and denies everything else; it never goes to a judge. Linear's tools are known by their server's prefix (`linearToolPrefixes`): `mcp__claude_ai_Linear__` for the claude.ai connector and `mcp__<server>__` (`mcpToolPrefix`) for each `mcp.linear.app` entry. Codex names a server's tool `mcp__<server>__<tool>` too (its hook name is split on `__` in `sessions/codex-refused-calls.ts`, and `test/codex.live.test.ts` calls `mcp__10db__commit`), so the same prefix applies; no signed-in Codex was checked.
- `reporter-events.ts` turns bus events into owed updates (`linear_posts` rows): `subscribeLinearEvents` reads what an event doesn't carry, `linearRowOf` (pure) maps it to rows with a dedupe key, and one `state.write` enqueues them for tasks whose `external` is a Linear link in a project where `reporterBlockedBy` is null (`linear-reporter.<projectId>` on, Your MCP servers on). A run's start and end keys carry the number of Ended rows the workstream already has, so a re-entry dedupes and a Retry posts. A new row is due `REPORT_DELAY_MS` out, or later when the task has a pending row on backoff. `reporter-settings.ts` reads the setting (absent is on); `bindings.ts` writes `{ on: true, note }` on a link and drops the project's pending rows on unlink.
- `reporter.ts` (`createLinearReporter`) is the run. One timer per task, armed at its earliest pending `due_at` (`start` arms from the store, `poke` re-arms); a pickup drops the project's pending rows when `reporterBlockedBy` says so, fails the due rows with the sign-in row's `note` on a checked `LinearVia.None` (an unchecked row goes ahead), and otherwise posts the starter into the task's Reporter conversation (`reporter-conversation.ts`, one per task, owner id the TaskId) and queues it. The session's `spec` (`reporter-owner.ts`) calls `begin`, which takes every row due now (stamping the session) and opens the in-memory `ReporterRun` the guard, `observe` (a seam fed by `tool_call` events through `ExploreLaunch.observeToolCall`) and `report_linear_post` answer from, by session id; a session id with no run is refused. A run settles once, from `onTurnEnded`, from `onState` when the conversation leaves a turn without a turn end (not `IdleWarm`), or from the 15-minute deadline (which stops the conversation first): taken rows still pending are withheld with the guard's first pattern, else failed one by one with `5 min x 2^tries` (6 h cap, `MAX_TRIES` 5), the end's words or "the session ended without recording". The conversation is retired and the task re-armed on a zero-delay clock timer, off the engine's effect chain. `stop` cancels timers and leaves every row as it is. The Reporter conversation is left out of `ExploreEngine.busy()` and the warm cap.
- The reporter's session is the smallest 10db opens: `ToolSearch` only, no agents, plugins, setup or project servers, the account's `mcp.linear.app` entries (and the claude.ai connectors on a plan whose Linear is one or unread), Codex web search off, a read-only lane sandbox (`createReporterPreparer` in `daemon/shape-session-tools.ts`), the Efficient tier at low effort (`daemon/reporter-launch.ts`), and `preToolUse` = `reporter.verdict` (an allowed call is a settled allow). The brief is a stub listing the rows until `reporterBrief` replaces it.
