# apps/daemon/src/status

- `status-service.ts` holds the status line's state: sources call `hold(key, …)` while something pauses work and `release(key)` when it lifts, and it keeps each hold pending for 2 minutes before it is shown and shown for 2 minutes after it lifts (`StatusDto`, served by `GET /status`). It runs on the injected clock's timers, so the edges fire with no client poll, and `onChange` (the daemon emits `status.changed`) runs when the shown set, a shown line's kind or label (not its sentence, whose load changes every sample, nor the busy processes behind it) or the busy level changes. `busy(level, holding, busiest)` takes each load sample's level (the load over the overload limit, 1 being where 10db holds new work) and, while holding, the busiest names; it rounds the level to tenths and tells the client only when the tenth, `holding` or the names change, and never while the level is under 0.5 before and after; the Factory row's status dot (`apps/desktop/src/shell/factory-status.tsx`), which shows from level 1 or a hold, draws from it at once, while the overload's line still waits out the 2 minutes. `stop()` (called as the daemon stops, after the sources) cancels the timers, so none fires into a closed database. It is memory only: a restart starts every hold again, and a source that still holds says so again.
- A source is a hold that ends by itself and asks the builder nothing: the admission load hold (`load/monitor.ts`), an account waiting for its model list (`accounts/model-list-wait.ts`) and the update's shaping hold (`self-update/self-update.ts`). A source never raises a card for it; one that used to withdraws the cards an earlier run left, once, when it is made. What needs the builder to act stays an Inbox ask.
