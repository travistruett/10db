# apps/daemon/src/placement

- `placement/` is pure like `routing/`: `proposePlacement` (task placement spec, P2) says where a new task works. A task whose areas name an entry in the project's `isolate` list, or that has a kind whose `ownCopy` switch is on (migration and dependency are seeded so), gets a separate copy and a stored reason (`touches migrations`: the kind's label in the plural), whatever the caller asked for; any other task takes the placement the caller named, else the project's default, with no reason; local delivery is always shared. Every place a task is built asks it: `createTask` in `daemon/services.ts` (the task API and the builder MCP's `create_task`) and an accepted proposal in `inbox/service.ts`. The builder's later override is a placement patch (`patchTask`), which stores the reason `chosen by the builder`. It imports `@10db/contracts` only. `placementAfterEdit` asks the same rule for a task whose areas or kinds changed: the builder's patch (`patchTask` in `daemon/services.ts`) and sizing both call it, and `placementRuleMoves` (db) says whether the answer would move the task.
