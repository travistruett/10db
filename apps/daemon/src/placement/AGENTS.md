# apps/daemon/src/placement

- `placement/` is pure like `routing/`: `proposePlacement` (task placement spec, P2) says where a new task works. A task whose areas name an entry in the project's `isolate` list, or whose risk tags include migration or dependency, gets a separate copy and a stored reason (`touches migrations`), whatever the caller asked for; any other task takes the placement the caller named, else the project's default, with no reason; local delivery is always shared. Every place a task is built asks it: `createTask` in `daemon/services.ts` (the task API and the builder MCP's `create_task`) and an accepted proposal in `inbox/service.ts`. The builder's later override is a placement patch (`patchTask`), which stores the reason `chosen by the builder`. It imports `@10db/contracts` only.
