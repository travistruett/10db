# apps/daemon/src/knowledge

- `knowledge/` owns the knowledge rules (spec §9), in the first tier so `briefing/` and `shape/` can import it: which records apply to a task (`scope.ts`), the context pack's packer (`pack.ts`: confirmed policies in scope, then heuristics, then the decisions relevant to the task, filled greedily into `CONTEXT_PACK_BUDGET_TOKENS` estimated tokens; beliefs are never packed; for one topic key only the most specific record enters), and how a pack reads as text (`render.ts`: `renderRules` and `renderDecisions`, one line per record with its id and scope, which the bootstrap prompt, the post-compaction re-injection and the Plan sessions' principles brief all use). `brief.ts` builds that brief (`principlesBrief`: the builder-wide and project policies and heuristics, packed as a lane's are, with no area and no decisions); a Plan session with nothing to resume starts with it, a new conversation's and one moved on at 70% alike (`decisions/2026-11-03-convert-writes-principles-confirmed-and-stores-questions-under-their-goal-or-task.md`). `areas.ts` reads a workstream's areas (its task's plus its live area claims) through `@10db/db`. `scope.ts`, `pack.ts` and `render.ts` are pure and import `@10db/contracts` only; no file here imports another daemon module. A record's state is derived on read, so a superseded, retired, withdrawn or proposed record never reaches a pack (`decisions/2026-11-03-the-context-pack-is-budgeted-in-tokens-by-shelf.md`).
