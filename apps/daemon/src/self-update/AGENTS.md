# apps/daemon/src/self-update

- `self-update/` makes the installed app follow `main` (`decisions/2026-11-03-app-follows-main-by-itself.md`). `createSelfUpdate` polls once a minute, asks `githubHeadOfMain` and `githubMainIsAhead` for main's head and whether it is ahead of the running commit, and only then stages a build (`install-app.sh --stage --running`: the newest finished build, as `make install-app` picks it, never an older one) and, when `midSessionWork` (`countMidSession` plus `DeliveryJobs.pending()` plus `ShapeService.turnsInProgress()`, a shaping turn running or queued) is 0, holds the scheduler back (`pause` is `stop()` then `await idle()`, because a tick can be inside `branchSnapshot`; `Scheduler.stop()` also keeps that tick from launching), looks again, and starts `install-app.sh --apply --quit-first --relaunch` detached. From the pause on, every way out but the install starting resumes the scheduler (`install` and `notStarted`): a throw is a failed `start-install` with its card, never a scheduler left stopped. What it follows is fixed when the app is built: `scripts/build.ts` writes `GITHUB_REPOSITORY` and `GITHUB_SHA` to `build-info.json` (`readBuildInfo`); no project, checkout, origin or `app_settings` value names the repository. The only setting is the app-wide `self_update.enabled` (on until the builder turns it off), served at `/settings/self-update`. Shutdown calls `SelfUpdate.stop()` first, so a check under way cannot start the scheduler again, and awaits it beside the delivery jobs. The install script runs outside any sandbox: `script-installer.ts` starts it with `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, `TENDB_INSTALL_GH` set to the gh `resolveGh` found, `GH_REPO` set to the pinned repository and the login environment minus `PATH`, `BASH_ENV`, `ENV`, `DYLD_*`, `LD_*` and `TENDB_INSTALL_*`; the script runs gh only as `$TENDB_INSTALL_GH`. A new call in the script goes through those rules, never a `PATH` lookup and never an input from a checkout. A shaping turn is no lane, so the status names it: `midSession.shapes` lists `ShapeService.runningTurns()` (the turns `turnsInProgress` counts, less those a hold parked), Settings and the factory note say which conversation the drain waits for, and when only such turns have held a drain for `SHAPE_HOLD_ALERT_MS` (5 minutes) `createSelfUpdate` raises one `self-update-shape-turn` card naming them; it and Settings give the same way out (`SHAPE_HOLD_WAY_OUT`: Stop, and the switch or a quit for a session that ignores the interrupt). The card resolves when a lane also holds the drain, the drain ends, or the install can start, and `settle` resolves one left by an earlier run, whose hold died with it. Tests wait on conditions (the head-check counter, the inbox, `Scheduler.idle()`), never on a sleep; the real scheduler is used where a lane must not start (`scheduler/scheduler.test.ts`).
