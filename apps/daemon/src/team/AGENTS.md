# apps/daemon/src/team

- `team/` seeds the team configuration at start and turns a task into its stored step plan. Read the step a workstream is on with `currentStep` from `@10db/contracts`. Daemon tests get profiles from `test/seed-profiles.ts` (the catalogue fixture, ranked like a real one) and invented measurements from `test/catalogue.ts`; `seedTeam` writes no model profile, flow, pattern or role setting. `routingInputs` (`team/routing-inputs.ts`) gathers what `chooseModel` reads for a project: its account's profiles, tier overrides and list; `playbookInputs` gathers the kinds and the playbook overrides.
- The routing tables the playbook replaced (`flows`, `patterns`, `role_settings`, `team_bindings`, a persona's `minimum_score` and `model_pin`, a task's and project's `flow_id`, a task's `risk_tags`) stay, written by nothing: no route, service or seed reads or writes them. Only `readLegacyRouting` (`packages/db/src/store/legacy-routing.ts`) reads them, for the move in `team/move-*.ts`, which runs once at start. `PATCH /tasks/:taskId` takes `modelSetting` (null removes the override). A new install seeds no flow, pattern or role setting.
