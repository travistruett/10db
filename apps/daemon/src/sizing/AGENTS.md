# apps/daemon/src/sizing

- `sizing/` sizes a task that has not started: its kinds by rules, and its rigor and the kinds the rules did not settle by the judge (`task_rigor` once, `task_kinds` once per kind, answered `yes` or `no`). `sizeByRules` (`rules.ts`, pure) keeps the kinds the builder or an agent gave, adds each kind whose `impliedBy` names one of the task's areas (from `rules`) unless the builder took it off (`kindsOff`), then the judge's kinds; it never produces a rigor of its own, so a task the rules raise keeps no stored rigor and `effectiveRigor` lifts it by its kinds. `sizingFingerprint` hashes the title, description, criteria, areas and goal; a task is sized again only when it differs from the task's `sized_for`.
- `createSizingService` listens to `task.created` and `task.changed`. A task that is open, has no workstream and is not in a pass is sized by rules at once, in one write through `applyTaskSizing` (a judged rigor for older text is dropped, and the placement rule is asked again unless the task's join into a batch is pending, `starter.joiningProblem`). Then, with the judge on, an account picked for decisions and the decision switched on, it is queued for the judge: at most 4 judge calls in flight across all tasks, oldest first; a call ending hands its slot straight to the next one waiting, and a call whose task's text changed while it waited, or that waited past a stop, is never made. A CI fix and a pass page start at once, so they are never queued (they have a workstream or a pass by the time the event arrives). A kind the builder or an agent gave, took off, or that the rules imply is not asked; a pinned rigor is not asked.
- The judge's state is the title, description, criteria, areas and goal title, fenced as data (`judge-sizing.ts`, the fence duplicated from `runner/forced-review.ts` because the runner sits above this module). Answers apply in one write only if the task is still open and unstarted, its text has the same fingerprint and its pins (rigor pinned, pinned kind keys, `kindsOff`) are those the calls were made under; otherwise each answered call is recorded `stopped` and nothing is applied. An answer below the decision's floor, or a fallback, leaves the rules' value. Only calls that acted are stored in `sizing_calls`, so `sizedByRules` is true until one did. A listener never throws into the bus, and a throwing judge never fails task creation.
- `settled(taskIds, timeoutMs)` resolves when the tasks' sizing in flight has ended or at the timeout on the injected clock (`JUDGE_TIMEOUT_MS` from `@10db/contracts`, 4 s, the judge's own cutoff; `DaemonOptions.sizingWaitMs`). `services.settleSizing` is that wait, awaited at the very top of `POST /tasks/:taskId/start`, `POST /projects/:projectId/batches` and the builder MCP's `start_task`, before any read. Automatic starts (a page moved to a copy, a CI fix, an Inbox start card) don't wait.
- A task queued for the judge carries `sizing_owed_for`, the fingerprint it owes an answer for, set in the same write as the rules' sizing (`applyTaskSizing`'s `owedFor`) and only for a task actually queued (never in the sweep's write for a task older than 24 hours). Every end of the judge's work clears it in its own write while it still equals that fingerprint (`clearSizingOwed`): answers applied, a fallback other than a stop, nothing to ask, the task no longer sizable, text or pins changed. A job ended by `stop()` writes nothing, so the debt stays; `sweep()` then asks again (`listOwedTasks`) for each open, unstarted task whose debt was recorded (the task last written) in the last 24 hours and whose current fingerprint is the one owed, and forgives the rest. A judge that throws leaves the debt for the next start.
