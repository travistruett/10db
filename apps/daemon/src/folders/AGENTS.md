# apps/daemon/src/folders

- `folders/` holds gate detection (`gateCandidates`, spec §9.2, pure over files its caller has read) and `inspectFolder` (spec §9.1, `POST /folders/inspect`). Inspection reads the folder and writes nothing: git answers through `Git.inspect` on the unpinned, observed path, which never calls `pinned()` or `onRefused`, so a refusal is an `unreadable` answer and never an Inbox card; `Makefile` and `package.json` are read after an `lstat`, a link or a file over 256 KiB counting as absent. `proposeAreas` (`POST /folders/propose-areas`, `decisions/2026-10-29-propose-areas-from-the-repository.md`) proposes a new project's areas from `Git.survey`'s files and commits, named by the injected `AreaNamer`. The route passes the request's `signal` down: a client that disconnects aborts the namer's `CompletionSpec.signal`, which stops Claude Code, and the model gets `NAMING_MS` before names come from paths. Its globs must match each file as Node's `matchesGlob` does, with no `dot` option: no `*` or `**` matches a dot name, and a pattern with two `**` never matches a dot name in its last part, so `area-candidates.ts` builds each file's glob from where it is held and a randomized test checks every file lands in exactly one area. The Workbench setup (`proposeSetupAreas`, `workbench-setup.ts`) rebuilds an existing project's whole area list from HEAD's object store, never opening a checkout file or running anything: the same structural candidates and history merge (only areas with no role merge; names from paths, no model), each route a page (file routes from `area-candidates.ts`; routes in code from `code-routes.ts`, which reads `router.*`, `routes.*`, `App.*` and `main.*` under a unit's `src/` and resolves each route's component, or what a component defined there renders, to a folder directly under `views/`, `pages/`, `screens/` or `routes/`), each page given the code only it imports (`page-code.ts` over `import-graph.ts`: tsconfig `paths` and `baseUrl`, relative imports, `index.*`, `import()` and `require()` with a literal; at most 5,000 source files of 2 MB, read in batches by `Git.surveyTexts`, every read of one setup within 32 MB (`SETUP_READ_BYTES`), at most 20 router files an app, and up to 20 more of its source files named like a layout, nav, sidebar, menu or shell, as whole words of the file name and never a test, story or e2e file (`navFiles`), read for label guesses only; where two labels claim a route a nav-named file beats another, and a trailing slash is ignored; `surveyTexts` refuses a partial clone (an `extensions.partialClone` key, whatever its value, or a promisor remote, and a config it can't read) before reading a blob, and its object reads run with `GIT_NO_LAZY_FETCH=1`, `GIT_ALLOW_PROTOCOL=none` (which beats a repository's own `protocol.*.allow`), `protocol.allow=never`, no ssh command, credential helper or askpass; a test or story starts no reach; what a layout, or a code-routed app's router and entry, reaches outside the route folders is shared, as is what two pages reach; a page takes a folder only when every source file in it, tests aside, is its alone, else its files one by one), an app's index pages (a route folder's or route group's own `page.*`, `route-pages.ts`) pages of their own at the path they show (`home` at `/`), a screen whose page files only `redirect(` left out as "redirects to another page", a nested route group passed through to its screens, a screen with no page file at its own path a page with no route, a code-routed page named only by a path with a parameter given the longest static start of it the router defines, a relative route path joined to its parent (the object around it, `getParentRoute`, the `<Route>` around it; 20 deep, 500 characters at most), a code-routed page given the label its nav shows (`route-labels.ts`: one linear pass over the router and nav files that reads each object literal holding a `to`, `path` or `href` starting with `/` and a `label` string of 1-40 characters, the first label for a route standing; a page named by its files gets none, and `pageLabel` capitalises its name), a rebuild that finds no page answering the project's own list, a page the project already has (its name matches a page area) never a row, so a label the rebuild adds shows only in the proposed list, a label the builder set winning over the guess and one a kept page lacks taking it, and a kept area that becomes a page carried on its row (`PageRow.was`) so unticking puts it back exactly, the root layout and the source folders pages share marked shared, and the areas open tasks name kept as they are (`rebuild-areas.ts`, pure: a kept area that is exactly a page's route folder becomes that page, its globs only growing). Source text is read by a hand-written linear scanner and router brackets in one pass: no regex with overlapping quantifiers runs over a repository's text. It imports `git`, `github`, `@10db/contracts` and `zod` (for the namer's answer) only; `daemon/` wires it and `api` reaches it through `ApiServices`.
- Broad areas (`broad-areas.ts`, `broadAreaSplit`, pure): an area with no role, not the catch-all, that holds one
  folder whole and has a folder of at least three sibling packages (a child folder with `apps.py`,
  `pyproject.toml`, `setup.py`, `package.json`, `Cargo.toml`, `go.mod` or another manifest directly in it; never
  `__init__.py`, which every Python subpackage has; never under a fixtures, examples or templates folder) that
  hold at least half its files splits into its core, `<area>-shared`, which holds every other file, and one area
  per package (the old name is retired, so no one reads it as the whole folder) (`core`, `common`, `shared`, `lib`, `utils` and the like stay in the core). A new project's proposal
  (`propose-areas.ts`) and the setup's structural areas no task names are split in place; a kept area open tasks
  name is offered as a `SplitRow` the builder ticks, and Apply's `areaSplits` retags its open tasks in the same
  write (`packages/db/AGENTS.md`). New folders under a split root fall to the catch-all.
- `committed-file.ts` (`readCommitted`) reads a repository file for 10db's judge (`trust/call-runs.ts`): its text at
  `refs/remotes/origin/<base>` (`Git.bytesAt`, then `fileAt` to tell a missing path from a link or one over 256
  KiB), given only while the checkout holds the same bytes at that path. The checkout's side finds each part of the
  path by its exact name in its folder's listing and `lstat`s it, so a link anywhere on the path, or a name only
  another case of which is there (the Mac opens `gnumakefile` for `GNUmakefile`), is `differs`; when the base lacks the name too, `differs` names the folder's one such entry, which
  lets `callRuns` pass from make's `makefile` to a committed `Makefile`. A path in neither
  is `absent`; anything else, a git error included, is `differs`. It never throws.
  `dev-services.ts` (`readComposeServices`) reads the compose files at the same base for the judge's environment.
