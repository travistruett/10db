# apps/daemon/src/folders

- `folders/` holds gate detection (`gateCandidates`, spec §9.2, pure over files its caller has read) and `inspectFolder` (spec §9.1, `POST /folders/inspect`). Inspection reads the folder and writes nothing: git answers through `Git.inspect` on the unpinned, observed path, which never calls `pinned()` or `onRefused`, so a refusal is an `unreadable` answer and never an Inbox card; `Makefile` and `package.json` are read after an `lstat`, a link or a file over 256 KiB counting as absent. `proposeAreas` (`POST /folders/propose-areas`, `decisions/2026-10-29-propose-areas-from-the-repository.md`) proposes a new project's areas from `Git.survey`'s files and commits, named by the injected `AreaNamer`. The route passes the request's `signal` down: a client that disconnects aborts the namer's `CompletionSpec.signal`, which stops Claude Code, and the model gets `NAMING_MS` before names come from paths. Its globs must match each file as Node's `matchesGlob` does, with no `dot` option: no `*` or `**` matches a dot name, and a pattern with two `**` never matches a dot name in its last part, so `area-candidates.ts` builds each file's glob from where it is held and a randomized test checks every file lands in exactly one area. The Workbench setup (`proposeSetupAreas`, `workbench-setup.ts`) rebuilds an existing project's whole area list from HEAD's object store, never opening a checkout file or running anything: the same structural candidates and history merge (only areas with no role merge; names from paths, no model), each route a page (file routes from `area-candidates.ts`; routes in code from `code-routes.ts`, which reads `router.*`, `routes.*`, `App.*` and `main.*` under a unit's `src/` and resolves each route's component, or what a component defined there renders, to a folder directly under `views/`, `pages/`, `screens/` or `routes/`), each page given the code only it imports (`page-code.ts` over `import-graph.ts`: tsconfig `paths` and `baseUrl`, relative imports, `index.*`, `import()` and `require()` with a literal; at most 5,000 source files of 2 MB, read in batches by `Git.surveyTexts`, every read of one setup within 32 MB (`SETUP_READ_BYTES`), at most 20 router files an app; `surveyTexts` refuses a partial clone (an `extensions.partialClone` key, whatever its value, or a promisor remote, and a config it can't read) before reading a blob, and its object reads run with `GIT_NO_LAZY_FETCH=1`, `GIT_ALLOW_PROTOCOL=none` (which beats a repository's own `protocol.*.allow`), `protocol.allow=never`, no ssh command, credential helper or askpass; a test or story starts no reach; what a layout, or a code-routed app's router and entry, reaches outside the route folders is shared, as is what two pages reach; a page takes a folder only when every source file in it, tests aside, is its alone, else its files one by one), an app's index pages (a route folder's or route group's own `page.*`, `route-pages.ts`) pages of their own at the path they show (`home` at `/`), a screen whose page files only `redirect(` left out as "redirects to another page", a nested route group passed through to its screens, a screen with no page file at its own path a page with no route, a code-routed page named only by a path with a parameter given the longest static start of it the router defines, a relative route path joined to its parent (the object around it, `getParentRoute`, the `<Route>` around it; 20 deep, 500 characters at most), a rebuild that finds no page answering the project's own list, and a kept area that becomes a page carried on its row (`PageRow.was`) so unticking puts it back exactly, the root layout and the source folders pages share marked shared, and the areas open tasks name kept as they are (`rebuild-areas.ts`, pure: a kept area that is exactly a page's route folder becomes that page, its globs only growing). Source text is read by a hand-written linear scanner and router brackets in one pass: no regex with overlapping quantifiers runs over a repository's text. It imports `git`, `github`, `@10db/contracts` and `zod` (for the namer's answer) only; `daemon/` wires it and `api` reaches it through `ApiServices`.
