# apps/daemon/src/judge

- `judge/` asks a fast model a typed question through OpenRouter for a routine decision (`decisions/2026-10-31-openrouter-makes-routine-decisions.md`). `judge.choose` reads the config (`getJudgeConfig`) and the key of the OpenRouter account decisions run on (`JudgeConfig.accountId`; `createJudgeKeyReader` in `daemon/judge-services.ts`, injected as `readKey(accountId)`: the account's own `account:<id>` Keychain item through `readAccountSecretAsync`, the fingerprint check launches use, so the event loop never waits on `security`; it counts against the 4 s timeout; never cached; no account, an archived or other kind of account, or a missing or changed secret is `no_key`) itself, calls TypeSafe's System One models (`typesafe/*`) on `/api/v1/systemone`, every other model OpenRouter's decision list names on `/api/alpha/decisions`, and any other model on `/api/v1/chat/completions` (`openrouter.ts` cites the shapes; `modelApi` picks; with the list unreadable a model is taken to be a decision model; `decisions/2026-11-13-a-decisions-model-is-picked-from-openrouters-list.md`), parses each response with zod, logs the call to `judge_calls` and never throws: off, no key, a timeout (`JUDGE_TIMEOUT_MS`, 4 s, on the injected clock; it lives in `@10db/contracts` so the Decisions chart's cutoff line is this value), an HTTP error or an unparseable answer is a `fallback` and the caller applies today's rule. A System One or decisions choice's confidence is the chosen option's probability, else its `confidence`, and an answer with neither is a fallback; a chat model's is its own `confidence`. `decision-model-list.ts` reads OpenRouter's decision models (`decision-models.ts` parses them, keyless, `?output_modalities=decisions`) and keeps them 6 hours: a decision never waits for it (routing reads the copy held, or none while the first read runs), an old copy is answered at once and read again behind the caller, and after a failed read none starts for a minute; `GET /judge/models` serves them (409 with the judge off, 502 when unreadable). `PATCH /judge` that changes a decision's model asks the model the test decision with the key decisions will run on first, and refuses the patch when it can't answer (400; 409 with the judge off). The logged outcome of an answer is provisional (`acted` at or above the floor, else `below_floor`); the decision that acts on it records the real one with `recordJudgeOutcome`. The key is scrubbed from error text and is in no response, event, row or log. `GET/PATCH /judge`, `POST /accounts/:id/test` (one tiny call with that OpenRouter account's key: 404 unknown, 400 not OpenRouter, 409 with the judge off) and `GET /judge/calls` are served by `daemon/judge-services.ts`; `accounts/openrouter-key-move.ts` moves a key left in the `openrouter-api-key` item into an OpenRouter account once at start (never throws; with the judge off it is not called); `startDaemon` deletes calls older than 30 days. `Judge.off` is the `TENDB_JUDGE=off` flag: a decision checks it first and makes no `choose` call, so no `fallback_off` row is logged. The runner asks the one decision built, review size (`runner/review-size.ts` holds the rules, which force a review with no call for a binary file or a path in a project hazard, a manifest, lockfile, migration, CI or harness file, and the state, which fences the task text and diff as data and carries only "gate passed (exit 0)"; `RunnerOptions.judge` is injected, `offJudge` in `test/engine.ts` keeps today's rule; a cancel or shutdown aborts the call through `ctl.gateAbort`): see `docs/architecture/01-factory-loop.md`.
- `GET /judge/calls/page` (a `JudgeCallsPageQuery`: limit, offset, decision, outcome; 400 for an unknown decision or outcome) answers one page of the call log with the total of the filter, and `GET /judge/decisions` answers each decision's last 30 days (calls, acted, below the floor, shadow, stopped, fallbacks by reason, cost, median latency, the answers); both are served by `daemon/judge-services.ts` over `judgeDecisionStats` and `pageJudgeCalls`. `GET /judge/models` adds each model's cost per million decisions and time per decision with their source, computed per request from the database and returned as a new list, never into the cached one (`decision-model-numbers.ts`: the builder's own mean logged cost and median latency over 30 days, else the model's input price over the builder's typical decision size, a fixed guess when no call can say, and OpenRouter's median latency from the sync's stored speeds).
