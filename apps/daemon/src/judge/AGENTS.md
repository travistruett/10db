- `GET /judge/calls/page` (a `JudgeCallsPageQuery`: limit, offset, decision, outcome; 400 for an unknown decision or outcome) answers one page of the call log with the total of the filter, and `GET /judge/decisions` answers each decision's last 30 days (calls, acted, below the floor, shadow, stopped, fallbacks by reason, cost, median latency, the answers); both are served by `daemon/judge-services.ts` over `judgeDecisionStats` and `pageJudgeCalls`. `GET /judge/models` adds each model's cost per million decisions and time per decision with their source, computed per request from the database and returned as a new list, never into the cached one (`decision-model-numbers.ts`: the builder's own mean logged cost and median latency over 30 days, else the model's input price over the builder's typical decision size, a fixed guess when no call can say, and OpenRouter's median latency from the sync's stored speeds).
- Decisions run on an OpenRouter, Anthropic API key or Bedrock account (`decisions/2026-11-21-decisions-run-on-any-api-account.md`; `powersDecisions` in `@10db/contracts`; the store refuses a plan login with `PLAN_LOGIN_CANT_DECIDE`). `PATCH /judge` that changes the account sets every decision to the new account's default model (`daemon/decision-offer.ts`: OpenRouter's `typesafe/jev-1.13`, else the Efficient tier model's launch id from the account's list) unless the patch names models the account lists, and saves nothing unless every resulting model answers the test decision; an account with no model list yet is refused. On Anthropic and Bedrock a decision's model is checked against the account's list; `GET /judge/models` serves that list (with the same cost and time numbers) while Decisions run on such an account, else OpenRouter's. `POST /accounts/:id/test` works for any account that powers decisions, on its default model. The status reports no missing secret for a Bedrock account that signs with an AWS profile. `NO_DECISION_CREDENTIAL` is the no-credential detail. Archiving the Decisions account is refused (`archiveAccount`). The benchmarks sync's key is the Decisions account's when it is OpenRouter, else any live OpenRouter account's. `JudgeService.lastFallback(account)` keeps in memory why the account's latest decision call fell back (a rejected key, an expired profile, a timeout), and the judge status carries it as `account.fallback`, which Settings › Decisions shows as "Decisions are falling back to rules: <reason>". A decision's call is priced from the account's own model list (`account_models` price per million tokens, matched on the launch id); with no listed price the cost is null. The Bedrock client of a profile is kept per profile and region, so the SDK's credential cache outlives a call.
- `outage.ts` watches how each decision's call went (`JudgeDeps.onCallHealth`, wired in `startDaemon` to `createJudgeOutageCard` in `inbox/judge-outage-card.ts`). The first failure of a run logs at warn. A failure that won't clear alone (no key, HTTP 401/402/403, Anthropic's "credit balance is too low", an expired Bedrock sign-in) raises one status card at once; any other needs most calls failing over `OUTAGE_WINDOW_MS` (5 minutes: at least `OUTAGE_FAILURES`, 5, failures and more failures than answers), or `OUTAGE_SILENCE_MS` (2 minutes) failing with no answer between, so a tail of slow answers among good ones raises nothing. A failed call's health carries its model and the account's kind. The card, "10db's judge can't answer", folds under `judge-outage`, says "Decisions run on <provider>, <model>." (the provider from the account's kind, else the error text) and names the cause and fix; nothing more is raised while it stays down. It closes after 3 answers in a row, or at once when the judge is switched off (Settings or `TENDB_JUDGE=off`; also once after a start, for a card a stopped daemon left). Nothing is raised again within 30 minutes of closing. One decision switched off reports nothing; only the whole judge off closes the card. A stopped call counts for nothing.
