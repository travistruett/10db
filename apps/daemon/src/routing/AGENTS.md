# apps/daemon/src/routing

- `routing/` is pure: the playbook resolver, AA's Intelligence Index, which every role is routed on (`decisions/2026-11-12-every-role-routes-on-intelligence.md`: AA retired its Coding and Agentic indexes), the router, escalation and step plans over rows its caller passes in. `playbook.ts` (`resolveSteps`) turns a task's effective rigor, kinds and the playbook overrides into each step's persona, requirements (the cell's model setting and each kind override's), effort, need and fallback rung; a kind only adds a requirement or raises the effort, and a step a kind adds that the rigor has no cell for takes the cell of the lowest stronger rigor that runs the role. `choose-model.ts` (`chooseModel`) is the one place that picks a step's model and effort: the task's own setting (and effort pin) alone, else the strongest result of the step's requirements (higher Intelligence; unscored, the higher rung, then price, then effort), with tiers and prices from the profiles (`decisions/2026-11-07-one-function-chooses-a-steps-model.md`). `offeredProfiles(profiles, accountModels, provider)` narrows the profiles to the account's list; routing names no model, so a model is reached only through its tier, its price or a setting. Tiers run weakest first (`pools.ts` `TIERS`); an unscored Critical cell runs the top of Capable and Frontier, and a top pick from Capable with no tier named spans both (`topSpan`), while a named `top_of_tier` stays in its tier. A retry is `escalateStep`; a step whose cell names one model (`pinned`) never steps up. No model reaching a step's need takes the strongest on offer and the reason says so. A step with nothing routable holds a tier name as its `model`, no `profileId` and the setting that decided: the launcher must never launch it.
- Playbook defaults and seeded kinds (built; nothing routes from them yet): `routing/playbook-defaults.ts` holds `DEFAULT_ROWS` (the steps each rigor runs), `DEFAULT_CELLS` (each cell's automatic minimum score, the role's own persona, any effort) and `FALLBACK_RUNG` (the tier, top-or-cheapest and effort a cell runs on when no profile on the account is scored); defaults live in code and the database holds only overrides. `team/seed-kinds.ts` offers the eight kinds (`SEEDED_KINDS`) from `seedTeam`, in its transaction, once, recorded by the app setting `kinds.seeded`, so a kind the builder deletes or edits stays that way and a key the builder already made is kept.
