# apps/daemon/src/guard

- The guard's protected paths (`guard/account-rules.ts`) are the data directory and the default account's sign-in; `startDaemon` builds them once and passes them to the runner and the MCP handler.
- A session's PreToolUse hook answers with `judgePreToolUse` (`guard/pre-tool-use.ts`): the guard's verdict, and `ask` for a call it allows that the broker must still see, whatever the permission mode. In auto mode the classifier settles every call no rule asks about, so these go to the broker: a Bash command that may run a hazard the task hasn't claimed (`hazardHit`, `firstUnread` and `unreadableHazard` in `guard/unread-hazards.ts` over the unclaimed hazards that have commands; `eval`'s words are read again as a command), an endless background loop (whatever is claimed), a Monitor call with an input key beyond command, description and timeout_ms (a Monitor command runs inside the sandbox, so the guard judges it as Bash), every `WebFetch`, `WebSearch`, the MCP resource tools and repo MCP tools, a read the file-access judge would ask about and a write to a Claude Code configuration path (`FileAccessJudge.readAsk`/`writeAsk`). Claude Code sends an `ask` to `canUseTool` past any allow rule and in auto mode (spike rows g and h). It refuses a Bash or Monitor call with a non-empty `allowed_domains`, which in auto mode would let the classifier alone widen the sandbox's hosts with no card (`decisions/2026-10-31-lanes-run-in-auto-mode-inside-the-sandbox.md`). The matcher reads redirections three ways plus a fourth that drops any `<`/`>` word (`redirectionReadings`), tries every later word as a wrapped program (`guard/wrapped-commands.ts`, all words up to 16 and the programs with rules past that), reads `run` aliases and npm/bun aliases as the canonical subcommand (`packageManagerVariants`), and refuses git and gh behind `xargs`/`parallel` always. Two readings let a read-only check through unclaimed hazards: a word the shell fills in after a fixed pnpm program or script (`pnpm exec prettier|eslint|vitest|tsc $F`, `pnpm exec node SCRIPT $F`, `pnpm [--filter PKG] test|lint|typecheck|build|format|check|coverage $F`; `argumentsOnly` in `guard/unread-hazards.ts`, unless a hazard command goes on from those words) is only an argument, while `pnpm $SUB`, `pnpm exec $X`, `pnpm run $S` and `$P add` still ask; and arithmetic over names the command sets only to numbers (digits, `$?`, `$(date +%s)`, `$((…))` over such names; `guard/numeric-names.ts`) is read, unless the command holds a shell, `eval`, `source`, `find` or `xargs` or sets the name another way.
