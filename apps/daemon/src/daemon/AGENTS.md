# apps/daemon/src/daemon

- The Workbench setup's settings (`decisions/2026-11-10-workbench-setup-suggests-settings-from-origins-base.md`): `daemon/suggest-settings.ts` (`suggestSettings`) reads every file from origin's base commit, found once by the exact name `refs/remotes/origin/<base>` (`originBaseCommit`, `Git.remoteTrackingCommit`; never a guessed ref name, which a lane-made branch or tag can answer), never HEAD, which a local-delivery project's lanes write; with no such ref it reads HEAD, suggests no dev login, and suggests Docker only from the builder's own commands. The detectors are pure in `folders/` (`detect-app-address.ts`, `detect-dev-login.ts`, `detect-changed-check.ts`); the live look (`daemon/listening-ports.ts`, lsof, 3 s) and the probe (`daemon/loopback-probe.ts`, one GET, 1 s, no redirect, only `localhost`, `127.0.0.1`, `[::1]`) come in through `DaemonOptions` (`listeners`, `probe`), so a daemon test owns no port. The dev login is the one model question (`askWithin`, `NAMING_MS`), and `devLoginAnswer` keeps only its exact argv shapes with arguments the repository's scripts pass (`devLoginWords`). Allow Docker follows the gate command, a saved turn check, or the scripts at origin a suggested check runs, never 10db's own check text nor the model-written dev login. The branch note counts with `Git.countCommits` and shows `git push origin <base>`; setup never pushes.
- Page labels for projects that had pages before labels existed: `daemon/page-label-guess.ts`. At start, before the API serves, `seedPendingPageLabels` lists every project there is under the app setting `workbench.page_labels_pending`. It does this once; the list only shrinks after, so a project added later is never guessed. `guessPendingPageLabels` then runs beside the start and is aborted at shutdown. For each listed project it runs the Workbench setup's read (`proposeSetupAreas`, HEAD's object store only). It gives each page with no label the label the setup guessed for the page of the same name (`folders/guessed-labels.ts`, pure), and takes the project off the list. A label the builder set is never replaced. A builder's save of a project's areas (`services.patchProject`, which Settings and the setup's Apply both call) takes the project off the list. The guess writes only if the project is still listed inside its write, so areas saved during the read stand. A repository it can't read is logged and stays listed.
- `connect-service.ts` (`createServiceConnector`, `POST /settings/connect/:service`) sets a service up for a project's account in one call. `CONNECTABLE_SERVICES` is the table (server name and address); the route accepts only its keys. It adds the server with the pinned CLI (Codex `mcp add <name> --url`, Claude Code `mcp add --transport http --scope user`) when no server of the builder's has the entry's host, never overwriting a different server of that name; it approves that server through Trust's Approve, and only a server at a table entry's own host; then a Codex account's sign-in starts (`McpSignIns.start`), and a Claude Code account is told to finish with `/mcp`. Each step that already holds is skipped. The CLI runs on the login environment pointed at the builder's home and at no account's folder, and its result is parsed with zod.
