# apps/daemon/src/daemon

- The Workbench setup's settings (`decisions/2026-11-10-workbench-setup-suggests-settings-from-origins-base.md`): `daemon/suggest-settings.ts` (`suggestSettings`) reads every file from origin's base commit, found once by the exact name `refs/remotes/origin/<base>` (`originBaseCommit`, `Git.remoteTrackingCommit`; never a guessed ref name, which a lane-made branch or tag can answer), never HEAD, which a local-delivery project's lanes write; with no such ref it reads HEAD, suggests no dev login, and suggests Docker only from the builder's own commands. The detectors are pure in `folders/` (`detect-app-address.ts`, `detect-dev-login.ts`, `detect-changed-check.ts`); the live look (`daemon/listening-ports.ts`, lsof, 3 s) and the probe (`daemon/loopback-probe.ts`, one GET, 1 s, no redirect, only `localhost`, `127.0.0.1`, `[::1]`) come in through `DaemonOptions` (`listeners`, `probe`), so a daemon test owns no port. The dev login is the one model question (`askWithin`, `NAMING_MS`), and `devLoginAnswer` keeps only its exact argv shapes with arguments the repository's scripts pass (`devLoginWords`). Allow Docker follows the gate command, a saved turn check, or the scripts at origin a suggested check runs, never 10db's own check text nor the model-written dev login. The branch note counts with `Git.countCommits` and shows `git push origin <base>`; setup never pushes.
- Model settings (`daemon/model-settings-services.ts`; `chooseModel` reads them): `GET`/`PUT /model-settings` and `GET`/`PUT /projects/:projectId/model-settings` read and write one scope's role settings and patterns (`ModelSettingsDto`). A `PUT` sets the roles it lists and, when it has `patterns`, replaces that scope's list in the order sent; a null role setting clears the scope's row (a project's role then uses the global one, a global role 10db's default), because Automatic is a setting and an unset role is not. A project's pattern may name only that project's areas (400 otherwise). `PATCH /tasks/:taskId` takes `modelSetting` (null removes the override). `team/seed-patterns.ts` offers the one "High-risk work" pattern once, under the app setting `patterns.seeded`, so a pattern the builder deletes or edits stays so.
