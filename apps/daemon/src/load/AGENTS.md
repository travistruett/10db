# apps/daemon/src/load

- `load/` is the load guard (`decisions/2026-10-30-hold-work-while-the-mac-is-overloaded.md`, levels from `decisions/2026-11-14-one-admission-gate-holds-lanes-on-load-disk-and-a-machine-cap.md`): `guard.ts` declares an overload (load above 2× the cores for 5 minutes, ending below 1.5×) and holds waiters, and `episode()` names the one on now for the admission gate's line; `culprits.ts` reads `ps` and `lsof` and says which gate or lane each busy process belongs to, `monitor.ts` reports the overload to the status service (`status/`) with the busy processes, which the header shows after 2 minutes, and raises no card; it withdraws a `machine-overloaded` card an earlier version left open when it is made. While it is on, the scheduler's `held` launches nothing, the runner's `hold` starts no session or task gate, and `limitGates`' `hold` starts no shipping gate; each hold is an `untilClear(signal)` that a stop ends, with a sync `holding()`. A task's gate waits in the runner, not in `limitGates`, before it takes its batch's turn or a slot, and looks again in its `beforeStart` once it has them, because a gate parked inside the turn keeps a sibling's gate, an install and a migrations claim waiting behind it (`decisions/2026-11-03-app-follows-main-by-itself.md`). The runner records each lane session's temp dir (`laneTempDirs`) so an orphan is named by it. A failed ship gate's card says so through `ShipperDeps.load`. Tests inject `read` and `processes` (`DaemonOptions.load`), never real load. Never read another process's environment.
- `disk.ts` holds new lanes (not gates or ships) while free disk is below the Capacity floor, reading on each `holding()` call, and lets go at the floor plus `CLEAR_MARGIN_BYTES`; it keeps one `machine-disk-low` card on `projectForMachineCard`'s project (`card-project.ts`). A null read never holds. Tests inject `DaemonOptions.disk.freeBytes`; without `DaemonOptions.disk` nothing reads the disk.
- `capacity.ts` is the `capacity` app setting (`machineLaneCap`, `diskFloorGb`), read by the scheduler's cap getter on each tick and by the disk floor. `scheduler/admission.ts` folds the load, the disk and the drain into the scheduler's `held` and words the holds for `GET /admission`.
- `card.ts` says, when `mds_stores`, `mdworker` or `fseventsd` is among the busy processes, that the hand-made worktree folder's two Inbox cards (`delivery/hand-made-worktrees.ts`) are what 10db offers against it.
