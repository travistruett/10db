# apps/daemon/src/test-value

- `test-value/` asks the `test_value` judge decision about each test a run's commits added (`decisions/2026-11-18-a-judge-flags-new-tests-that-duplicate-or-fold-into-existing-ones.md`). `judgeNewTests` (`judge-new-tests.ts`) is the one entry: it asks `judge.ready(TestValue)` first (off, no key or the decision's switch off is no call and no flag), reads the non-merge commits since `baseHead` through `Git.commitMessagesSince` (only the run's own, `commits`, which the runner passes from `runCommits`), takes each test file's diff (`diffSince`, 256 KiB) and its text at that commit (`fileAt`), and builds one `TestValueCase` per added case. It never throws: a git or judge failure is a logged warning and no flags.
- `test-cases.ts` is pure text: it finds `it`/`test`/`it.each(...)('name'` calls by regex (not an AST, so a call built dynamically is not found), takes a case's lines until the closing line at its indent, and treats a case as new only when its name's line is an added line, so a row added to a table is never judged. `valueCardOf` reads the `Value:` paragraph of a message.
- `test-value-ask.ts` is the typed question: options `keep`, `move_cheaper`, and `fold_into_<n>` and `duplicate_of_<n>` for up to 20 neighbours, which the criteria name; `readTestValue` turns an answer into a flag, and anything below the floor, a fallback or a choice that is no option is none. The state is fenced as data (`judge/fenced-text.ts`).
- `test-value-follow-ups.ts` makes the texts: the follow-up task for a flag (`fileTestValueFollowUps` files at most 10 in one write and none for a title already in the project) and the reviewer's brief lines (`testValueBrief`). The runner calls them: `testValueFollowUpsAfter` before the write that ends an implement step passed by the gate (or finished with no gate) files follow-ups only when no Review follows; a Review's first-round start puts the brief in its prompt (`PromptInput.testValue`) and files nothing.
