# apps/daemon/src/benchmarks

- `benchmarks/` syncs Artificial Analysis's free model list with the builder's own key, read from the Keychain (service `10db`, account `artificial-analysis-api-key`). A model's speed is AA's `performance_v3.mean_output_tokens_per_second` (measured under load across short, long and multi-turn agentic workloads, reasoning tokens included); the older `performance` object is ignored, since AA nulls its fields from 2026-12-10. Of AA's evaluations only `artificial_analysis_intelligence_index` is read. AA data stays on the machine: never in logs, fixtures, docs or the repo, and every view of it shows AA's attribution. Tests use invented numbers and an injected `fetch`.
- `openrouter-sync.ts` reads OpenRouter's scores (`openrouter-client.ts`: Artificial Analysis's indexes as OpenRouter relays them, and OpenRouter's own benchmarks) daily and each wanted model's per-provider p50 speed at most hourly, with the key of the account decisions run on (`readKey` is called at the start of every run, before any request, the keyless model list included; no key means no request and the outcome `no_key`). Wanted models are OpenRouter's listed ids that `joinOpenRouterId` places on a model a live account offers, plus the callable decision models (never `~` routers). One pacer allows 20 requests in any 60 s window, counted per HTTP request, on the injected clock. A failed score read keeps the held rows; a failed speed read leaves that model's rows and goes on; `unauthorized` and `rate_limited` end the run, and every non-`ok` outcome is tried again an hour later. `poke()` joins a run in flight and, if the key read since differs, runs once more; `stop()` starts no further request and arms no timer. The status is app setting `openrouter.sync_status` and never holds the key. It is created only with `DaemonOptions.openRouterSync` and neither `judgeOff` nor `benchmarksOff`; `PATCH /judge` that changes the account pokes it. It writes `openrouter_measures` only, never `model_profiles`.
