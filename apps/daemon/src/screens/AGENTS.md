# apps/daemon/src/screens

- `screens/` is Shape's `see_screen` (spec §5.5, `decisions/2026-11-03-plan-sees-the-app-through-screenshots-not-a-browser.md`): `broker.ts` is the rendezvous the app's window long-polls (`POST /screens/claim`) and answers (`/screens/:id/image`, `/refuse`), in memory, so a request writes no row; `screens.ts` asks it, checks the picture by its bytes (`image-check.ts`), keeps it under `<shapes>/<id>/screens/` and writes the transcript rows. `render-access.ts` is what a request's **render token** may do: a GET of a route a screen shows. **Every GET the daemon serves is named there, allowed or refused with a reason** (`api/render-reads.test.ts` fails for one in neither), so a new GET route, a read that writes or runs a command above all, must be classified in the same change. `api` takes it as `ScreenRoutes` in `ApiDeps`; the UI token alone reaches the screen routes.
