# apps/daemon/src/shape

- `shape/` runs a Shape conversation (spec `docs/superpowers/specs/2026-11-02-10db-brainstorm-chat-design.md`, decision `decisions/2026-11-02-shape-session-and-convert.md`). A conversation's session opens through `AgentAdapter.open` with the explore profile (`sessions/claude-session.ts`), not the lane profile: it loads no settings or plugins and has no lane, claim or area (`decisions/2026-11-05-plan-runs-commands-and-project-tools-through-the-lane-broker.md`). `ShapeServiceDeps.prepare` (`daemon/shape-session-tools.ts`, present only with a lane sandbox) gives each session a read-only lane sandbox (`forSession({ readOnly: true })`: the whole checkout in `denyWrite`), the project's approved MCP servers (`inbox/project-mcp-reader.ts` with no workstream) and the lanes' permission broker owned by the conversation (`shapeId`, no workstream, project rules only, `commandsAsk`: every command that reaches it is carded); `release` withdraws its cards, stops what its commands left running (the adapter spawns Plan's Claude Code itself and reports its pid, which `trackProcesses` watches, as a lane's) and disposes the sandbox when the session ends. The servers are read from the launcher's `projectEnv()`, never the session's env; a remote one on a private host (`privateHostProblem`) is left out; a session whose servers' AWS credentials expire within five minutes is closed before the next turn, which resumes it with fresh ones; an unreadable `.mcp.json` or an unbuildable sandbox gives a session with less, named in its first message. `confinement.ts` (`judgeShapeCall`, the PreToolUse hook): a Read, Grep or Glob only on real paths under the checkout or the conversation's files directory (refused, never asked); `Bash` from the session or a `code-researcher` judged by `judgePreToolUse` with no areas, hazards or claims, a read-only command settled and any other `ask`, with background jobs, `nohup`, `setsid`, `disown`, `run_in_background` and `dangerouslyDisableSandbox` refused; a project MCP tool `ask` from the session and refused from any agent; `Agent` only for the three reviewers, the researcher and the code researcher, always in the foreground (`run_in_background: false` through `updatedInput`), with `model` one the account offers (`ShapeAccess.agentModels`); a Shape tool by who is calling (`agent_id`). Without `prepare` the session has no `Bash` and no project server, and the hook refuses both. Each command and project tool call writes a dimmed line naming who made it (`commandLine`). `service.ts` runs the turns one at a time with a queue, ignores a Propose while one is queued or running, answers Convert 409 while a turn runs (`interrupt: true` stops the turn and holds the queue), moves to a fresh session seeded with `digest.ts`'s deterministic digest past 70% of the context, and closes an idle session after 10 minutes (resumed from `shapes.sdk_session_id`). `validate.ts` is pure (every error at once), `rounds.ts` reconciles a `propose_plan` draft with the rows (pins kept, dropped keys refused), `convert.ts` writes goals, loose tasks, additions, changes, removals and decisions in the caller's one transaction and starts nothing, and `undo.ts` is Remove Draft Goal and Withdraw Decision. A change to the confinement must keep the live test (`test/shape-session.live.test.ts`, `TENDB_LIVE_CLAUDE=1`, never in `make gate`) passing; re-run it after each Claude Code or SDK upgrade. `mcp/server.ts` builds a Shape session's tool set from its `sessions.shape_id`, and a session with neither a workstream nor a shape gets 401. `view.ts` is the read model the screen renders (`GET /shapes/:id`: the transcript, every proposal with its typed body and what Convert made of it, the latest `note_heard` items as `heard`, and where the session is as `turn`); the service announces `shape.changed` when a turn starts and ends, since `turn` is in no row. The routes (`/projects/:id/shapes`, `/shapes/:id/{messages,propose,stop,convert}`, `/goals/:id/remove-draft`, `/shapes/:id/decisions/:id/withdraw`) are served by `daemon/shape-services.ts`; Convert answers 400 `{errors}` for a refusal and 409 while a turn runs. `startDaemon` makes the service with the project's account and the `plan` role's model (`launch`), and closes it before the runner stops. A daemon on the fake adapter run from `main.ts` answers a Shape conversation with `scriptedShapeBehaviour` (`sessions/fake-shape.ts`): it echoes what it heard with `note_heard`, and on Propose states one goal with two tasks, two loose tasks and a decision, in the project's first area.
- Shape ceremony, review and rehearsal (slice 4, spec §7, `decisions/2026-11-02-shape-ceremony-review-and-rehearsal.md`): `shape/ceremony.ts` is the rule (loose L, goal XL, more than 5 tasks, a one-way path force `spec`; the builder pins `direct`; the content hash ignores `ceremony`, so pinning it neither re-rehearses nor answers a question). One-way paths are the app setting `shape.oneWayPaths.<projectId>` (`GET/PUT /projects/:id/one-way-paths`); a task is one-way when its area or hazard holds a tracked file (`git ls-files`, cached 30 s) matching a glob. `review.ts` holds `write_spec`, `report_finding` and `resolve_finding`; the reviewer (scope, engineering, rehearsal) is never read from tool input: the PreToolUse hook in `confinement.ts` stamps `reviewer` from the subagent's `agent_type` through `updatedInput`, and `report_finding` with none is refused, so only a subagent can report. A rehearsal's mark is written on a `final` report (a none, or the last question). `service.rehearse` queues a rehearsal turn (a `rehearse` note kind, which Jev's Propose counting ignores) for tasks with no mark at their current hash, and `POST /shapes/:id/findings/:fid/dismiss` is the builder's dismissal; a builder edit answers that task's rehearsal questions. Convert never waits on a finding or question; it warns. `GET /shape-measures` also carries the question-card rates.
- Shape preview, attachments and reopening (slice 5, spec §10.2, §10.3, §12): `shape/preview.ts` (`buildPreview`, carried in `ShapeViewDto.preview`) reads and never writes. The project's running and queued work comes first (a held run, or a task no longer open, holds no lane), each for what is left of its estimate: the hours a conversation derived for it, else the project's median lane time per finished task (the M bucket while none has finished), less its lane time so far, floored at zero. The draft's pending tasks follow, additions included, with their derived hours. `preview-schedule.ts` (`simulateFactory`) is pure: running work keeps its lane, even past a `maxLanes` lowered since; queued work goes next, then the draft, longest chain first; a task starts once its dependencies have ended, a lane is free and no running task claims one of its areas. The critical path runs back from the last task to end through what let each one start, and a clash is an area two tasks claim with nothing ordering them (two pieces of existing work never clash). The end estimate adds the project's median non-lane time per finished task for each draft task on the critical path. `attach.ts` is the session's `attach` tool: a Mermaid diagram, a Vega-Lite chart (`ChartSpec` refuses a `url`, `href`, `src`, `srcset` or `background` key anywhere and requires `data.values`) or an HTML mockup, on a proposal key (a goal's task keys included) or on a goal or task this conversation converted. Each call adds a `shape_attachments` row; the view carries them as `attachments` and leaves out a stored body that no longer parses, and the desktop renders them inert (`apps/desktop/AGENTS.md`). `GET /goals/:id/shape` and `GET /tasks/:id/shape` answer which conversation made a goal or task (`shape_links`), or null, for the drawers' Open conversation. `POST /shapes/:id/resume { event }` (`service.resume`, for the engine's Re-plan in Shape cards) records the event as a note a proposal may cite and queues it for the next turn with each converted row's current state (`converted-state.ts`: a task's status, "not started", or "started" with its run's state, as in "started (queued)"); it starts no turn, and a fresh session's digest carries the same lines. Re-planning is `propose_plan`'s `additions`, `changes` and `removals`; validation allows a change or removal only for a task that has not started, and a successful round moves a converted conversation back to `proposed`.
