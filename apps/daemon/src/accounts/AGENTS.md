# apps/daemon/src/accounts

- `accounts/` owns account pauses (`account_pause.<id>`; usage limit, monthly cap, refused), the monthly cap in local time on the injected clock, readiness and the preparer, staggered subscription starts, the account cards and the account service. The scheduler and the runner ask `AccountRuntime.blocked` before every session start; a cap or refusal pause lets running sessions finish and a usage limit stops them. `limits.ts` acts on a session's usage report: past a project's threshold its lanes hand off and it moves to its usable fallback (ready, not paused, capped when metered), or the builder is asked; at the hard limit a project with a fallback moves at once. Only projects with work in flight move or are asked.
- `accounts/` also moves projects between accounts. `PATCH /projects/:id` and the cards go through `AccountMoves.move` (`moves.ts`), which remembers a move off a usage-limited account; `move-back.ts` moves a project back by itself when the limit that moved it resets (`MoveCause.MoveBack`, a project event naming both accounts; a move the builder made by hand, or one recorded without `moveBackAutomatic`, raises the card instead); `usage-reports.ts` keeps each account's latest report in memory. `Runner.handOff` asks a project's lanes on an account to hand off in the account's own words (`HANDOFF_NUDGE_ACCOUNT`). The runner reads the project's account before each session and never resumes a conversation that ran on another account: `runner/next-action.ts` starts the lane fresh from its handoff.
- `harnessOf(account)` (`@10db/contracts`) is the only question of "does Claude Code or Codex run this account?": the account's stored `settings.harness`, else its kind's first in `HARNESSES_OF_KIND`, null when the kind has none. A site that picks an adapter, a config directory variable (`CODEX_HOME` or `CLAUDE_CONFIG_DIR`), a briefing, a judge floor or a capability asks it (through `accountAgentOf` in `environment/` where it needs the kind beside it) and never tests `AccountKind.CodexSignin`; a test of the kind stays for the credential only (sign-in steps, `credentialsMatch`, `signsInWithLogin`, the ChatGPT login in the Codex home). A kind with no harness (none today) is refused at bind and at launch with `requireHarness`'s message.
- `accounts/` also lists and starts the builder's MCP sign-ins (`mcp-sign-ins.ts`, `GET`/`POST /settings/trust/mcp-sign-ins`). Candidates are the app-wide plan's remote servers that send no headers (`signInCandidates`); each non-archived Codex account × candidate reads `mcpAuthStatus` (15 s per account, cached 60 s, dropped when a sign-in ends) and never shows a `not_oauth` server. One slot per account and server lives in memory only: a second start reopens the page, a failure keeps its message until the next start, `stopAll` cancels every slot on shutdown, and each change sends `mcp_sign_in.changed` with no url. A Claude plan account in its own folder gets a terminal command (`claudeMcpSignInCommand`) instead, since only Claude Code signs it in.
- An OpenRouter account's list is not read from Codex: `list-refresh.ts` passes the identity probe, then reads OpenRouter's models API with the account's key (`fetchToolModels` in `benchmarks/openrouter-client.ts`: tool-capable models with their listed per-million prices) and stores it through `AccountLists.record`; a failed read keeps the last list. `priceSessionAtListing` (`@10db/db`) turns an OpenRouter session's tokens into its cost at the listed price, and the account's month adds the `judge_calls` cost when decisions run on it (`decisions/2026-11-21-openrouter-runs-agents-on-codex.md`). At start `removeLegacyOpenRouterKey` deletes the old `openrouter-api-key` item.
