# apps/daemon/src/github

- `github/` is the only module that runs `gh`, and `git/` the only one that runs `git`; both use `execFile` or `spawn` with argument arrays, never a shell. Network calls (fetch, push, every `gh` call) take a `NetworkCall` built from `environment/buildNetworkEnv`, a timeout and an abort signal, with prompts off. A push gets `pushTimeoutMs`, since it uploads every commit of the batch; fetch and `gh` get `networkTimeoutMs`. Fetch and push run detached in their own process group, and a timeout or abort kills the group. `Gh.prStatus` (`pr view --json url,state,statusCheckRollup`, summarised by the pure `summariseChecks`, each rollup entry parsed on its own so one it can't read makes the checks `unknown` rather than failing the read) reads a pull request's state and checks, and answers null for GitHub's not-found answer to a URL (`Could not resolve to a PullRequest`, or `... a Repository`); `prView` stays the smaller query shipping and the dependency check use. A failed call whose output shows gh never reached GitHub (its DNS line, or Go's `dial tcp`, `i/o timeout`, `connection refused` and the like) is `unreachable` rather than `failed`, for every gh call. Delivery tests fake `gh` with `test/fake-gh.ts` (`setChecks`, `setState`); real git runs against a local bare `origin` (`createTempRepoWithOrigin`).
