# apps/desktop/src/conversation

- `src/conversation/` is the conversation kit (sessions spec §8): `Markdown` (the only place streamdown is configured; `docs/architecture/decisions/2026-11-13-agent-output-renders-as-hardened-markdown.md`), `ConversationList` (windowed by article, one per builder message and one per agent turn, a turn longer than `ARTICLE_ROWS` in parts, tail-following with Jump to Latest, over `ConversationEntry`, a view model each screen maps its DTOs to), `ToolCallCard` (rows from `tool-words.ts`, reads and edits folded and subagent calls nested by `conversation-rows.ts`; edits as one `Diff` per hunk beside `hunk-gutter.ts`'s numbers, from the hunk's own starts). A link opens through `openWebLink` (`docs/architecture/decisions/2026-11-13-the-opener-opens-confirmed-https-links.md`). The kit never compares a harness id (ESLint). `e2e/window-csp.spec.ts` draws a Plan fence in WebKit under a script policy with no eval or WebAssembly. `Composer` takes a screen's own controls (`leading`, `actions`, `modelControl`, `notes` under the hint) and Attach's name; pictures wait in the draft until Send, or, with `uploads` (Plan's documents), each dropped, pasted or picked file goes to the screen at once and the screen keeps the refusals, which show as an alert; Send takes what it sends out of the input as it is pressed (`afterSend`) and a send that fails puts it back ahead of what was typed since, against the draft as it stands then (`onDraft` takes a `DraftChange`), so words typed on its way stay; a send on its way keeps Send's spinner; a Stop on its way never holds a send back; Enter sends, Shift+Enter is a new line and Enter picks from an open `@` or `/` list (`isSendKey`); Send is a small ↵ icon and Stop an icon while a turn runs; `DictationButton` starts macOS Dictation through the shell's `start_dictation` command (the `startDictation:` action down the responder chain, no Accessibility permission) and shows only in the desktop shell; `ModelMenu` (model chip, Effort submenu, More models) and `ContextRing` are the shared model and context controls (`model-menu-options.ts` holds their rules); `WorkingLine` takes the turn's start and the screen's words after the line (the Workbench's pass page uses all of them).
- `ConversationLayout` (`conversation-layout.tsx`) is every conversation's frame: Sessions' chat tab, Plan's pane and the Workbench's page each pass their bar as `header`, the list as `children`, the working line, waiting cards and composer as `footer`, and Plan's recent conversations as `after`. Below the bar is one column at most `CONVERSATION_WIDTH` (720 px) wide, centred, whose parts are the column's own flex items: the list takes the height left over and scrolls inside itself, and a footer card's `maxHeight: 50%` is the column's. `e2e/conversation-column.ts` checks the width and the centring on all three screens in WebKit. A list opens at its newest message unless Why? points elsewhere, then follows the tail as below.
- Every screen's list folds the agent's settled work (`collapseWork` in `conversation-rows.ts`): each run of reasoning
  and finished calls between replies is one closed row, "Worked · n Steps" or "Thought" (`work-row.tsx`). A running
  call, a failed or denied call, a notice and any line 10db records itself (`harnessTool` `10db.*`, such as Plan's
  lines) stay out of the fold, so what the agent does now and what needs the builder are always in view. The run's id
  is `work:<its first row's id>`, never that row's own, because open state is kept by id and opening the row inside
  must not close the run. A reader at the end of the list stays there when the window resizes (a `ResizeObserver` on
  the viewport); one who scrolled up stays put. The content surface is exactly the window's height less the title row and scrolls
  inside itself (`shell/app-frame.tsx`), so a list with its composer at the foot is bounded by the window; the
  Workbench e2e measures it in a 420 px tall window.
- `ConversationLayout` gives its list `ListScrolledContext` (`list-scrolled.ts`): the bar gains a 1 px hairline (a
  box-shadow, so its height never changes) while the list is scrolled from its start (`useHiddenEdges`); nothing is
  drawn at the list's foot. A screen that reads the draft after Send gets it from `onSend`, never from the input, which is
  already empty. A tool row's output drops the terminal's escape codes
  (`terminal-text.ts`). `ZoomablePicture` is a picture in a thread that opens in a dialog on a click.
- The composer's `held` prop (sessions spec §7.3): while a writer keeps the turn from Your folder, Send (and Stop and
  Redo) shows Wait for It, Send Reading Only and File as Tasks in place of sending; Esc cancels (the group owns Esc,
  so it never stops the turn), ⌘↩ waits. With no `held` it sends at once. The caller says when (`keepingWords`).
