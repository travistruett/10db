# apps/desktop/src/views/shape

- Plan (the builder's name for Shape: the nav item and the view's title read Plan, with the Tabler `route` icon; the routes, code, contracts and the spec keep Shape) (`views/shape/`, `daemon/shape-queries.ts`, `shell/shape-nav.tsx`) is the top-level view between Factory and Inbox; spec `docs/superpowers/specs/2026-11-02-10db-brainstorm-chat-design.md` §4. `/shape` is a new conversation that exists in the daemon only once its first message is sent, and it never redirects (New in a conversation's header, a link to `/shape`, must always reach the blank composer); `/shape/$shapeId` opens one. The nav item lists no conversations, but its target follows the selected project's list (`useShapes`, most recent first): it links to the latest conversation whose `state` is not `converted`, a running turn included, and to `/shape` when there is none or the list hasn't arrived (`latestOpenShape` in `shape-nav.tsx`). A list is keyed by project, so after a switch it can't offer another project's conversation. `/shape` shows the composer with the project's recent conversations beneath it (`recent-conversations.tsx`: title, last activity and what each produced, goals and tasks counted from its converted rows through `GET /shapes/:id`; nothing when there are none), and beside them Plan's measures (`plan-measures.tsx`, `GET /shape-measures`, all projects: the Sizing hit rate and the question cards per task, nothing until read; the wrapper in `conversation-pane.tsx` stacks the two in the conversation's 720 px column and scrolls past 45% of its height), and inside a conversation the composer's bottom row has the model chip (`plan-model-menu.tsx` over the conversation kit's `ModelMenu`: the models in `ShapeViewDto.models.offered`, the `plan` role's model marked default, an Effort submenu with only the efforts the model in use offers, kept across a model change where the new model offers it, and More models with search; `PUT /shapes/:id/model` with the model and effort; off while a turn runs or waits, with the daemon's refusal beside it; hidden when nothing is offered), the context ring and Dictate, and the header has New (a link to `/shape`) and History (`history-button.tsx`, a searchable popover over `GET /projects/:id/shapes`). `GET /shapes/:id` (`ShapeViewDto`) is the read for the proposals, the heard echo and the turn, and `shape.changed` refetches it (`INVALIDATIONS.shape`); the transcript is its conversation's (`view.conversationId`, `daemon/conversation-queries.ts`): the stored items (`GET /conversations/:id/items`, refetched by `conversation` events) and what streams now, a live store fed by the socket's `conversation.delta` frames by absolute offset (`writeLiveFrame`; a frame never moves the replay cursor) and read again from `/live` on open, reconnect, a gap or a state change. A message, Stop and Send Now go through `/conversations/:id/…`; the kit's `WorkingLine` says what the turn does and `JudgeLine` how it is judged, and `agents-line.tsx` says, where `capabilities.subagents` is false (Codex), that Plan runs without its research and review agents. The view is the conversation (`conversation-pane.tsx`, `transcript.tsx`, `plan-composer.tsx`: the conversation kit's `Composer` with Propose beside Send, Send never filled, and files uploaded as they are dropped, pasted or picked through its `uploads`) beside the read-only Proposed sidebar (`proposed-pane.tsx`: header, the pinned `summary-line.tsx` outside the scrolling list, `proposed-list.tsx` of `proposal-row.tsx` rows grouped by `proposed-groups.ts`) in `split-pane.tsx`, whose width rule is `split-layout.ts` (chat at least 420 px, sidebar 480, a drawer under 1100 px of content; an unmeasured width, as in jsdom, counts as split). A row is a button over a region like Factory's goal rows, so Enter opens it and ↑/↓ move between rows; the menu of a converted goal (Remove Draft Goal) or decision (Withdraw Decision) is its sibling. Keys are in `use-shape-keys.ts` and the input: Enter sends (⌘↩ too), Shift+Enter is a new line, ⌘⇧↩ is Propose, Esc stops a running turn unless a modal or menu is open. `round-announcer.tsx` is the one polite live region ("Round 3: 4 changes"), silent for the round the screen opened on. Convert (`convert-modal.tsx`) lists the pending rows Convert writes today (goals, loose tasks, decisions, changes, removals), says "Nothing starts. Tasks wait on the Board." and lists a 400's `errors` beside the primary; a turn that is running disables it and offers Stop. Replies render as markdown through the conversation kit (`conversation/`); the rest of the view's text is plain. Under the list, `preview-panel.tsx` draws `view.preview` (§10.2): one list per lane with work already in the factory first, the critical path in blue, each clash a dimmed line with the `arrows-split` icon, and "n tasks · h lane hours · ends in about h (estimate)". An opened row shows its attachments (`attachments/`, §10.3): a mockup in an `<iframe sandbox="">` through `srcdoc` under `MOCKUP_CSP`; a chart (checked again with `ChartSpec`, drawn by Vega-Embed with `refusingLoader` and `vega-interpreter`, since the window's CSP has no `unsafe-eval`) and a Mermaid diagram (`securityLevel: 'strict'`, SVG labels; only the kinds in `DRAWN_KINDS`, and refused if the parsed diagram names an image or its text a CSS load, because Mermaid draws in a temporary element in the live document) drawn to SVG and shown as an `<img>`, which runs no script and loads nothing. The task drawer (Overview) and Factory's open goal offer **Open conversation** (`open-conversation.tsx`, `GET /tasks/:id/shape` or `/goals/:id/shape`) only when a conversation made them; it opens `/shape/$shapeId`. The header shows `view.tokens` through `formatTokens`. `transcript.tsx` maps the items, then what streams, to the kit's entries (`plan-entries.ts`, `planItemEntries`: a `10db.plan` tool line is an `other` call named by the part before its first `·`, a `refused` line one 10db stopped; an open Send now line is a divider with Send Now; a streaming reply draws in streamdown's streaming mode until the stored one replaces it under the same id) and draws them with `ConversationList` (`busy` while a reply streams; a judge's soft hold offers Allow This, which sends "Go ahead: {title}"), which mounts only the articles near the viewport with `@tanstack/react-virtual`: Why? and stick-to-bottom go through the virtualizer because a row may not be in the DOM, and `test/setup.ts` gives a ScrollArea's viewport a height, since a virtual list with none mounts nothing. Remove Draft Goal is also in the Board's goal line menu ("More goal actions") and Factory's open goal (`remove-draft-goal.tsx`, `useRemoveDraftGoalAction`: a goal a conversation made whose status is Not started; the same `RemoveDraftGoalModal`). `e2e/shape.spec.ts` drives it in WebKit on the daemon's fake Shape session and scans each state with axe.
- A Plan's record (`views/shape/record/`, `daemon/plan-record-queries.ts`, decision `decisions/2026-11-12-a-plan-keeps-its-whole-record-locally.md`) is its own route, `/shape/$shapeId/record` (`tab`, `doc` (the document's id, since a goal's spec and its eval share a key), `rev` and `section` in the address, each kept only when it parses, `record-tabs.ts`), reached from Record in the conversation's header once the Plan holds a document or an entry, and from "Planned in". Its tabs (`RECORD_TABS`, each with its count) are Documents (a document list, a revision `Select`, the outline indented by level, and the body drawn whole through one `Markdown`, so a footnote or a reference link keeps its definition, and a picked section scrolls to its heading, which `Markdown` marks with its source line as `data-line`), Decisions (a row opens what was turned down and the builder's words), Evidence (each anchor with each task's newest check, named by the task and followed by where and when it read as text, "at <commit> · <date>": `anchor-status.ts`, Current green only when found at its line, Moved yellow, Changed red, Not checked gray, a page "Read <date>"; a superseded fact's badges are dimmed; State and Kind filters), Reviews (grouped by document, revision and round, each group's header counted over the whole filtered list, in the reviewer's words), Questions and Tasks (each task's section, which opens Documents there, and its state as Factory says it, or Cancelled, or Removed when the project no longer has it). A reviewer's, a question's and a decision's words draw their backtick code spans as code (`code-spans.tsx`). A list that fails says why in its table's body, so its header filters stay in reach. Every list is a daemon page in the Knowledge tables' style (`KnowledgeTable`), filters in the headers. Export as Markdown (`export-button.tsx`) takes a folder from the native panel, or a typed path in a browser, and shows the daemon's refusal, or the panel's own failure, under the button. On an imported Plan, or one whose agent has no subagents (Codex: `capabilities.subagents`, read from the Plan's conversation, so none starts until it loads), Convert offers no rehearsal: the Proposed pane has no Rehearse, opening Convert starts none, and one line says "Imported tasks aren't rehearsed: n tasks" ("Tasks on Codex aren't rehearsed: n tasks") instead of a Not rehearsed line per task. Words that name the agent (the composer's "Couldn't reach <agent>", Convert's "<agent> is still answering", the header's research-and-review line) use the conversation's `capabilities.label`; the sidebar's hints name none. An imported Plan's conversation shows "Imported <date>. Re-import to change its plan." where the composer's hint goes and offers no Propose, by button or ⌘⇧↩. A goal Convert made says "Planned in <Plan>" (`factory/planned-in.tsx`), and a task's drawer has a Plan context disclosure (`board/plan-context-disclosure.tsx`) showing, byte for byte, the block its lane got (`GET /tasks/:taskId/plan-context`, stored when packed, so a re-import never changes it) and its anchor checks with Evidence's badges, a check from another run than the one that got the block saying "checked by an earlier run". Markdown is drawn only by `conversation/`'s `Markdown` (streamdown, GFM only: raw HTML shown as its text and never rendered, so `<host>` or `Promise<void>` reads as written, sanitized, images replaced by "Image not shown", an `https:` link a link with no `href` (its address in its title and a closure, so no middle-click, context menu or drag opens it) whose click or Enter asks the builder to confirm its host and then opens it in the browser (`openWebLink`), and any other link its text; a fence is `CodeHighlight` on Shiki's JavaScript regex engine with Selenized themes). A text longer than `MARKDOWN_MAX_LENGTH` (512 Ki) is shown whole as a plain code block instead, and `MarkdownBoundary` shows the same when a drawing throws, as the recursive parser does on a text nested thousands deep.
