# apps/desktop/src/views/sessions/plan

A session's Plan: the panel beside its conversation, and the Record view. Plan has no screen of its own: a Plan belongs to a session (`ChatDto.planId`), and every link to a plan opens that session (`useOpenSession`, `sessions/open-session.ts`, which brings an archived one back first). Spec `docs/superpowers/specs/2026-11-19-10db-plan-in-sessions-design.md`.

- New Plan (the Sessions panel's + menu, the switcher, ⌘⇧N on any view, Factory's New Plan buttons through `useNewPlan` in `sessions/start-fresh-tab.ts`) opens a fresh tab with `plan: true` (`fresh-tabs.ts`). Its first send, or first dropped file, creates the session with `useCreateChat({ plan: true })`; dropped files then upload to `POST /shapes/:id/files` in order, a second send or drop joins the create in flight, a tab closed mid-create lets it finish and then closes the session (Recently closed holds it), and a failed create leaves the tab fresh with its draft and files and a Try Again. Reasons files were refused go to the session through `drop-notes.ts`.
- `plan-side.tsx` places the panel: beside the conversation when the tab holds 520 px of conversation and 420-480 px of panel, else a `SurfaceDrawer` about 560 px wide closed by "Close Plan"; with Changes open too its head switches between the two. `plan-choice.ts` keeps each session's open state (a session with a plan opens it by default), the title row's Plan toggle flips it, and an open panel folds the Sessions panel to the rail (`sessions-view.tsx` stops drawing it). `plan-panel.tsx` wraps `useShapeView(chat.planId)` and `proposed-pane.tsx`: header (Plan, round, Accept, ⋯ with Record and Export, Close Plan), the pinned `summary-line.tsx`, `proposed-list.tsx` of `proposal-row.tsx` rows grouped by `proposed-groups.ts`, `preview-panel.tsx`, and `heard-so-far.tsx` while there are no rows. A row is a button over a region, so Enter opens it and ↑/↓ move between rows. `row-editor.tsx` edits in place; an edit is measured against the row as the editor opened, and when a round changes the row under it the editor says "The agent changed this" and Save pins only the builder's fields. Accept (`convert-modal.tsx`) lists the pending rows, the cut list for a Plan of more than five goals, warnings and a 400's errors; it works while a turn runs and never stops it. The transcript maps a plan session's `shape_event` items with `plan-entries.ts` (`planEventEntry`, given to the kit's `itemEntries` as `own`); a session's files are dropped into its composer, which sends them to the plan.
- `plan-screen.tsx` is what a session's `see_screen` draws for the Plan (`/plan-screen/$shapeId`, inert outside the render frame): the conversation beside the panel, read only. `open-plan-session.tsx` is Open Session on a task's or goal's drawer. Plan's measures (`views/settings/plan-measures.tsx`) are in Settings › Planning.
- An opened row shows its attachments (`attachments/`): a mockup in an `<iframe sandbox="">` through `srcdoc` under `MOCKUP_CSP`; a chart (checked again with `ChartSpec`, drawn by Vega-Embed with `refusingLoader` and `vega-interpreter`, since the window's CSP has no `unsafe-eval`) and a Mermaid diagram (`securityLevel: 'strict'`, SVG labels; only the kinds in `DRAWN_KINDS`, and refused if the parsed diagram names an image or its text a CSS load) drawn to SVG and shown as an `<img>`, which runs no script and loads nothing.
- Remove Draft Goal is also in the Board's goal line menu ("More goal actions") and Factory's open goal (`remove-draft-goal.tsx`, `useRemoveDraftGoalAction`: a goal a plan made whose status is Not started; the same `RemoveDraftGoalModal`).
- A Plan's record (`views/sessions/plan/record/`, `daemon/plan-record-queries.ts`, decision `decisions/2026-11-12-a-plan-keeps-its-whole-record-locally.md`) is its own route, `/sessions/record/$shapeId` (`tab`, `doc` (the document's id, since a goal's spec and its eval share a key), `rev` and `section` in the address, each kept only when it parses, `record-tabs.ts`), reached from Record in the panel's ⋯ menu. Its tabs (`RECORD_TABS`, each with its count) are Documents (a document list, a revision `Select`, the outline indented by level, and the body drawn whole through one `Markdown`, so a footnote or a reference link keeps its definition, and a picked section scrolls to its heading, which `Markdown` marks with its source line as `data-line`), Decisions (a row opens what was turned down and the builder's words), Evidence (each anchor with each task's newest check, named by the task and followed by where and when it read as text, "at <commit> · <date>": `anchor-status.ts`, Current green only when found at its line, Moved yellow, Changed red, Not checked gray, a page "Read <date>"; a superseded fact's badges are dimmed; State and Kind filters), Reviews (grouped by document, revision and round, each group's header counted over the whole filtered list, in the reviewer's words), Questions and Tasks (each task's section, which opens Documents there, and its state as Factory says it, or Cancelled, or Removed when the project no longer has it). A reviewer's, a question's and a decision's words draw their backtick code spans as code (`code-spans.tsx`). A list that fails says why in its table's body, so its header filters stay in reach. Every list is a daemon page in the Knowledge tables' style (`KnowledgeTable`), filters in the headers. Export as Markdown (`export-button.tsx`) takes a folder from the native panel, or a typed path in a browser, and shows the daemon's refusal, or the panel's own failure, under the button. On an imported Plan, or one whose agent has no subagents (Codex: `capabilities.subagents`, read from the Plan's conversation, so none starts until it loads), Accept offers no rehearsal: opening Accept starts none, and one line says "Imported tasks aren't rehearsed: n tasks" ("Tasks on Codex aren't rehearsed: n tasks") instead of a Not rehearsed line per task. Words that name the agent (the composer's "Couldn't reach <agent>", the header's research-and-review line) use the conversation's `capabilities.label`; the sidebar's hints name none. A goal Accept made says "Planned in <session>" (`factory/planned-in.tsx`), a link that opens that session, and a task's drawer has a Plan context disclosure (`board/plan-context-disclosure.tsx`) showing, byte for byte, the block its lane got (`GET /tasks/:taskId/plan-context`, stored when packed, so a re-import never changes it) and its anchor checks with Evidence's badges, a check from another run than the one that got the block saying "checked by an earlier run". Markdown is drawn only by `conversation/`'s `Markdown` (streamdown, GFM only: raw HTML shown as its text and never rendered, so `<host>` or `Promise<void>` reads as written, sanitized, images replaced by "Image not shown", an `https:` link a link with no `href` (its address in its title and a closure, so no middle-click, context menu or drag opens it) whose click or Enter asks the builder to confirm its host and then opens it in the browser (`openWebLink`), and any other link its text; a fence is `CodeHighlight` on Shiki's JavaScript regex engine with Selenized themes). A text longer than `MARKDOWN_MAX_LENGTH` (512 Ki) is shown whole as a plain code block instead, and `MarkdownBoundary` shows the same when a drawing throws, as the recursive parser does on a text nested thousands deep.
