# apps/desktop/src/views/settings

- Kind drawer (`kind-drawer.tsx`): Implied by is a `TagsInput` whose suggestions are the stock hazard names and every project's area and hazard names (a name typed freely is kept); Skills is a `MultiSelect` of the harness's craft skills (`SKILL_NAMES`). The playbook row drawer (`playbook-row-drawer.tsx`) has Ships, "With Its Goal" or "Alone", saved at once with the rest of the row.

- Settings (`views/settings/`) is one route over `sections.ts`. Each section has a `scope` (`SettingsScope`: This Project or All Projects; the sidebar's `SegmentedControl` shows one at a time) and a `subhead` its links group under. To fill a planned section, set its `planned` to null and replace its arm in `section-body.tsx`. `?focus=<name>` on a section's address scrolls to and focuses the element that called `useFocusTarget(name)` (`focus-target.ts`); `ConnectionStatus` (`connection-status.tsx`) is the teal, yellow or gray dot with words that every connection state uses.
- Settings › This Project is Project (General, App Preview, Sharing, Board Columns), Planning, and Agents (Playbook, Billing, Trust, Sandbox). General holds Project, Checks, When Work Is Finished (with Commit Directly it also shows the Separate Copies switch, `localCopies`, and a Teardown Command field, `copyTeardownCommand`, once the switch is on; Save refuses the switch on with no command in the contract's words, `NAME_COPY_TEARDOWN`; the daemon refuses a Delivery change while a copy is unfinished and its reason shows in the bar) and Running Tasks (Fresh Session, Firm Reminder and Wait for Your Answer are there) and Archive (`project-archive-card.tsx`: a destructive `ConfirmModal` shows the daemon's refusal while work runs); App Preview holds App Address, Preview Command, Dev Login Command, and the screenshot matrix; Sharing (`sharing-section.tsx`) holds Pictures in Pull Requests and a Slack card whose Post Pictures to Slack switch and Slack Channel select are disabled with the reason when Slack is off or the project has no workspace, and show the scope fix when the token can't list channels; Billing holds Spending Limit per Task beside the accounts. Saving follows one rule (`settings-drafts.tsx`, one `SettingsDrafts` per page): a page with a typed field (General, App Preview, Planning, Billing, Sandbox, Linear, People's timers, Updates) holds every field on it for the page's one `SaveBar`, shown only while Save would send something (`useDraft`, Billing's account and backup as one draft and one patch; project fields through `useProjectFields`, `project-fields-state.ts`, compared as Save sends them, trimmed), with Discard and Save, then Saved; a table row saves in its own drawer or modal; a page of switches and picks saves each at once, and the bar says Saved as a write lands (a mutation with `meta.quiet` is an action and says nothing). Plan's Track Record (`plan-measures.tsx`, every project) ends Decisions' Decisions tab.
- Settings › Sandbox (`views/settings/sandbox-section.tsx`, address `network-hosts`, which old links kept) opens with a Permissions card (Allow localhost, Allow Docker, Allowed Commands), then `network-hosts-section.tsx`: it lists, adds and removes a project's allowed hosts through `/projects/:id/network-hosts`; the add form sits in the Allowed Hosts heading, the daemon's refusal text is shown under it, and Found in Project Files lists what a look found with an Allow each (`decisions/2026-10-29-project-network-hosts.md`).
- Settings › Trust and the project's Trust (This Project › Agents) are described in `trust/AGENTS.md`.
- Layout of the app-wide pages (Overview, Lane Permissions, Trust, Sessions, Integrations, People, Appearance, Updates, Keep-Awake, Agent Skill): a row's description is one short line, and anything longer goes behind a `HelpHint` (`help-hint.tsx`, an info `ActionIcon` opening a `HoverCard`), which `SettingRow` takes as `help` and `SettingsCard` as `help` beside its title (it also takes a one-line `description` and an `action`). A Trust row's per-agent note is behind the info button, and a server's config and sign-ins open from its name. Trust's "Applies from the next session" is said once, in the page's scope line. Integrations groups its cards under two headings, each with one dim line: Used by 10db (GitHub, Slack, Artificial Analysis: 10db holds the sign-in) and Agent Connectors (Linear, Figma: each agent account signs in, and tasks use them as MCP servers). - Settings › Decisions (`views/settings/decisions-section.tsx`, `daemon/judge-queries.ts`) edits the judge's config and the account's key through `/judge`; Account (`paid-by.tsx`) lists the accounts that can answer decisions (`powersDecisions`) and disables a plan login with its reason (`cantRunDecisions`), and a missing or changed key says decisions use 10db's rules. The key goes by `daemon/judge-secret.ts`, never TanStack Query, and the page shows only Set or Not set. The daemon emits no event for judge changes or calls, so the page invalidates its own queries after each mutation and polls the stats (`useDecisionStats`, `GET /judge/decisions`, the last 30 days) and the calls (`useJudgeCallsPage`, `GET /judge/calls/page`) every 30 s. The page is two `Tabs`: Decisions (the intro line with the Knowledge link; a bordered block of `SettingRow`s, selects in one column: "Let a Model Make These Calls", "Account" with its key state and View Account under the select, and "Model" (`DecisionModelPicker` over every decision); then "Every Decision", one grouped table: `decisions-table.tsx`: Decision, Status, Model, Sure Enough, Calls (30d), Outcome and Cost as their own columns, under a tinted, bold header row per group; its status badges never truncate, and with every decision off each reads plain Off since the page's switch says why; one link under it, "Compare decision models in Models", goes to Settings › Models `?class=decision`) and Recent (Recent decisions); the tab is page state. The decision models' chart and list are Models' Decision Models, not a tab here. `decision-catalogue.ts` is the one place a decision is added: its group, label, plain-words copy, mode (Acting or Shadow) and the clause Recent decisions says when the call fell back; its `Record` over `JudgeDecision` fails typecheck when a decision the daemon configures is missing, and a group with no rows is not drawn. `decision-numbers.ts` holds the pure text: status (Acting, Shadow, Off, and Off (all decisions) for every row while the master switch is off or `TENDB_JUDGE=off`), the last 30 days' cells (`lastThirtyDays`: calls, outcome and cost; a decision the daemon leaves out of the stats reads 0 calls, and a dash is a cell with nothing to say), the threshold preview and the outcome words. Account (`paid-by.tsx`, focus target `paid-by`) is the select of the account decisions run on (an OpenRouter, Anthropic API key or Bedrock account) and its key state, with "Decisions are falling back to rules: <reason>" when its latest call fell back; with no usable key every status is followed by "· no key" and every call falls back to today's rule. A row, or Enter on its name, opens `decision-drawer.tsx`: what it asks and does, its switch, `decision-model-picker.tsx` (from `GET /judge/models`, grouped by maker, each with its price; one 10db can't call is disabled with the reason, and so noted when saved; the daemon saves a pick only after it answers a test decision, so the field shows the pick while it is asked and the saved model again with the refusal; with no key it asks for an account under Account), Sure enough (`sure-enough.tsx`: a 50 to 99% slider whose edit is kept until saved, saved once after the builder stops, flushed on blur and on unmount, never on a click that doesn't move it; a floor saved outside 50 to 99 is drawn at the nearest end with its saved value in words; the preview counts the last 30 days' answers a floor would have acted on), the decision's last 30 days and its own Recent decisions. Recent decisions (`recent-decisions.tsx`) is a fixed-height table the daemon pages and filters by decision and outcome from its headers; a filter change goes back to page 1, and a filter that matches nothing keeps the header. When `JudgeStatusDto.off` is true it says so and disables the controls; the numbers and calls still show. Plan's Sizing and Questions measures are in Plan's view, not here.
