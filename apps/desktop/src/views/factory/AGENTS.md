# apps/desktop/src/views/factory

- Under the update note, `admission-note.tsx` says why new lanes and gates wait on this Mac: one line per hold from `GET /admission` (`daemon/admission-queries.ts`, read every 30 s since a hold changes with no event), in the daemon's words and order (load, disk, lane cap). Nothing shows while nothing holds.

- Factory's header holds Live | Metrics, the Activity button, the Project filter and one filled button, New Plan (starts a New Plan session, as the Sessions panel's menu does). Adopt a Plan… has no UI any more; `POST /projects/:id/goals/adopt` stays for briefs made elsewhere.
- Factory's open goal (`factory/goal-detail.tsx`) is four zones, not label/value rows: `GoalBar` (counts from `task-rows.ts` `barCounts`: merged and in review from the digest's progress, the rest from the rows) with Start Ready Tasks (a `BatchSheet` with `goal` set, as the Board's goal line opens), `NeedsYou` (the list's `waitingOn` cards plus each failed run with Retry), `GoalTasks`, then collapsed `SinceYouLooked` and `AboutGoal` and the dimmed `GoalFooter` (`goal-digest.tsx`). The task list replaces the Sessions table and the Pull requests list: `task-rows.ts` `taskRows` joins `useTasks` (every task, so a not-started one has a row), the latest workstream and the batches, says the state once (`taskState` from the Board, prefixed "In review · " for a task in review), and gives only a running row a step and context. A cancelled task has no row. The bar and Needs you come from the list's digest, which events keep fresh; only `SinceYouLooked` reads the answer to `useOpenGoal`.
- Factory (`views/factory/`, `factory-view.tsx`) is, under Live, one list of every project's runs (`live-list.tsx`, from `useWorkstreams({ active: false })` and the live passes), in the sections `live-groups.ts` sets (`liveGroups`, a pure table: each task's latest run (`TaskDto.workstreamId`, else the run made last), runs a live pass holds left to the pass's row, Needs You, Failed for a week unless the task was closed, Running, In Review for a finished run whose pull request is open, Waiting for a lane or for someone else, Done Today for 24 hours, by `lastMoment`, a finished run's finish or a live run's last activity; the tasks and batches come from `useTasksOfProjects` and `useBatchesOfProjects`), narrowed by the Project filter (`decisions/2026-11-19-factory-is-a-live-list-across-projects.md`). A row is a dot, the task, what it is doing, the project's tile and name in a fixed column, the time in a fixed column and an action slot every row keeps, so the columns line up; it opens `/board?task=<id>` after selecting the project, and a failed row's Retry sits in the slot only where `canRetryRun` says the daemon takes it, a refusal shown above the list. While the runs load the page shows `PageLoading`, and a failed read an Alert, never "Nothing is running". A live pass is a row (Needs You while pages wait, else Running). Sections are `role="group"` with their label as the name, not landmarks. The Goals section (`Goals` in `factory-view.tsx`, every shown project's goals through `useQueries` over `goalsQueryOptions`) shows only while a project has a goal, each project's `GoalList` under its name. `?view=metrics` swaps the page for the Rigor, Human touch and Card types panels of one chosen project. Within a project's `GoalList` (`GET /projects/:id/goals`, `daemon/goal-queries.ts`), goals are one hairline-divided list in the order `factory/goal-status.ts` sets: open goals by status, then done goals under a collapsed `Done (n)`; work in no goal is the live list.
- The Inbox card types panel (`factory/card-types-panel.tsx`, `daemon/card-types-queries.ts`, `GET /projects/:id/card-types`, counted in SQL by `inboxCardTypes` in `packages/db`) sits under Human touch in Metrics when one project is shown: per card type, the cards raised in the last 7 and 30 days and how many were answered with a real choice, dismissed (answer `dismissed` or `Dismiss`) or closed by 10db (cancelled, expired, or resolved with a reason). A type is its fold-key prefix; for a card whose key names no type (none, or the sha256 the ask path stores for an ask with no key of its own), a flag's title before its first colon, and any other kind, or a flag with no title prefix, the kind's name. A type with at least 5 cards in a window of which 80% were dismissed or withdrawn is `noisy` (`isNoisyCardType`): its row is tinted, badged and listed first. The Inbox's `DISMISS_CHOICE` and the contracts' `DISMISS_CHOICES` name the same answer.
- The Rigor panel (`factory/rigor-panel.tsx`, `daemon/rigor-figures-queries.ts`, `GET /projects/:id/rigor-figures?days=7|14|30`) sits above Human touch in Metrics when one project is shown: a table per rigor and for all of them of the work per done task in the chosen period (default 14), a task counting under the rigor it has now, with the project's judge-override line. Human touch's columns are every Inbox kind, so they add up to Cards.
- Activity (`activity-drawer.tsx`, `activity-row-item.tsx`, `activity-content.tsx`) is a history button in the Factory's title row, beside the project filter, opening a `SurfaceDrawer`, since most of the time none of it matters: the notices that tell the builder something and ask nothing (`GET /activity/page` by `useActivityRows`, `daemon/activity-queries.ts`), newest first, for the project the Factory's filter shows or every project. It shows 20, and Show More adds 20 (loading the next page when it runs out). A row opens its notice in the drawer (`ActivityContent`: the line, body, when, the project and Open Task), with All Activity back to the list; focus moves to that link when a notice opens and back to its row on the way back, so Esc still closes the drawer. A search field narrows the list (`q`, 250 ms after the last keystroke). The open notice is looked up by its group key on each render, so a repeat that joins it (`×n`, grouped within 10 minutes by the daemon) shows at once. A `notice.posted` event invalidates `activityKeys.all`, which also refreshes the task drawer's notices. Activity is never counted by the rail, the menu bar or `useOpenInboxCount`. `e2e/inbox-activity.spec.ts` covers it against the real daemon. It is a log, never counted and never answered; the Inbox has no Activity list, since a notice is not a state a card is in.
