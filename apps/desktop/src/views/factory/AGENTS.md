# apps/desktop/src/views/factory

- Factory's header has one filled button, Plan Work (a link to `/shape`, the new conversation). Adopt a Plan… has no UI any more; `POST /projects/:id/goals/adopt` stays for briefs made elsewhere.
- Factory's open goal (`factory/goal-detail.tsx`) is four zones, not label/value rows: `GoalBar` (counts from `task-rows.ts` `barCounts`: merged and in review from the digest's progress, the rest from the rows) with Start Ready Tasks (a `BatchSheet` with `goal` set, as the Board's goal line opens), `NeedsYou` (the list's `waitingOn` cards plus each failed run with Retry), `GoalTasks`, then collapsed `SinceYouLooked` and `AboutGoal` and the dimmed `GoalFooter` (`goal-digest.tsx`). The task list replaces the Sessions table and the Pull requests list: `task-rows.ts` `taskRows` joins `useTasks` (every task, so a not-started one has a row), the latest workstream and the batches, says the state once (`taskState` from the Board, prefixed "In review · " for a task in review), and gives only a running row a step and context. A cancelled task has no row. The bar and Needs you come from the list's digest, which events keep fresh; only `SinceYouLooked` reads the answer to `useOpenGoal`. The Not in a goal row still lists sessions (`goal-sessions.tsx`).
- Factory (`views/factory/`) is the project's goals (`GET /projects/:id/goals`, `daemon/goal-queries.ts`), one hairline-divided list in the order `factory/goal-status.ts` sets: open goals by status, Not in a goal, then done goals under a collapsed `Done (n)`. A status's dot color and label come from `board/goal-status.ts`, the same as the Board's goal line. Every row (`goal-row.tsx`) is a button with `aria-expanded` over a `role="region"`; one is open at a time and Escape closes it. `/factory?goal=<id>` (the Board's Open in Factory) starts that goal's row open, with the Done group open when the goal is done, and reads its digest once through the same mutation (a ref keeps a StrictMode remount from reading it twice); a goal the project does not have opens nothing. Opening a goal calls `GET /goals/:id/digest` as a mutation (`useOpenGoal`), because that read moves the goal's "last opened" mark: a query would repeat on a remount and find its own window closed. The Δ rows (Waiting on, Deviations, Decisions) come from that answer and every other row from the list, which events keep fresh. A session row (`goal-sessions.tsx`) names its task by `taskHeadline`, else `taskTitle`, and links to `/board?task=<id>&goal=<goalId>` (no `goal` for a task not in a goal); `BoardView` starts its goal filter from the link's `goal`, and Retry stays on the row. A queued or held run names no step (`step-cell.tsx`), and the daemon's digest never counts one as running.
