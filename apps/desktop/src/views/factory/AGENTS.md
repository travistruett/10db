# apps/desktop/src/views/factory

- Under the update note, `admission-note.tsx` says why new lanes and gates wait on this Mac: one line per hold from `GET /admission` (`daemon/admission-queries.ts`, read every 30 s since a hold changes with no event), in the daemon's words and order (load, disk, lane cap). Nothing shows while nothing holds.

- Factory's header holds Live | Metrics, the Activity button, the Project filter and one filled button, New Plan (starts a New Plan session, as the Sessions panel's menu does). Adopt a Plan… has no UI any more; `POST /projects/:id/goals/adopt` stays for briefs made elsewhere.
- Factory's open goal (`factory/goal-detail.tsx`) is four zones, not label/value rows: `GoalBar` (counts from `task-rows.ts` `barCounts`: merged and in review from the digest's progress, the rest from the rows) with Start Ready Tasks (a `BatchSheet` with `goal` set, as the Board's goal line opens), `NeedsYou` (the list's `waitingOn` cards plus each failed run with Retry), `GoalTasks`, then collapsed `SinceYouLooked` and `AboutGoal` and the dimmed `GoalFooter` (`goal-digest.tsx`). The task list replaces the Sessions table and the Pull requests list: `task-rows.ts` `taskRows` joins `useTasks` (every task, so a not-started one has a row), the latest workstream and the batches, says the state once (`taskState` from the Board, prefixed "In review · " for a task in review), and gives only a running row a step and context. A cancelled task has no row. The bar and Needs you come from the list's digest, which events keep fresh; only `SinceYouLooked` reads the answer to `useOpenGoal`.
- Factory (`views/factory/`, `factory-view.tsx`) is, under Live, `FactoryOverview` (`factory-overview.tsx`, in a `Container` at the Page width), which reads every project's runs (`useWorkstreams({ active: false })`), the live passes, tasks, batches, the open Inbox, `GET /admission` and each shown project's goals, and sorts the runs with `liveGroups` (`live-groups.ts`, a pure table: each task's latest run, runs a live pass holds left to the pass, Needs You, Failed for a week unless the task was closed, Running, In Review for a finished run whose pull request is open, Waiting for a lane or for someone else, Done Today for 24 hours, by `lastMoment`), narrowed by the Project filter (`decisions/2026-11-25-factory-leads-with-needs-you-then-projects.md`). Three parts: `GlanceTiles` (five figures), `NeedsYouPanel` (`needs-you-panel.tsx`: waiting runs named by the open card that targets them, with Open and Answer, waiting passes, and failed runs grouped by `failureCauses` in `factory-summary.ts`, project + failure kind + failed step, as one `FailureActions` (`failure-actions.tsx`): the shell's `SplitButton` with Retry (Retry All for a cause, one retry after another) where `canRetryRun` allows and Close Task (Close All) in its menu where `canCloseRun` allows (`useCloseTask`, no confirm), or a ⋯ menu with only Close Task, a refusal shown above the rows; a click anywhere on a row but its buttons opens it (its task's drawer, a cause's runs, a pass), so no row has Open; each row's kind is a sentence-case Mantine `Badge` in the first column, and a failure's dim line is `failureReason`'s first sentence with `failureLine` as its tooltip; then a Waiting on others table, each question out with someone else by its person (an `Avatar`), its card's title and its task) and `ProjectList` (`project-list.tsx`: a Mantine `Accordion` (`separated`, each item a raised card: `--tendb-color-card` and `--tendb-elevation-raised`, DESIGN.md Elevation) item per project, `StackedBar` (a `Progress.Root` with a section per part) from `barCounts`, then only a yellow "N need you" and a red "N failed" `Badge` (xs, light) where there are any, the bar's `HoverCard` (`BarBreakdown`) listing each part with a count above zero, or "Idle · nothing open", the control's accessible name the project and `projectLine`, and an idle project's bar (`projectRank` 2) at reduced opacity; sorted by `projectRank`, open by `startsOpen` or a goal that is failed, waiting on you or running, or the linked goal; opened, its `GoalList` and then its work in no goal as `TaskLine`s, with In Review and Done behind a fold each). A `TaskLine`'s mark sits outside its button, so a failed line's red dot is `FailureDot` (`failure-card.tsx`): a `HoverCard` with `failureLine`, the agent's reason and `FailureActions`, while the line itself says only "Failed at <step>" (`failedAt`). A running line shows `StepProgress` (`stacked-bar.tsx`, Mantine's segmented progress: a `Group grow` of `sm` `Progress` bars, one per step), `stepLabel` (`STEP_LABEL` from `task-rows.ts`) and `ModelBadge`; any other line has neither, so its state spans those three columns (`data-wide`). A line's title and state are `xs` `ClippedText` (`clipped-text.tsx`), which shows a Mantine `Tooltip` with the whole text only when the text is cut. Goal rows (`goal-row.tsx`), task lines and folds all sit on `.cols` in `factory-overview.module.css`, one `grid-template-columns` for the card (a task line's button takes it through `subgrid`) whose columns between the marks and the time shrink to zero (the title keeps a quarter of the row), so no column pushes the time past a narrow card; Needs you's lines pass `compact`, which drops the bar and model columns. The project header's bar starts on the goal bars' edge and runs to the goal rows' status column: `useBarColumn` (`bar-column.ts`) reads the resolved tracks of the first `.cols` row in the card, again on every resize, since the accordion's control sits outside that grid; a folded card, with no row drawn, keeps a 220 px name and a 240 px bar, and the bar gives way before the badges on a narrow card. A project's bar is 6 px, a goal's 4 px. A task line, a Needs you row and a goal's task (`goal-tasks.tsx`) set `?task=<id>` on `/factory` (`router.tsx`), and `FactoryOverview` mounts the Board's drawer for it (`board/project-task-drawer.tsx`, the drawer from its project's reads) with Open on Board, which selects the project and opens `/board?task=<id>`; closing drops `task` with `replace`, and the drawer's Cancel Run asks `CancelRunModal` here. The drawer over Factory offers no Start afresh, since how a start went is said on its Board card. While the runs load the page shows `PageLoading`, and a failed read an Alert; with no runs, passes or goals it is the shell's `EmptyState`, "Nothing is running". `?view=metrics` swaps the page for the Rigor, Human touch and Card types panels of one chosen project. Within a project's `GoalList` (`GET /projects/:id/goals`, `daemon/goal-queries.ts`), goals are one hairline-divided list in the order `factory/goal-status.ts` sets: open goals by status, then done goals under a collapsed `Done (n)`, each row (`goal-row.tsx`) with a small bar (`goalBar`), the short status (`goalStatusWord`), the merged count "2/5" and any news as a badge on the card's columns, a `HoverCard` with `goalDetails` and the news, and `verdictLine` and the news as its accessible name.
- The Inbox card types panel (`factory/card-types-panel.tsx`, `daemon/card-types-queries.ts`, `GET /projects/:id/card-types`, counted in SQL by `inboxCardTypes` in `packages/db`) sits under Human touch in Metrics when one project is shown: per card type, the cards raised in the last 7 and 30 days and how many were answered with a real choice, dismissed (answer `dismissed` or `Dismiss`) or closed by 10db (cancelled, expired, or resolved with a reason). A type is its fold-key prefix; for a card whose key names no type (none, or the sha256 the ask path stores for an ask with no key of its own), a flag's title before its first colon, and any other kind, or a flag with no title prefix, the kind's name. A type with at least 5 cards in a window of which 80% were dismissed or withdrawn is `noisy` (`isNoisyCardType`): its row is tinted, badged and listed first. The Inbox's `DISMISS_CHOICE` and the contracts' `DISMISS_CHOICES` name the same answer.
- The Acceptance panel (`factory/acceptance-panel.tsx`, `daemon/acceptance-queries.ts`, `GET /projects/:id/acceptance-figures?days=7|14|30`) sits above the Rigor panel: completed, sent back and sent to you counts and why acceptance isn't checking. The Board header (`board/acceptance-line.tsx`) shows the same counts for 7 days; each links here.
- The Rigor panel (`factory/rigor-panel.tsx`, `daemon/rigor-figures-queries.ts`, `GET /projects/:id/rigor-figures?days=7|14|30`) sits above Human touch in Metrics when one project is shown: a table per rigor and for all of them of the work per done task in the chosen period (default 14), a task counting under the rigor it has now, with the project's judge-override line. Human touch's columns are every Inbox kind, so they add up to Cards.
- Activity (`activity-drawer.tsx`, `activity-row-item.tsx`, `activity-content.tsx`) is a history button in the Factory's title row, beside the project filter, opening a `SurfaceDrawer`, since most of the time none of it matters: the notices that tell the builder something and ask nothing (`GET /activity/page` by `useActivityRows`, `daemon/activity-queries.ts`), newest first, for the project the Factory's filter shows or every project. It shows 20, and Show More adds 20 (loading the next page when it runs out). A row opens its notice in the drawer (`ActivityContent`: the line, body, when, the project and Open Task), with All Activity back to the list; focus moves to that link when a notice opens and back to its row on the way back, so Esc still closes the drawer. A search field narrows the list (`q`, 250 ms after the last keystroke). The open notice is looked up by its group key on each render, so a repeat that joins it (`×n`, grouped within 10 minutes by the daemon) shows at once. A `notice.posted` event invalidates `activityKeys.all`, which also refreshes the task drawer's notices. Activity is never counted by the rail, the menu bar or `useOpenInboxCount`. `e2e/inbox-activity.spec.ts` covers it against the real daemon. It is a log, never counted and never answered; the Inbox has no Activity list, since a notice is not a state a card is in.
