# apps/desktop/src/views/workbench

- The Workbench (`views/workbench/`, spec `docs/superpowers/specs/2026-11-09-10db-workbench-design.md` §4) is the nav item between Plan and Knowledge at `/workbench` (`workbench-search.ts`: `task` selects a page, `tasks` comes from the Board's Work on These, `goal` from Factory's Work on This; each kept only when it parses). The frame (`shell/app-frame.tsx`) folds the rail and panel by the window's width and says through `FrameSlots.panelShown` whether it draws the panel now (a column, or the open sheet). With a pass open `PassWorkspace` always mounts `Panel section="workbench"`: while the panel is shown the queue (`QueueList`, Add Page) is its body, under a head holding the pass's name and its ⋯ (`PassMenu`: Finish, Rename, Abandon) and, once a page is signed off, the pull request control while it can act (no counts line: each row says its state), and the title row names the shown page (its label, "state · route" as meta, and its row's Take Out menu); while it is not shown (a medium window with the sheet closed, a narrow window) the queue is the strip across the top of the content, its Panel renders nothing, and `PassHeader` draws the pass's line and ⋯ into the title row; the queue is never drawn twice, focus held in it moves to the shown page's row when it changes place, and a row picked in the sheet closes it (`closeSheet`). `workbenchLayout` is gone: the workbench has no width rule of its own. `WorkbenchScreen` (`workbench-view.tsx`) takes its reads (the live pass, `PassStartDto`, tasks, Inbox items, a goal's pages) and the daemon calls (`WorkbenchActions`: start, add pages, rename, abandon) as props, and hands the workspace `PassWorkspaceProps` through `renderWorkspace`; the route (`WorkbenchView`) fills them for the selected project from `daemon/pass-queries.ts` (`useLivePass` over `GET /passes?live=true`, `usePassStart`, read only when the project has a page area, `useGoalPassPages`, `useTurns`, and a mutation per route, each refetching `passKeys.all` once it lands) and keeps the selected page in `?task=`. With no page area it is the setup (`setup/workbench-setup.tsx`, `decisions/2026-11-10-the-workbench-setup-rebuilds-the-areas-for-one-apply.md`): `POST /projects/:projectId/workbench-setup` (`useWorkbenchSetup`, aborted when the screen goes, never retried by itself, standing ten minutes, and read for Workbench Settings' count only while no pass is open) proposes the areas rebuilt; Areas (`areas-section.tsx`) says what the list comes to in one line (`areasSummary`), each new page is a ticked row whose untick folds it back (`withoutPages`), the kept areas and what was left out say why, and the other areas are behind Show Other Areas; Settings (`settings-section.tsx`) and Branch (`branch-section.tsx`, the push as a command to copy) show when the daemon has them; one Apply (`setupPatch` in `setup-rules.ts`) sends one `PATCH /projects/:id`, a 400's words above it, and a list the project would refuse (`setupAreasProblem`) disables it; a setup with nothing to suggest says Nothing to set up. Once the project has page areas the rebuild is one row of its own, Rebuild areas, unticked unless a counted new page exists, and Apply sends the areas only when it is ticked; a rebuild that changes nothing shows no Areas. With page areas, the start page's `TitleRow` and `PageIntro` (title UI Workbench, "Work through pages with the agents, live.") always offers Workbench Settings on the title row, its badge only above 0 (`setUpCount`: the settings and the new pages not in `ProjectDto.leftOutPages`, never the branch note), with Back to Pages, and at the list's foot one dimmed line "Sessions `/sessions` found in code · Review" when the setup has new pages (`newPagesOf`), Review opening the setup (the setup is read on its own, so the start page never waits on it); in the setup the rebuild starts ticked when one is counted, a page left out before shows unticked, and Apply sends `leftOutPages` (the project's list less each ticked new page plus each unticked, `leftOutAfter`) with the areas; a page shows everywhere by its `label` (the DTO's, `pageLabel` over an `AreaDef`), never its area name, and Add Page's picker finds it by label, name or route; with no pass, the start page (`start-pass.tsx`) is the project's pages as rows to tick (`page-list.tsx`: a Checkbox named by the page's label, its route in monospace, when it last changed, "Waits for <task>" when held), then an "Open UI tasks" subhead and the joinable tasks, and at the foot StartLines and any refusal on the left and, on the right, what is ticked in words (`tickedWords`: "2 pages · 1 task") before the primary Start Pass; it sends no first message, each page waits for the builder's. The searchable picker (`page-picker.tsx`) stays for Add Page. Rules in `start-pass-rules.ts` (joinable tasks, a ticked row disabling every row that shares a page or a file by `globsOverlap`, at most `PASS_PAGE_CAP_MAX` pages, `passName`, `pageCap`) and Start Pass's lines (`start-lines.tsx`; each lack in words, those fixed in Settings › General with Open Settings: Docker off, no app address, and `no_changed_check`, "No changed-files check: turns run unchecked."); with a pass, `PassHeader` (`headerLine`, which wraps, with the actions moving under it, kept right, when the window is too narrow for both, so the ⋯ menu stays on screen (`e2e/workbench.spec.ts` measures it from 420 to 1280 px); the pull request control once a page is signed off, ⋯ Close Pass/Rename/Abandon Pass, the timing hint, `close-progress.tsx` while closing, naming the next step that does anything for the project's delivery, gate and take-outs (whether it takes pages out held from the landing of its sign-offs, since each page taken out leaves the view before the step is recorded), and announcing only its first line, Abandon kept in reach) and its notices (`header-notices.tsx`: red for a failure, yellow for what needs a look, a color for every `PassNoticeKind`, a failed or unrun check after a turn (`turn_check`) red; one notice is one row and two or more fold into one line, "N issues · <the first one's first line>", with Show All/Hide opening the list in place, so the header stays one line tall; each row shows its first line clamped to one line, the rest (a failed gate's log tail, or a first line over `LONG_LINE`) behind Show More (`aria-expanded`, `aria-controls`) in a pre-wrap block that scrolls; the close's own notice (`close`: a close that stopped) offers Continue Close while the pass is closing, and while it shows the header's close progress line is gone (`CloseFacts.stopped`), posting `POST /passes/:passId/close/continue`, its refusal said in the row; Ask Agent to Fix on a sendable one (the daemon's Send to Agent), offered only while the pass is open and disabled once sent, asks which page, then posts `POST /tasks/:taskId/thread/:noticeId/send-to-agent` for that page; a notice naming an open Retarget card offers Retarget to `<base>` while the pass is open or closed, answering it) over the workspace, and its dialogs (`add-page-modal.tsx`, `rename-modal.tsx`, `abandon-modal.tsx`, which names by label the pages whose changes it deletes and those that stay ("Discards: Billing, People (their changes are deleted). Stays: Settings (signed off).") and, from a close, says the close stops, refused once the close moves the folder's branch). The pull request control (`pr-button.tsx`) reads `GET /passes/:passId/pull-request` first: not offered, no button is drawn in the panel or the header, and the signed-off page's foot (`PrFoot`) says "Signed off. No pull request yet: <the daemon's reason>" instead; offered, Open Draft PR posts at once (pushing is easy to undo), asking first only when the branch carries commits from before the pass that `origin` lacks, which the pull request would list too; once there is a pull request it shows "PR #n", a Draft badge, the gate on the pushed tip ("Checks running/passed/failed") and Push to PR. A signed-off page shows the same control at its foot, above the composer, with "Signed off. CI checks it once it is in the pull request." (or why there is no pull request yet), so the next step is where the builder signed off. Close Pass (`close-pass-modal.tsx`, rules in `close-choices.ts`) reads `GET /passes/:passId/close`, which stops nothing, and sends `PassCloseRequest` with the preview's token: unfinished pages Take Out or Sign Off Now (Keep/Drop for a page taken out), files no page owns Leave Out or Add to a page that lands, foreign commits, the gate's consequence and the summary; an answer of `changed` redraws the lists, keeps the choices made, says what changed in the footer's alert beside Close Pass, and confirms with its new token. A close that finishes while the pass is on screen leaves one line above the start page's list, "Settings pass closed; its work is on main.", until another pass opens (an Abandon leaves none). A closed pass that has not settled is one line above the start page's list (`closed-pass-line.tsx`, words by its Move card's reason, else its pull request's state), with its notices, which offer no Ask Agent to Fix: its pull request, and Move `<branch>` to `origin/<base>` while its Move card is open, answering that card. The take-out and close previews are read afresh on each opening (`gcTime: 0`); the pull request preview is read only while the pass is open, again when a page is signed off or the pull request is made, the same pass's last answer standing until the new one arrives, so an open confirm stays open. `daemon/pass-close-queries.ts` calls the sign-off, take-out preview, pull request, close and Send to Agent routes through `DaemonClient`. Settings › General sets the project's App address (`ProjectPatch.appUrl`, a loopback origin). The batch sheet offers Work on These when every ticked task names a page; The sidebar's Workbench item counts the pages of the selected project's pass, while it holds pages, that wait on the builder (`views/workbench/workbench-count.ts`, the queue's ranks 1-3, read as "n pages waiting"). Factory's live list shows each project's pass while it holds pages as a row (`factory/live-list.tsx`: "UI Workbench · 3 pages waiting on you"), which opens the Workbench in that project, and an open goal whose UI work is done or nearly so (`goalReadyForPass`) reads `GET /goals/:goalId/pass-pages`, only then and only while no pass of the project holds pages, and offers `WorkOnThis`. The task drawer says "Has saved Workbench work" with Discard Saved Work (`board/kept-work.tsx`, a confirm, then `DELETE /tasks/:taskId/kept-work`) and links the pass-wait notice to the Workbench. In a page (`page-pane.tsx`, `page-actions.ts`): the thread is the kit's (`page-thread.tsx` over `page-entries.ts`): `ConversationList` over the task conversation's items (`PassPageDto.conversationId`) and what its session streams now (`useConversationLive`), the builder's pictures read from `GET /conversations/:id/files/:fileId`, replies as markdown, tool rows with Allow This on a soft judge denial (it sends "Go ahead: <call>" as the builder's message), and each ended turn's files and pictures after its last agent item; the composer is the kit's `Composer` with the pass's phase table (`page-composer-phase.ts`), Open Page and Sign Off in its slots (`page-composer.tsx`); the working line is the kit's `WorkingLine`, counting from the turn's start and naming the streaming call or the turn's last report, with the files so far and Show Log. Send posts to the task's conversation (`POST /conversations/:id/messages`; a page whose task has none yet posts `POST /tasks/:taskId/thread`, which makes it), an empty composer's Stop posts `/tasks/:taskId/stop`, Stop and Redo posts the draft to `POST /conversations/:id/redo`, and Sign Off posts `POST /passes/:passId/tasks/:taskId/sign-off`; a page signing off says so at the foot of its thread (`sign-off-line.tsx`), and one waiting for another page's turn offers Cancel Sign-Off (`DELETE`, same path); a Ready page shown marks its turn opened once (`POST /tasks/:taskId/turns/:turnId/opened`, only while the pass's timing says it never was); a failed page says `passTurnFailureLine` (`board/task-state.ts`: what happened, and that Retry Turn sends the last message again) and offers Retry Turn (`retry-turn.tsx`), which answers the turn's flag with `PASS_RETRY_TURN_CHOICE`; a notice in the thread the daemon offers (its item's `offer`: a review finding or a failed check, or Allow this for a call auto mode denied) has Ask Agent to Fix (`page-thread.tsx`) while the pass is open, which posts `POST /tasks/:taskId/thread/:messageId/send-to-agent` for that page and that notice and is disabled once sent, kept in the list's row state (`conversation/row-state.tsx`). A page whose status is Asks (its run's question or permission: `askOf` in `page-status.ts`, carried as `QueueRow.ask`) draws the Inbox's own card in its pane (`page-ask.tsx`, `InboxCard` without the Inbox's key hints, keyed by the item so no draft passes to the next, gone once answered) and answers it through `POST /inbox/:id/answer` with the body the Inbox sends (`inbox/card-answer.ts`); slice 6's shared-code question is answered there too. A working page's line ends with Show Log, a drawer over `GET /pass-turns/:turnId/activity` (`turn-log-drawer.tsx`) read once it opens and again on each of its turn's `session.activity`; the page pane holds it, so it stays open as the turn ends. Each page's unsent draft lives in Sessions' draft store under `draftKey.task(taskId)` (`sessions/session-drafts.ts`), the key a pass of one's tab uses, so it survives another page, another view and, its words, a restart. Escape in a field (the composer, a question's note) goes back to the shown page's row, where J and K go on; the composer takes the cursor when the builder shows another page (a pointer click, N), not on the page the Workbench opens on and not from a row picked with the queue's keys (`QUEUE_ATTRIBUTE` in `queue-list.tsx`); as the window gains focus, a notification's click among its ways, the shown page's composer takes it whatever moved, unless a dialog is open (spec §4.3). Until the builder's first message a page's thread says where the page is, above any notice that lands first; Open Page is the composer's alone. A working page's line names the pass's median turn only once it is a minute or more, and a queue row's state line sits under the page's name, indented past the dot, and wraps rather than cut. A queue row (`queue-row.tsx`, `queue-row.module.css`) is drawn as an Inbox row: rounded, on the panel's row tones, a hairline to the next that goes beside a filled row, and its ⋯ shown on hover, on the shown page and with focus. Add Page is the shell's `CreateButton` at the queue's foot (`PassWorkspaceProps.onAddPage`), outside the list J and K step through, disabled once the pass is not open; the row menu's Remove reads "Take it out of this pass. Its changes move to its Board task." Notices, a card's body, the sign-off line, the close's summary and the closed pass's line draw each backtick pair as code (`shell/code-spans.tsx`), never as markup. Each queue row of an open pass has its own menu (`row-menu.tsx`, a sibling of the row's button; J/K skip it) with Take Out (`take-out-modal.tsx`), which reads `GET /passes/:passId/tasks/:taskId/take-out` first and offers Keep (the default) or Drop for each unlanded shared change (`shared-choices.tsx`: the pages that changed its files later named first, Drop disabled with its `dropRefusal`), then sends every choice in `shared`; a take-out that stopped short names the files that kept changing. A Ready item notifies "<Page> is ready" with a numeric id (`desktop/notify-pass.ts`), whose click selects the page and brings the window forward; the listener is registered once at mount and every send waits for it, and as the window gains focus the workspace selects by `focusTarget` (`decisions/2026-11-09-a-ready-notification-selects-its-page-by-its-id.md`). The window's `minWidth` is 420 px so the narrow layout shows in the app (`decisions/2026-11-09-the-window-narrows-to-the-workbench.md`). `e2e/workbench.spec.ts` drives the Workbench; its only unit tests are the start-pass and setup rule tables.
- The Workbench setup's Settings and Branch (`views/workbench/setup/`, `decisions/2026-11-10-workbench-setup-suggests-settings-from-origins-base.md`): `setting-drafts.ts` holds each suggested setting as the builder ticks and edits it (`settingDrafts`, all ticked) and the fields Apply sends (`settingsPatch`, folded into `setupPatch`'s one `PATCH`; an unticked or emptied row sends nothing, so an unticked Allow Docker records no opt-out). `setting-rows.tsx` shows each row's value editable in place with where it was found, and Allow Docker's warning in full while ticked; `branch-row.tsx` shows the base branch's unpushed commits with the push as a command to copy, never a button.
- Pictures of the builder's app (Workbench spec §10): `daemon/screen-queries.ts` reads a task's pictures (`GET /tasks/:taskId/screens`, refetched on `task.screen_added`), one picture as a data URL by id (`GET /screens/:screenId`, read once) and Settings' status line (`GET /projects/:projectId/pictures`, every 5 s, since the browser's download and a sign-in send no event). A page's thread shows its before beside where the page is until the builder's first message and at the top of the list after, and each turn's pictures under its reply, matched by turn id (`views/workbench/turn-pictures.tsx`); the task drawer shows each route, viewport and theme's before beside its after, or "No before picture" (`views/board/task-pictures.tsx`). Alt text (`screen-alt.ts`) says the page, when (before, after a turn with its number, after sign-off), the window and a theme other than the app's own. A task in a goal opens its thread with the pictures the goal's other tasks kept of its page (`TaskScreensDto.fromGoal`, under "Earlier in this goal", `OpeningPictures`), then its own before. The queue's rank 2 (`PageStatus.PreviewBroken`, red, waiting on the builder) is a Ready page whose turn broke the preview (`PassPageDto.preview`), "Preview broken: `/settings`", the row's line drawn through `CodeSpans`; it counts in the sidebar and the header and is announced. While `PassViewDto.preview` is `broken`, a working page reads "Working · changing · 4 min"; `pageStatus` takes the pass's pages and preview. The header's `preview` notice (no turn named) is yellow. Settings › General's Pictures of pages card holds the dev login command, the screenshot matrix (`settings/screens-matrix-field.tsx`: at most three viewports as width by height rows and the themes as checkboxes, checked by `checkGeneral` with the contract's cap of four pictures a route) and `settings/pictures-status.tsx`.
- `PagePane` takes an optional `header` in place of the page's label. `WorkbenchScreen` shows a live pass even where the project has no page area (a pass of one has the one `10db-whole-project` page, which `pageLabelIn` and `areaLabel` read as "Whole project"); the setup screen shows only when no pass holds tasks. `StartPass` takes the project's `FolderDto`: when its refusal is only chats' turns (`sessions/when-busy.ts`) it offers Stop the Turn and Open and Open When It Ends beside Start Pass (the request's `whenBusy`), and `PendingOpenLine` shows a pass waiting to open until the folder route drops it.
