# apps/desktop/src/views/workbench

- The Workbench (`views/workbench/`, spec `docs/superpowers/specs/2026-11-09-10db-workbench-design.md` §4) is the nav item between Plan and Knowledge at `/workbench` (`workbench-search.ts`: `task` selects a page, `tasks` comes from the Board's Work on These, `goal` from Factory's Work on This; each kept only when it parses). On `/workbench` a window under 900 px folds the sidebar (`collapsed` on both breakpoints, the navbar `inert`) behind a header burger beside the traffic lights, and under the shell's `sm` breakpoint (768 px) every view does, since the shell's mobile sidebar would cover the window; leaving the view folds it again. `WorkbenchScreen` (`workbench-view.tsx`) takes its reads (the live pass, `PassStartDto`, tasks, Inbox items, a goal's pages) and the daemon calls (`WorkbenchActions`: start, add pages, rename, abandon) as props, and hands the workspace `PassWorkspaceProps` through `renderWorkspace`; the route (`WorkbenchView`) fills them for the selected project from `daemon/pass-queries.ts` (`useLivePass` over `GET /passes?live=true`, `usePassStart`, read only when the project has a page area, `useGoalPassPages`, `useTurns`, and a mutation per route, each refetching `passKeys.all` once it lands) and keeps the selected page in `?task=`. With no page area it is the setup (`setup/workbench-setup.tsx`, `decisions/2026-11-10-the-workbench-setup-rebuilds-the-areas-for-one-apply.md`): `POST /projects/:projectId/workbench-setup` (`useWorkbenchSetup`, aborted when the screen goes, never retried by itself, standing ten minutes, and read for the picker's count only while no pass is open) proposes the areas rebuilt; Areas (`areas-section.tsx`) says what the list comes to in one line (`areasSummary`), each new page is a ticked row whose untick folds it back (`withoutPages`), the kept areas and what was left out say why, and the other areas are behind Show Other Areas; Settings (`settings-section.tsx`) and Branch (`branch-section.tsx`, the push as a command to copy) show when the daemon has them; one Apply (`setupPatch` in `setup-rules.ts`) sends one `PATCH /projects/:id`, a 400's words above it, and a list the project would refuse (`setupAreasProblem`) disables it; a setup with nothing to suggest says Nothing to set up. Once the project has page areas the rebuild is one row of its own, Rebuild areas, unticked, and Apply sends the areas only when it is ticked; a rebuild that changes nothing shows no Areas. With page areas, the picker's header offers Set Up (n) while the setup has settings or a branch note (`setUpCount`; new page rows show inside it but are not counted, so a page left out is not asked for again), with Back to Pages; with no pass, the picker (`start-pass.tsx`, `page-picker.tsx`, rules in `start-pass-rules.ts`: joinable tasks, a ticked row disabling every row that shares a page or a file by `globsOverlap`, at most `PASS_PAGE_CAP_MAX` pages, `passName`, `pageCap`) with Start Pass's lines (`start-lines.tsx`; each lack in words, those fixed in Settings › General with Open Settings: Docker off, no app address, and `no_changed_check`, "No changed-files check: turns run unchecked."); with a pass, `PassHeader` (`headerLine`, which wraps, with the actions moving under it, kept right, when the window is too narrow for both, so the ⋯ menu stays on screen (`e2e/workbench.spec.ts` measures it from 420 to 1280 px); Add Page, Open Pull Request once a page is signed off, ⋯ Close Pass/Rename/Abandon Pass, the timing hint, `close-progress.tsx` while closing, naming the next step that does anything for the project's delivery, gate and take-outs (whether it takes pages out held from the landing of its sign-offs, since each page taken out leaves the view before the step is recorded), and announcing only its first line, Abandon kept in reach) and its notices (`header-notices.tsx`: red for a failure, yellow for what needs a look, a color for every `PassNoticeKind`, a failed or unrun check after a turn (`turn_check`) red; each shows its first line, the rest (a failed gate's log tail) behind Show More (`aria-expanded`, `aria-controls`) in a pre-wrap block that scrolls; the close's own notice (`close`: a close that stopped) offers Continue Close while the pass is closing, and while it shows the header's close progress line is gone (`CloseFacts.stopped`), posting `POST /passes/:passId/close/continue`, its refusal said in the row; Send to Agent on a sendable one, offered only while the pass is open and disabled once sent, asks which page, then posts `POST /tasks/:taskId/thread/:noticeId/send-to-agent` for that page; a notice naming an open Retarget card offers Retarget to `<base>` while the pass is open or closed, answering it) over the workspace, and its dialogs (`add-page-modal.tsx`, `rename-modal.tsx`, `abandon-modal.tsx`, which names the pages that go back and those that stay and, from a close, says the close stops, refused once the close moves the folder's branch). Open Pull Request (`pr-button.tsx`) reads `GET /passes/:passId/pull-request` first: not offered, it is disabled with the daemon's reason (`PrReason`) on a line of its own under the header's row, which describes the button; offered, its confirm names the commits from before the pass that `origin` lacks and where the gate runs, then posts; the pull request's link shows once it has one. Close Pass (`close-pass-modal.tsx`, rules in `close-choices.ts`) reads `GET /passes/:passId/close`, which stops nothing, and sends `PassCloseRequest` with the preview's token: unfinished pages Take Out or Sign Off Now (Keep/Drop for a page taken out), files no page owns Leave Out or Add to a page that lands, foreign commits, the gate's consequence and the summary; an answer of `changed` redraws the lists, keeps the choices made, says what changed in the footer's alert beside Close Pass, and confirms with its new token. A close that finishes while the pass is on screen leaves one line above the picker, "Settings pass closed; its work is on main.", until another pass opens (an Abandon leaves none). A closed pass that has not settled is one line above the picker (`closed-pass-line.tsx`, words by its Move card's reason, else its pull request's state), with its notices, which offer no Send to Agent: its pull request, and Move `<branch>` to `origin/<base>` while its Move card is open, answering that card. The take-out and close previews are read afresh on each opening (`gcTime: 0`); the pull request preview is read only while the pass is open, again when a page is signed off or the pull request is made, the same pass's last answer standing until the new one arrives, so an open confirm stays open. `daemon/pass-close-queries.ts` calls the sign-off, take-out preview, pull request, close and Send to Agent routes through `DaemonClient`. Settings › General sets the project's App address (`ProjectPatch.appUrl`, a loopback origin). The batch sheet offers Work on These when every ticked task names a page; The sidebar's Workbench item counts the pages of the selected project's pass, while it holds pages, that wait on the builder (`views/workbench/workbench-count.ts`, the queue's ranks 1-3, read as "n pages waiting"). Factory shows each project's pass while it holds pages as `PassLine` ("Settings pass · 3 waiting"), which opens the Workbench in that project, and an open goal whose UI work is done or nearly so (`goalReadyForPass`) reads `GET /goals/:goalId/pass-pages`, only then and only while no pass of the project holds pages, and offers `WorkOnThis`. The task drawer says "Has saved Workbench work" with Discard Saved Work (`board/kept-work.tsx`, a confirm, then `DELETE /tasks/:taskId/kept-work`) and links the pass-wait notice to the Workbench. In a page (`page-pane.tsx`, `page-actions.ts`): Send posts to the thread, an empty composer's Stop posts `/tasks/:taskId/stop`, Stop and Redo posts the draft to `/thread/redo`, and Sign Off posts `POST /passes/:passId/tasks/:taskId/sign-off`; a page signing off says so at the foot of its thread (`sign-off-line.tsx`), and one waiting for another page's turn offers Cancel Sign-Off (`DELETE`, same path); a Ready page shown marks its turn opened once (`POST /tasks/:taskId/turns/:turnId/opened`, only while the pass's timing says it never was); a failed page says `passTurnFailureLine` (`board/task-state.ts`: what happened, and that Retry Turn sends the last message again) and offers Retry Turn (`retry-turn.tsx`), which answers the turn's flag with `PASS_RETRY_TURN_CHOICE`; a notice in the thread the daemon offers (`sendable`: a review finding or a failed check) has Send to Agent (`thread-message.tsx`) while the pass is open, which posts `POST /tasks/:taskId/thread/:messageId/send-to-agent` for that page and that notice and is disabled once sent. A page whose status is Asks (its run's question or permission: `askOf` in `page-status.ts`, carried as `QueueRow.ask`) draws the Inbox's own card in its pane (`page-ask.tsx`, `InboxCard` without the Inbox's key hints, keyed by the item so no draft passes to the next, gone once answered) and answers it through `POST /inbox/:id/answer` with the body the Inbox sends (`inbox/card-answer.ts`); slice 6's shared-code question is answered there too. A working page's line ends with Show Log, a drawer over `GET /pass-turns/:turnId/activity` (`turn-log-drawer.tsx`) read once it opens and again on each of its turn's `session.activity`; the page pane holds it, so it stays open as the turn ends. Escape in a field (the composer, a question's note) goes back to the shown page's row, where J and K go on; the composer takes the cursor when the builder shows another page (a pointer click, N), not on the page the Workbench opens on and not from a row picked with the queue's keys (`QUEUE_ATTRIBUTE` in `queue-list.tsx`); as the window gains focus, a notification's click among its ways, the shown page's composer takes it whatever moved, unless a dialog is open (spec §4.3). Until the builder's first message a page's thread says where the page is, above any notice that lands first; Open Page is the composer's alone. A working page's line names the pass's median turn only once it is a minute or more, and a queue row's line wraps rather than cut. Notices, a card's body, the sign-off line, the close's summary and the closed pass's line draw each backtick pair as code (`shell/code-spans.tsx`), never as markup. Each queue row of an open pass has its own menu (`row-menu.tsx`, a sibling of the row's button; J/K skip it) with Take Out (`take-out-modal.tsx`), which reads `GET /passes/:passId/tasks/:taskId/take-out` first and offers Keep (the default) or Drop for each unlanded shared change (`shared-choices.tsx`: the pages that changed its files later named first, Drop disabled with its `dropRefusal`), then sends every choice in `shared`; a take-out that stopped short names the files that kept changing. A Ready item notifies "<Page> is ready" with a numeric id (`desktop/notify-pass.ts`), whose click selects the page and brings the window forward; the listener is registered once at mount and every send waits for it, and as the window gains focus the workspace selects by `focusTarget` (`decisions/2026-11-09-a-ready-notification-selects-its-page-by-its-id.md`). The window's `minWidth` is 420 px so the narrow layout shows in the app (`decisions/2026-11-09-the-window-narrows-to-the-workbench.md`). Tests render a component with `renderWithTheme`, `renderWithRouter` (`test/theme.tsx`) or `renderWithDaemonAndRouter` (`test/daemon.tsx`) when it links elsewhere in the app.
- The Workbench setup's Settings and Branch (`views/workbench/setup/`, `decisions/2026-11-10-workbench-setup-suggests-settings-from-origins-base.md`): `setting-drafts.ts` holds each suggested setting as the builder ticks and edits it (`settingDrafts`, all ticked) and the fields Apply sends (`settingsPatch`, folded into `setupPatch`'s one `PATCH`; an unticked or emptied row sends nothing, so an unticked Allow Docker records no opt-out). `setting-rows.tsx` shows each row's value editable in place with where it was found, and Allow Docker's warning in full while ticked; `branch-row.tsx` shows the base branch's unpushed commits with the push as a command to copy, never a button.
- Pictures of the builder's app (Workbench spec §10): `daemon/screen-queries.ts` reads a task's pictures (`GET /tasks/:taskId/screens`, refetched on `task.screen_added`), one picture as a data URL by id (`GET /screens/:screenId`, read once) and Settings' status line (`GET /projects/:projectId/pictures`, every 5 s, since the browser's download and a sign-in send no event). A page's thread shows its before beside where the page is until the builder's first message and at the top of the list after, and each turn's pictures under its reply, matched by turn id (`views/workbench/turn-pictures.tsx`); the task drawer shows each route, viewport and theme's before beside its after, or "No before picture" (`views/board/task-pictures.tsx`). Alt text (`screen-alt.ts`) says the page, when (before, after a turn with its number, after sign-off), the window and a theme other than the app's own. A task in a goal opens its thread with the pictures the goal's other tasks kept of its page (`TaskScreensDto.fromGoal`, under "Earlier in this goal", `OpeningPictures`), then its own before. The queue's rank 2 (`PageStatus.PreviewBroken`, red, waiting on the builder) is a Ready page whose turn broke the preview (`PassPageDto.preview`), "Preview broken: `/settings`", the row's line drawn through `CodeSpans`; it counts in the sidebar and the header and is announced. While `PassViewDto.preview` is `broken`, a working page reads "Working · changing · 4 min"; `pageStatus` takes the pass's pages and preview. The header's `preview` notice (no turn named) is yellow. Settings › General's Pictures of pages card holds the dev login command, the screenshot matrix (`settings/screens-matrix-field.tsx`: at most three viewports as width by height rows and the themes as checkboxes, checked by `checkGeneral` with the contract's cap of four pictures a route) and `settings/pictures-status.tsx`.
