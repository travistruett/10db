# 10db Release Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.1.0 as a Developer ID signed, notarized and stapled Apple Silicon DMG, with `SHA256SUMS` and build provenance attestations. The release must come from a tag that only the release bot can create, and it is published only after Travis approves it and every step succeeds (spec §5).

**Architecture:** There are three workflows.
1. `release-please.yml` runs on every push to `main`, using a `10db-release-bot` App token. It keeps a Release PR open. Merging that PR makes it create a draft GitHub Release and its `vX.Y.Z` tag at once.
2. The tag push triggers `release.yml`. That workflow's single job waits in the protected `release` environment for Travis's approval. It then checks that every version file matches the tag, builds with `tauri build --target aarch64-apple-darwin`, and lets Tauri sign, notarize and staple the app. Next it notarizes and staples the DMG itself, verifies both with Gatekeeper, attests `SHA256SUMS`, uploads the assets, and finally flips the draft to published.
3. `release-dry-run.yml`, run by hand, builds the same DMG unsigned, with no secrets and no release.

Two small scripts hold the logic, so that it is testable outside CI: `scripts/release/check-version.mjs` and `scripts/release/build-macos.sh`. A repo test pins the workflows' security properties.

**Tech Stack:**
- Tauri 2.12 (`tauri` 2.12.3, `@tauri-apps/cli` 2.12.2).
- Xcode command-line tools: `codesign`, `xcrun notarytool`, `xcrun stapler`, `spctl`, `hdiutil`.
- release-please 17 through `googleapis/release-please-action` v5.0.0.
- `actions/create-github-app-token` v3.3.0, `actions/attest-build-provenance` v4.2.2.
- GitHub environments, Vitest 5, `yaml` 2.9.1.

**Spec:** `docs/superpowers/specs/2026-10-14-10db-repo-governance-design.md` (§5 versioning and releases; §4 workflow hardening; G8, G9). Read §4 and §5 before starting.

## Global Constraints

- **Platform:** Apple Silicon only: target `aarch64-apple-darwin`, runner `macos-15` (arm64). No Intel and no universal builds (G9). No auto-updates: no Tauri updater and no updater key (spec §5 Deferred).
- **Versioning:** one SemVer version for the whole repo, starting at `0.1.0`. Before 1.0, a breaking change bumps the minor version. Tags are plain `vX.Y.Z`.
- **Version files**, which release-please bumps together:
  - `package.json` (root)
  - `apps/desktop/src-tauri/tauri.conf.json` (`$.version`)
  - `apps/desktop/src-tauri/Cargo.toml` (`$.package.version`)
  - `apps/desktop/src-tauri/Cargo.lock` (the `tendb-desktop` entry)
  - `.release-please-manifest.json`
- **Environments:**
  - `release` holds every Apple secret. Its required reviewer is Travis (user id `1370873`), and it deploys from tags matching `v*` only.
  - `release-bot`, created by plan 04, holds the bot's credentials and deploys from `main` only.
- **Release secret names**, exactly:
  - `APPLE_CERTIFICATE` (base64 `.p12`)
  - `APPLE_CERTIFICATE_PASSWORD`
  - `APPLE_API_KEY` (App Store Connect Key ID)
  - `APPLE_API_ISSUER` (Issuer ID)
  - `APPLE_API_KEY_P8` (the `.p8` file's contents)
  - `APPLE_TEAM_ID`
- **Tauri 2.12 env var names**, verified in the `tauri-bundler` source at `tauri-cli-v2.12.2`:
  - `APPLE_CERTIFICATE` and `APPLE_CERTIFICATE_PASSWORD`: Tauri imports the certificate into a temporary keychain.
  - `APPLE_API_KEY`, `APPLE_API_ISSUER` and `APPLE_API_KEY_PATH`: notarization through App Store Connect.
  - `APPLE_SIGNING_IDENTITY` is optional when `APPLE_CERTIFICATE` is set, so this plan doesn't set it.
  - Tauri signs both the app and the DMG, but it notarizes and staples only the app. This plan notarizes and staples the DMG itself.
- **Action pins.** Every action is pinned to a full commit SHA with a `# vX.Y.Z` comment. The values, verified on 2026-10-14 (all six tags are lightweight tags that point straight at commits):
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`

  - `actions/attest-build-provenance@4d101475d8b20a2381f78447822ac1eab6504dd8 # v4.2.2`

The release-workflow test fails if the two drift. `renovate.json` has no custom manager for the `version:` input, so a one-sided bump is caught by that test and fixed by hand. Each job also sets `cache: false` and an `install_args` limited to the tools it needs (`node pnpm rust`).
- **Workflow hardening** (spec §4):
  - top-level `permissions: {}`, and each job lists exactly what it needs;
  - `persist-credentials: false` on every checkout;

## Review Focus

These are the five failure modes most likely to break the first real release. Each has a test or check in the owning task.
1. **release-please tags `10db-v0.1.0` instead of `v0.1.0`.** In manifest mode it puts the component in the tag by default, so `release.yml` would never fire. The config must set `include-component-in-tag: false`. The test is in Task 1.
2. **The Release PR can never pass `policy`.** Two separate causes would block it:
   - Its default title `chore(main): release …` uses a scope that isn't allowed.
   - release-please re-serializes `tauri.conf.json` with `JSON.stringify`, which expands `["app"]` across lines, and writes `* ` bullets in `CHANGELOG.md`. Prettier `--check` rejects both.

   The tests are in Task 1.
3. **The tag and the app version disagree**, e.g. a stale `Cargo.lock` or a `tauri.conf.json` that was never bumped. The DMG would then say 0.0.0. `check-version.mjs` must fail and name every stale file. The test is in Task 2.
4. **Notarization credentials are missing or misnamed.** Tauri then only warns and skips notarization, which would ship an app Gatekeeper rejects. The signed build must refuse to start without every variable, and it must end with `spctl` and `stapler validate` on the DMG and on the app inside it. The tests are in Task 2 and Task 3.
5. **A run that isn't a tag push reaches the signing secrets or the release**, e.g. the dry run or a PR. Only the tag-triggered job may bind `release`. The dry run must reference no secret, no environment and no `gh release`. The tests are in Task 3.

import { parse } from 'yaml';
import { readRepoFile } from './workspace';

interface WorkflowStep {
  readonly id?: string;
  readonly name?: string;
  readonly if?: string;
  readonly uses?: string;
  readonly run?: string;
  readonly with?: Readonly<Record<string, unknown>>;
  readonly env?: Readonly<Record<string, unknown>>;
}

interface WorkflowJob {
  readonly 'runs-on'?: string;
  readonly environment?: string | { readonly name: string };
  readonly permissions?: Readonly<Record<string, string>>;
  readonly steps?: readonly WorkflowStep[];
}

interface Workflow {
  readonly on: Readonly<Record<string, unknown>>;
  readonly permissions?: Readonly<Record<string, string>>;
  readonly jobs: Readonly<Record<string, WorkflowJob>>;
}

export const releaseWorkflowPaths = {
  release: '.github/workflows/release.yml',
  releasePlease: '.github/workflows/release-please.yml',
  dryRun: '.github/workflows/release-dry-run.yml',
} as const;

export function readWorkflow(path: string): Workflow {
  return parse(readRepoFile(path)) as Workflow;
}

export function environmentOf(job: WorkflowJob | undefined): string | undefined {
  const environment = job?.environment;
  return typeof environment === 'object' ? environment.name : environment;
}

export function stepsOf(job: WorkflowJob | undefined): readonly WorkflowStep[] {
  return job?.steps ?? [];
}

// Checks that every file carrying the app version agrees with the release version.
// Usage: node scripts/release/check-version.mjs <x.y.z>

}

function tomlString(section, key) {
  return new RegExp(`^${key}\\s*=\\s*"([^"]*)"`, 'm').exec(section)?.[1];
}

  .split(/^\[/m)
  .find((section) => section.startsWith('package]')) ?? '';

  '.release-please-manifest.json': JSON.parse(read('.release-please-manifest.json'))['.'],

- [ ] **Step 4: Write `build-macos.sh`**

`scripts/release/build-macos.sh`:
```bash
#!/usr/bin/env bash
# Builds the Apple Silicon DMG into dist/release/ and writes dist/release/SHA256SUMS.
#   signed    Tauri signs the app and the DMG with the Developer ID certificate, and notarizes
#             and staples the app. This script then notarizes and staples the DMG, and checks
#             the DMG and the app inside it with Gatekeeper. Needs APPLE_CERTIFICATE,
#             APPLE_CERTIFICATE_PASSWORD, APPLE_API_KEY, APPLE_API_ISSUER, APPLE_API_KEY_PATH
#             and APPLE_TEAM_ID.
#   unsigned  No signing and no notarization, for dry runs. Gatekeeper rejects the result.
set -euo pipefail

usage() { echo "usage: build-macos.sh signed|unsigned" >&2; exit 2; }
fail() { echo "build-macos.sh: $*" >&2; exit 1; }

mode="${1:-}"
[ "$mode" = signed ] || [ "$mode" = unsigned ] || usage

if [ "$mode" = signed ]; then
  missing=0
  for name in APPLE_CERTIFICATE APPLE_CERTIFICATE_PASSWORD APPLE_API_KEY APPLE_API_ISSUER APPLE_API_KEY_PATH APPLE_TEAM_ID; do
    if [ -z "${!name:-}" ]; then
      echo "build-macos.sh: $name is not set" >&2
      missing=1
    fi
  done
  [ "$missing" -eq 0 ] || exit 1
  [ -f "$APPLE_API_KEY_PATH" ] || fail "APPLE_API_KEY_PATH does not point to a file"
fi

[ "$(uname -s)-$(uname -m)" = Darwin-arm64 ] || fail "needs an Apple Silicon Mac, got $(uname -s)-$(uname -m)"

root="$(cd "$(dirname "$0")/../.." && pwd)"
target=aarch64-apple-darwin
bundle="$root/apps/desktop/src-tauri/target/$target/release/bundle"
out="$root/dist/release"
rm -rf "$bundle" "$out"
mkdir -p "$out"

if [ "$mode" = signed ]; then
  pnpm --filter @10db/desktop tauri build --target "$target" --bundles dmg
else
  pnpm --filter @10db/desktop tauri build --target "$target" --bundles dmg --no-sign
fi

shopt -s nullglob
dmgs=("$bundle"/dmg/*.dmg)
[ "${#dmgs[@]}" -eq 1 ] || fail "expected one DMG in $bundle/dmg, found ${#dmgs[@]}"
dmg="$out/$(basename "${dmgs[0]}")"
cp "${dmgs[0]}" "$dmg"

team_of() { codesign --display --verbose=4 "$1" 2>&1 | sed -n 's/^TeamIdentifier=//p'; }
json_field() { node -p "JSON.parse(require('node:fs').readFileSync(process.argv[1], 'utf8')).$2" "$1"; }

if [ "$mode" = signed ]; then
  codesign --verify --strict --verbose=2 "$dmg"
  [ "$(team_of "$dmg")" = "$APPLE_TEAM_ID" ] || fail "the DMG is not signed by team $APPLE_TEAM_ID"
  result="$(mktemp)"
  xcrun notarytool submit "$dmg" --key "$APPLE_API_KEY_PATH" --key-id "$APPLE_API_KEY" \
    --issuer "$APPLE_API_ISSUER" --wait --output-format json > "$result"
  status="$(json_field "$result" status)"
  if [ "$status" != Accepted ]; then
    xcrun notarytool log "$(json_field "$result" id)" --key "$APPLE_API_KEY_PATH" \
      --key-id "$APPLE_API_KEY" --issuer "$APPLE_API_ISSUER" >&2 || true
    fail "notarization of the DMG ended with status $status"
  fi
  xcrun stapler staple "$dmg"
  xcrun stapler validate "$dmg"
  spctl --assess --type open --context context:primary-signature --verbose=4 "$dmg"
fi

mount="$(mktemp -d)"
hdiutil attach -nobrowse -readonly -mountpoint "$mount" "$dmg" > /dev/null
trap 'hdiutil detach "$mount" -quiet || true' EXIT
apps=("$mount"/*.app)
[ "${#apps[@]}" -eq 1 ] || fail "expected one app in the DMG, found ${#apps[@]}"
app="${apps[0]}"
binaries=("$app"/Contents/MacOS/*)
[ "$(lipo -archs "${binaries[0]}")" = arm64 ] || fail "$(basename "${binaries[0]}") is not arm64-only"
if [ "$mode" = signed ]; then
  codesign --verify --deep --strict --verbose=2 "$app"
  [ "$(team_of "$app")" = "$APPLE_TEAM_ID" ] || fail "the app is not signed by team $APPLE_TEAM_ID"
  xcrun stapler validate "$app"
  spctl --assess --type execute --verbose=4 "$app"
fi
hdiutil detach "$mount" -quiet
trap - EXIT

(cd "$out" && shasum -a 256 -- *.dmg > SHA256SUMS)
echo "build-macos.sh: $mode build ready in dist/release/"
cat "$out/SHA256SUMS"
```
Checksums are computed last, because stapling changes the DMG's bytes. The script uses only bash 3.2 features, since that is macOS's `/bin/bash`; it avoids empty arrays under `set -u`.
