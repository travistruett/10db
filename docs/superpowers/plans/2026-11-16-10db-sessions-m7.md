# Sessions M7: Open in Terminal and Hand Back

## Brief

**What changes for you.** A chat gets **Open in Terminal**. It closes the chat's session and continues the
conversation in the agent's own TUI, `claude --resume` or `codex resume`, with the chat's instructions, plugins and
MCP servers and without your settings file. Settings › Sessions picks how it opens: in Terminal, in iTerm, or
**Copy the Command** to paste into any terminal (Ghostty, Warp, kitty). The tab reads "In your terminal" until you
click **Hand Back**. Messages you type meanwhile wait, then run on the agent's own session, which remembers the
terminal's turns. It works on a Claude plan, an API key, Bedrock, a gateway and Codex.

**What it buys.** Everything 10db doesn't do yet (TUI-only commands, plan mode, rewind) is one click away, on the
same conversation.

**What could go wrong, and how we'd know.**
- **The terminal runs outside 10db's sandbox and judge.** Its own prompts guard it, and the popover says so every
  time. What still holds:
  - no key in the script, a command line or the agent's shell, wherever the agent allows it
  - no settings file and no project hook
  - only approved MCP servers, with the project's still in their sandbox
  - your folder held
- **A forgotten Hand Back holds Your folder.** Tasks, branch cuts, switch-backs and passes wait, each naming "the
  chat ‘X’ in your terminal". Each wait keeps its project's delivery slot. While 10db's own git work waits, other
  chats' turns read only, and a 10db update waits for Hand Back.
- **Quitting 10db while a terminal holds the folder** could have hung on that waiting git work. M7 makes the waits
  stop with 10db and resume at the next start, and a real restart test proves it.
- **Each harness's flags.** Six live checks need your accounts. Until they pass, the PR names what is unproven.

**Calls you might disagree with:**
- **Chats only.** A task's Open in Terminal needs runner work, so it is a follow-up.
- **The choice lives in Settings › Sessions,** not General.
- **On a Bedrock key account, the terminal's commands don't see the key.** Claude Code can't then use auto mode
  there. API-key and gateway accounts read their key through a helper and keep auto mode.
- **Codex runs as Codex does by default.** 10db's lane-only settings are switched off, except the billing line and
  the folder's `untrusted` pin. It gets no skills folders: Codex has no flag for them.
- **Opening again while open** opens another window: two writers on one session, as Copy the Command allows.

**Migrations:** none. **Needed from you:** run live checks LC1-LC6 before merge. Reply to approve.

## Global Constraints

- Every takeover file lives in `<dataDir>/conversations/<id>/takeover/`, mode 700. That includes the script,
  `takeover.command` (mode 700). The spec's §7.5 path moves into this one folder, so one removal clears it.
- The script's first command after the shebang is `rm -- "$0"`. No secret is in it.
- A key is read with `/usr/bin/security find-generic-password -s 10db -a <secretRef> -w`:
  - inside Claude Code's `apiKeyHelper` where the account allows it
  - else in the script, with `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`
- The daemon runs `/usr/bin/open -a <Terminal|iTerm> <script>` with `execFile`, never a shell. The webview gets no
  new capability.
- Words:
  - Banner: "In your terminal. This runs outside 10db's sandbox. 10db won't touch this session until you hand it
    back."
  - Hand Back notice: "Turns from your terminal are in the agent's memory; they aren't shown here."
  - Refusal: "Your folder is in use by {holder}"
  - Held line: "Held until you hand back"
  - Hand Back's question: "Is {capabilities.label} closed in your terminal?"
- No label names a provider except through `capabilities.label`. The popover's harness-specific lines come from the
  daemon as text.
- Code style: `as const` objects, branded IDs, and zod at every boundary (the setting, the takeover file, the
  provider session id, the routes). Typed errors with `name`. No `as` casts.
- No new dependency.
- **Every wait on Your folder passes `AbortSignal.any([jobSignal, own])`** to `reserveGitWhenFree`. This covers
  M6a's waits, M7's, and M6b's Open When It Ends, so `deliveryJobs.stop()` always ends them.
- **A handed-over token is never leaked** (M6b plan review r2, R2-B2). `reserveGitWhenFree` releases a token whose
  signal aborted before it rejects, and each caller releases in a `finally` that wraps its re-checks. This covers
  the switch back, the pass card's `switchFolder`, and the git work that Hand Back wakes.

## Design

### What the terminal session is, and what protects it

The builder's own TUI on the pinned binary, outside 10db's sandbox, guard and judge. 10db adds no restriction the
agent lacks (root `AGENTS.md`), keeping only what a hard limit or its own coordination needs.

| Still holds | Gone while in the terminal |
| --- | --- |
| The TUI's own permission system: Claude Code's mode, Codex's sandbox and approvals | 10db's kernel sandbox: writes anywhere the builder can, reads secrets, any network |
| No settings file (`--setting-sources ''`): no project or user hook, allow list or billing switch | 10db's judge, trust policy and limits: a push or a merge is the TUI's to ask about |
| Only approved MCP servers (`--strict-mcp-config`). The project's stdio servers still run in their own `srt` sandbox. 10db's `/mcp` server is not there | The guard's git rules: `.git` writes, git hooks and the credential helper all work |
| No key in the script, an argv or a file 10db writes. On API key and gateway, none in the TUI's environment either (`apiKeyHelper`). On a Bedrock key, the key is in the env but kept from its commands (`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`). Codex's header tokens are excluded from shell commands | Protected reads: the terminal agent can run `security` and read 10db's account keys, the data dir and `~/.claude.json`, behind the TUI's prompt only |
| Your folder held: no lane, branch cut, switch back or pass runs under it | `endJobs`: what the terminal starts runs until the builder stops it |
| Pinned binary, no auto-update | |

### The flow

All of one chat's takeover calls (open, again, Copy the Command, Hand Back, archive's end) run in order on one
per-chat chain in `takeover/service.ts`, so they never interleave. Messages and Stop go to the engine, which refuses
them by state.

**Open** (`POST /conversations/:id/takeover`). The chat is **opening** (in the service's memory) from step 1 until
step 5:
1. Refuse early, each with its words:
   - not a chat: "Only a chat opens in your terminal for now"
   - archived: "This chat is archived"
   - the reducer's busy words (`busyWords`)
   - `folderHold.blockers(projectId, { kind: Takeover, chatId })`: "Your folder is in use by {holder}"
   - the pinned agent not ready: its status words
2. `prepareTakeover` writes the files. **Any throw from here to step 5 removes them.**
3. `folderHold.takeOver(projectId, chatId, () => engine.openTerminal(convId))`, synchronous:
   - the blockers are checked again
   - the engine refuses a retired or archived chat, or a busy state (a message sent during step 2 may have
     started a turn)
   - else it reduces `open_terminal`, writing `taken_over`
   - then `FolderHoldChanged` is emitted

   It answers `{ closed: Promise<void> }`, which settles once the `Close` effect has run (spec §7.5 step 1).
4. `await closed`. Then check the state is still `taken_over`; if not, remove the files and refuse.
5. By the setting:
   - **Terminal or iTerm:** `opener(app, script)`. A failure runs `folderHold.handBack(…, () =>
     engine.terminalFailed(convId))`, removes the files, and answers 502 with the reason ("iTerm isn't installed.
     Choose another in Settings › Sessions.").
   - **Copy the Command:** nothing is opened. The answer carries the line, and the UI copies it.
6. Answer `TakeoverDto`.

**Again, or Copy the Command while taken over** (`POST …/takeover`, `POST …/takeover/command`): check
`taken_over`, re-prepare every file (never read back: the terminal agent can write them), then open or answer the
line. The state and hold don't change.

**Hand Back** (`POST …/hand-back`):
1. `engine.holdStarts(convId)`, then `chatService.watchFolder(chat)` (Wait for It's path). The held messages wait
   for the folder rather than running read-only.
2. `folderHold.handBack(projectId, chatId, () => engine.handBack(convId))`: reduce `hand_back`, which writes the
   notice, then `changed`, then `serveWaiters`.
3. Remove the files.

**Ordering.** A waiting `reserveGitWhenFree` (`freeing`) blocks chat askers, so the chat's waiter isn't served
while git work waits. `flushFree` hands the reservation over inside the wake (M6b review r1 F2: whichever of M6b
and M7 lands first carries that change). So the git work holds before anything else runs, and the chat's messages
run at its release. That is git first, deterministically.

**Archive while taken over:** after the UI's confirm, `archiveChat` awaits `engine.retire` (→ `idle_cold`), then
`folderHold.handBack(projectId, chatId, () => {})` tells the scheduler and serves waiters, then the files go.
`takenOverChats` skips archived chats, so no path leaves an archived holder.

**Restart:** `taken_over` is a row, which the hold reads and the engine's restart row keeps. A taken-over chat's
files stay, so its terminal keeps working; `sandbox/stale-files.ts` skips the server temp dirs a live
`takeover.json` names. `takeover.recover()` removes the folder of any chat not `taken_over` (a restart while
opening). Recovery's switch back is queued, not awaited (`7eda3576`); Task 1 gives it the job's signal.

**The update drain is unchanged** (call 10): counting folder waits as parked needs a rule for which waits a
restart redoes, and M6b's pending open isn't redone.

**New reducer event:** `terminal_failed`. From `taken_over` it goes to `idle_cold` with `RunQueue`; anywhere else
it stays. `HandBackNotice` is applied for real (today it does nothing).

**Fix found while designing.** `ExploreEngine.reduce` calls `turnStarting` for any `builder_message` from outside
`BUSY` with something queued. A message while `taken_over` or `paused_account` therefore:
- takes a chat hold and releases it, emitting `FolderHoldChanged` twice
- consumes a Send Reading Only choice (`takeReadOnlyChoice`, `chat/hooks.ts`) that was meant for the turn after
  Hand Back

The fix: the engine calls `turnStarting` only when `takesTurn(reduceExplore(rt.state, event, facts))` is true.

### The script and the line

`renderTakeover(cmd): { script: string; line: string }` (pure, `takeover/render.ts`). Every value goes through
`singleQuoted`. A NUL throws `TakeoverRefusedError`.

```sh
#!/bin/sh
rm -- "$0"
cd -- '<cwd>' || exit 1
for v in $(/usr/bin/env | /usr/bin/sed -n 's/^\(ANTHROPIC_DEFAULT_[A-Za-z0-9_]*\)=.*/\1/p'); do unset "$v"; done
                                              # one loop per prefix; names only match [A-Za-z0-9_]
. '<sealed env file>'                         # Codex header tokens only
AWS_BEARER_TOKEN_BEDROCK=$(/usr/bin/security find-generic-password -s 10db -a '<ref>' -w) || {
  echo '10db could not read this account’s key from the Keychain.'; exit 1; }
export AWS_BEARER_TOKEN_BEDROCK               # Bedrock key only
/usr/bin/env -u '<VAR>' … '<NAME>=<value>' … '<binary>' '<arg>' …
echo; echo 'Back in 10db, click Hand Back.'
```

- `$(cat -- '<file>')` is an `ArgFromFile { prefix, file }` element, rendered inside double quotes. It is never raw
  text.
- `line` is `/bin/sh -c '<the body without rm>'`, so it runs the same in zsh, bash or fish, and leaves nothing
  exported in the builder's shell.
- **Files** (`takeover/files.ts`):
  - `conversations/<id>` and `takeover/` must `lstat` as real directories under the data dir's real path. A link
    there is refused, never followed, and removal checks the same before the recursive remove.
  - Each file is written after `unlink`, with `open(path, 'wx', mode)`, then `chmod`: the script mode 700, the
    rest mode 600.
  - `takeover.json` keeps only `since`, the app and the server temp dirs. It is display data, read through zod, and
    nothing is run from it.

### Changed setting files and notes

`settingFilesChanged(changed, checkout)` (pure, `takeover/setting-files.ts`) filters `Git.changedPaths(checkout)`.
That is read against a private index, so no filter, fsmonitor or submodule runs. It keeps
`claudeProtectedPaths(checkout)` (`sandbox/file-access.ts`) and `.codex/`, compared case-folded (APFS).

daemon writes the notes, so the UI never branches on the harness:
- "Your folder is held until you hand back."

- the harness's first screen (Codex: "Codex asks how to open the folder first: choose Open restricted.")
- each gap ("Codex in your terminal doesn't get your skills folders.")
- the closed-pass warning
