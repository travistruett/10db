# Sessions M7: Open in Terminal and Hand Back

## Brief

**What changes for you.** A chat gets **Open in Terminal**. It closes the chat's session and opens your Terminal
(or iTerm, set in Settings › Sessions) on the agent's own TUI. That is `claude --resume` or `codex resume` on the same
conversation, with the chat's instructions, plugins and MCP servers, and without your settings file. The tab reads
"In your terminal" until you click **Hand Back**. Messages you type meanwhile wait, then run on the agent's own
session, which remembers the terminal's turns. It works on every account: a Claude plan, an API key, Bedrock, a
gateway and Codex.

**What it buys.** Everything 10db doesn't do yet (`/`-commands only the TUI has, plan mode, rewind, `/resume`
pickers) is one click away, on the same conversation.

**What could go wrong, and how we'd know.**
- **The terminal runs outside 10db's sandbox and judge.** It is your own Claude Code or Codex. Only its own
  permission prompts guard it: Claude Code's ask or auto mode, Codex's sandbox and approvals. The popover says so
  every time. The security table below lists what still holds: no key in a file or on a command line, no settings
  file, no project hook, only approved MCP servers, and your folder held.
- **A forgotten Hand Back holds Your folder.** Tasks, branch cuts, switch-backs and passes wait, each naming "the
  chat ‘X’ in your terminal". A wait keeps its project's delivery slot, so that project's other delivery work queues
  behind it.
- **Quitting or updating 10db while a terminal holds the folder** could have hung on 10db's waiting git work. M7
  makes those waits stop with 10db and resume at the next start. A real restart test proves it.
- **Each harness's flags.** Six live checks need your accounts and a real Terminal. Until they pass, the PR says
  which provider is unproven.

**Calls you might disagree with:**
- **Chats only.** A task's Open in Terminal needs runner work (its lane, claims and recovery). It is filed as a
  follow-up.
- **The terminal app setting lives in Settings › Sessions,** not General: Sessions holds every other chat setting.
- **Codex in the terminal doesn't get your skills folders.** Codex has no flag for them. The banner says so, and a
  follow-up closes the gap.
- **Opening again while already open** just opens another terminal window. Two windows on one session are two
  writers, as Copy Command already allows.
- **The project's approved MCP servers run unsandboxed in the terminal,** as Claude Code runs them. The whole
  terminal is outside the sandbox, so a sandbox around one server buys nothing.

**Migrations:** none. The terminal choice is a field in the existing Sessions app setting.

**Needed from you:** nothing to start. To finish, run the live checks LC1-LC6 with your accounts. Reply to approve.

- Code style: `as const` objects, branded IDs, zod at every boundary (the setting, the takeover file read back, the

- Pin nothing new: no dependency is added.

## Review Focus

1. **A takeover that outlives 10db.** Quit or update while a terminal holds the folder and 10db's git work waits.
   10db must stop promptly and pick the work up after restart (Tasks 1-3).
2. **A planted link where the script or its folder goes.** The terminal agent runs as the builder and can write the
   data dir. A link must never redirect the next write (Task 9).
3. **Agent-controlled text reaching the script:** instructions from `AGENTS.md`, a repo server's args, a model ID,
   the provider session id. None may break out of its quoting or turn into an option (Tasks 8, 9).
4. **A held message during a takeover.** It must take no hold and write no "reads only" notice. It runs exactly
   once after Hand Back, through a restart too (Tasks 5, 12).
5. **`open` fails** (iTerm not installed, Linux CI): the chat must not stay `taken_over` holding the folder
   (Tasks 4, 12).

## Design

### What the terminal session is, and what protects it

The terminal runs the builder's own agent TUI on the pinned binary, outside 10db's kernel sandbox, guard and judge.
10db adds no restriction Claude Code or Codex doesn't have (root `AGENTS.md`: trust the developer). It keeps only
three things: its own writers apart (the hold), no key leaked, and no agent-written config loaded unseen.

| Still holds | Gone while in the terminal |
| --- | --- |
| The TUI's own permission system: Claude Code's mode (ask, or auto mode with its built-in rules), Codex's sandbox (`workspace-write`) and approvals (`on-request`) | 10db's kernel sandbox: writes anywhere the builder can, reads secrets, any network |
| No settings file (`--setting-sources ''`), so no project or user hook, permission allow list or billing switch | 10db's judge, trust policy and limits (§2): a push, a force push or a merge is the TUI's to ask about |
| Only approved MCP servers (`--strict-mcp-config`); 10db's own `/mcp` server is not in it | The guard's git rules: `.git` writes, git hooks and the builder's credential helper all work |
| No key in the script, an argv or a file 10db writes; keys are read from the Keychain inside the script | Protected reads: the terminal agent can run `security` as the script does and read 10db's account keys, the data dir and `~/.claude.json`, behind the TUI's prompt only |
| Your folder held: no lane, branch cut, switch back or pass runs under it | `endJobs`: what the terminal starts runs until the builder stops it |
| Pinned binary, no auto-update (`DISABLE_AUTOUPDATER=1`; `check_for_update_on_startup=false`) | |

The popover and the banner say "outside 10db's sandbox" every time. `docs/security.md` gets this table.

### The flow

**Open in Terminal** (`POST /conversations/:id/takeover`):
1. Refuse early: not a chat ("Only a chat opens in your terminal for now"); the reducer's refusals; any
   `folderHold.blockers(projectId, { kind: Takeover, chatId })` ("Your folder is in use by {holder}"); the pinned
   agent not ready (its status words).
2. `prepareTakeover` (async): the setup dir, servers, instructions file, onboarding marks, the changed setting
   files, the command, the script, and `takeover.json`.
3. `folderHold.takeOver(projectId, chatId, () => engine.openTerminal(convId))`. This call is synchronous: it checks
   the blockers again, the engine reduces `open_terminal` (writing `taken_over`), and `FolderHoldChanged` is emitted.
   A blocker found here removes what step 2 made and refuses.
4. `opener(app, scriptPath)`. A failure (non-zero exit) runs `folderHold.handBack(..., () =>
   engine.terminalFailed(convId))`, removes the takeover's files, and answers 502 with the reason: "iTerm isn't
   installed. Choose Terminal in Settings › Sessions."
5. Answer `TakeoverDto`.

**Hand Back** (`POST /conversations/:id/hand-back`):
- `folderHold.handBack(projectId, chatId, () => engine.handBack(convId))` reduces `hand_back`, which writes the
  notice and runs the queue.
- Then it removes the takeover folder and the script, if the script is still there.

**Again while taken over:** the same POST writes a fresh script from the kept `TakeoverCommand` (in
`takeover.json`) and opens it. No state or hold changes.

**Archive while taken over:** the UI confirms "End takeover and archive?". `archiveChat` then runs `engine.retire`
(the reducer's confirmed archive goes to `idle_cold`), emits `FolderHoldChanged`, serves the waiters, and removes
the chat's folder, the takeover's with it.

**Restart:** `taken_over` is a row. The hold reads it (`takenOverChats`), the engine's restart row keeps it, and
`takeover.json` and the setup files stay on disk, so the terminal keeps working. Recovery's switch back is queued,
not awaited (built: `7eda3576`). M7 makes every wait on the folder stop with the daemon (Tasks 1-3).

The new reducer event is `terminal_failed`: from `taken_over` → `idle_cold` with `RunQueue`; anywhere else, stay.
`HandBackNotice` is applied for real (today it does nothing).

**Fix found while designing:** `ExploreEngine.reduce` calls `turnStarting` for any `builder_message` from outside
`BUSY` with something queued. A message while `taken_over` (or `paused_account`) therefore takes a chat hold, then
releases it. A refused take also writes a stray "reads only" notice. The engine calls `turnStarting` only when the
reducer's outcome begins a turn (`takesTurn(reduceExplore(...))`, computed with the real facts first).

### `takeoverCommand`: the table

`TakeoverSpec` is what the chat's session had, rebuilt by `prepareTakeover`:
- `binary` (the pinned path), `cwd`, `providerSessionId` (validated), `model` (the launch id), `effort`
- the account kind and the launch's `TakeoverLaunch`
- `pluginDirs`
- the instructions file
- the MCP config file (Claude) or `codexServers` (Codex)
- `web` (the switch)

The result is `TakeoverCommand { cwd, unset[], set{}, keychain[{variable, account}], sources[], argv[] }`, with
`argv[0]` the binary. One row per cell in `sessions/claude-takeover.test.ts` and `sessions/codex-takeover.test.ts`.

Extra rows:
- a server name `McpServerName` (`sessions/mcp-server-name.ts`) rejects is left out
- a project stdio server whose env holds a literal value under `SENSITIVE_NAME` is left out on Codex ("its env
  holds a secret 10db won't put on a command line"); `${NAME}` values become `env_vars`
- a provider session id outside `^[A-Za-z0-9-]{1,128}$` throws `TakeoverRefusedError`
- no instructions: no instructions flag

**Servers.** A takeover uses the session's set, from the same reads (`createShapePreparer`'s pieces):
- **Your stdio servers:** `launchYourMcpServers` with the takeover folder as the files root, so their sealed env
  files live until Hand Back.
- **Your remote servers:** URL, headers and `oauth`.
- **Project servers:** the approved ones, as the repo declares them (`${VAR}` unexpanded, so Claude Code expands
  them from the terminal's env), unsandboxed (call). A server whose approval names an AWS profile gets `AWS_PROFILE`
  in its `env`. Remote ones are filtered to public hosts, as for a session.
- **Never:** 10db's own `/mcp` server. Its tools need a live 10db session, and the terminal has git itself.
- **Connectors** (plan, switch on): the relay's `claudeai-proxy` entries in `mcp.json`. LC2 checks that the CLI
  takes them from a file. If it doesn't, they are left out and the banner says so.

**Instructions:** only the setup's (`setupPromptText`: the project's and the builder's instructions). 10db's chat
prompt names `/mcp` tools the terminal lacks, so it stays out (call).

### The script

`renderTakeover(cmd): { script: string; line: string }` (pure, `takeover/render.ts`). Every value is
`singleQuoted` (`sandbox/posix-quote.ts`). A value with a NUL throws `TakeoverRefusedError`. The script:

```sh
#!/bin/sh
rm -- "$0"
cd -- '<cwd>' || exit 1
. '<sealed env file>'                       # once per source, Codex remote headers only
ANTHROPIC_API_KEY=$(/usr/bin/security find-generic-password -s 10db -a '<secretRef>' -w) || {
  echo '10db could not read this account’s key from the Keychain.'; exit 1; }
export ANTHROPIC_API_KEY
/usr/bin/env -u '<VAR>' … '<NAME>=<value>' … '<binary>' '<arg>' …
echo
echo 'Back in 10db, click Hand Back.'
```

- `$(cat -- '<file>')` is the one unquoted-looking form, always inside double quotes. Its file is 10db's. The
  renderer takes it as an `ArgFromFile { prefix, file }` argv element, never as raw text.
- **`line`** is the same body in one subshell, `( cd -- … && … && /usr/bin/env … )`, so no key stays exported in
  the builder's shell. Copy Command copies it.
- **Writing:** the takeover folder is `<dataDir>/conversations/<id>/takeover/`, mode 700, made after `lstat` shows
  nothing or a real directory (a link is removed, never followed). The script is written after `unlink` of whatever
  is at its path, with `open(path, 'wx', 0o700)` (`O_EXCL` never follows a link), then `chmod 0o700`.
- `mcp.json` and the instructions file are written the same way, mode 600.
- `takeover.json` (mode 600) holds a `TakeoverFile`: the `TakeoverCommand` (no secret in it), `since`, the app,
  `changedSettingFiles` and `leftOut`. It is read back through zod.

### Changed setting files

`settingFilesChanged(changed: readonly string[], checkout: string): string[]` (pure, `takeover/setting-files.ts`)
filters `Git.changedPaths(checkout)` (uncommitted and untracked, read without running status) to:
- `claudeProtectedPaths(checkout)` (`sandbox/file-access.ts`: `.claude/settings*.json`, `.mcp.json`,
  `.claude/{hooks,skills,agents,commands}/`)
- `.codex/`

Names are compared case-folded (APFS). The banner and the popover list them: "These project files changed and
won't be loaded: …". The settings files and hooks never load (`--setting-sources ''`). `.mcp.json` servers load only
by approved hash. Whether Claude Code loads a changed `.claude/skills` file natively is LC1's question; the banner
names it either way.

## Calls (with their cost if wrong)

1. **Chats only.** Cost: a pass of one or a task can't go to the terminal until the follow-up.

4. **Project servers run unsandboxed in the terminal.** Cost: a repo server runs as Claude Code would run it, with
   no `srt`; only approved hashes run.

   tools the terminal lacks.

   allows.

   that project's delivery queue, named in every wait. Follow-up: the wait leaves the slot.
8. **A closed pass allows Open, with a warning.** Cost: a terminal commit makes the settle stop and ask (today's Move
   card).
