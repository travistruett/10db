- **The data migration.** `pnpm exec drizzle-kit generate --custom --name slack_workspaces_backfill` in
  `packages/db`, authored once by hand, after the generated one. Comment each statement with what and why.
  1. **Each send's team from its first recipient's contact**, matched on person and Slack user, so a contact
     re-pointed at another user since doesn't claim old sends:
     `UPDATE stakeholder_sends SET team_id = (SELECT pc.team_id FROM stakeholder_send_people sp JOIN
     person_contacts pc ON pc.person_id = sp.person_id AND pc.user_id = sp.user_id WHERE sp.send_id =
     stakeholder_sends.id AND sp.recipient = 1 ORDER BY sp.position LIMIT 1) WHERE team_id IS NULL`.
  2. **A send with no matching contact takes the workspace signed in now:**
     `UPDATE stakeholder_sends SET team_id = (SELECT json_extract(value, '$[0].teamId') FROM app_settings WHERE
     key = 'slack.workspaces') WHERE team_id IS NULL`.
     - Before this build every writer kept at most one entry, so `$[0]` is that one.
     - It is the only place in the branch that reads the first entry; say so in the comment.
  3. **The migration returns its live orphans itself.** A live send whose team is still null (no matching
     contact and no workspace) can never be posted or read. The same migration fails it and gives its card to
     the builder, as `failSendsToBuilder` would:
     - `UPDATE inbox_items SET assignees = '["me"]', routed_by = 'builder', route_suggestion = NULL WHERE id IN
       (SELECT inbox_item_id FROM stakeholder_sends WHERE team_id IS NULL AND state IN ('draft', 'sending',
       'sent'))`;
     - then `UPDATE stakeholder_sends SET state = 'failed', error = 'no_workspace', updated_at = <now> WHERE
       team_id IS NULL AND state IN ('draft', 'sending', 'sent')`.
     - Closed, failed and answered sends keep a null team: history that counts for no workspace.
  4. **Every project without a stored choice is bound to that workspace:**
     `INSERT OR IGNORE INTO app_settings (key, value, updated_at) SELECT 'slack.' || p.id,
     json_object('teamId', json_extract(s.value, '$[0].teamId')), <now> FROM projects p JOIN app_settings s ON
     s.key = 'slack.workspaces' WHERE json_array_length(s.value) > 0`. `OR IGNORE` keeps a stored choice, Off
     (`{"teamId":null}`) included.
  - Check every name against `packages/db/src/schema.ts` before writing:
    - `inbox_items.assignees` and `route_suggestion` are JSON text;
    - `routed_by` takes `RoutedBy.Builder` (`'builder'`), and `BUILDER_HANDLE` is `'me'`;
    - `app_settings.value` is JSON text;
    - write `<now>` in the ISO format other rows use (`strftime('%Y-%m-%dT%H:%M:%fZ', 'now')`).
  - No event is emitted: the daemon reads the rows at start.

## State-table rows

| State | Event | Next |
|---|---|---|
| upgrade, one workspace W | migration | every project without a setting bound to W; a stored Off stays Off; each send gets its team; contacts keep their rows (card 6) |
| upgrade, a live send whose team can't be found | migration | failed `no_workspace` and its card back to the builder, by the migration itself (card 6) |
| upgrade, no workspace | migration | nothing is bound; every project reads Off (card 6) |

## Tests

Core: a migration. One new file, `packages/db/src/migrations-slack-workspaces.test.ts`, on the pattern of
`migrations-model-ids.test.ts`: a real database file in a temp directory, migrated with `migrationsBefore` to the
migration before this one, seeded with SQL, then migrated the rest of the way.
- **One workspace.** Seed `slack.workspaces` with W; projects P1 (no setting) and P2 (`{"teamId":null}`); Mark
  with a W contact (`UM`) and a DM channel; two sent sends, one to Mark as `UM` and one whose recipient's contact
  was deleted. After the migration:
  - the contact count and Mark's row are unchanged;
  - both sends have team W;
  - P1's setting is `{"teamId":"W"}` and P2's is still `null`;
  - Mark can be given a contact in a second team, and a second W contact is refused by the unique index.
- **No workspace.** The same seed without `slack.workspaces`:
  - no `slack.` setting is written;
  - the send to Mark has W from his contact;
  - the orphan is `failed` with `no_workspace`, and its card's assignees are `["me"]`.

Prove it red first: drop statement 4, and the P1 assertion fails. Value card: `protects=an upgrade keeps
every project sending where it sent and every contact and send in its workspace, and returns what can't be;
fails_when=the backfill misses a send, drops a contact, leaves an orphan live, or overwrites a project's Off;
why_new=migration (core); no_claim=databases with more than one workspace stored, which no earlier build could
write`.

## Review note

Orphan **drafts** stay drafts: the migration fails only sending or sent sends it cannot place, since `failSend`
allows nothing else. A draft with no workspace is redrafted or held by the normal path.
