# 10db M0 Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the 10db monorepo baseline (spec §11): empty apps and packages wired together end to end, every convention enforced by a test or a lint rule, `make gate` green locally and CI green.

**Architecture:** One pnpm workspace. `packages/contracts` (zod schemas and generated JSON Schema), `packages/db` (Drizzle on better-sqlite3), `packages/harness` (the injected plugin dir, empty for now), `apps/daemon` (Hono on Node, serving `/health`), `apps/desktop` (Vite + React + Mantine UI inside a Tauri 2 shell). The UI calls the daemon through Hono's typed client. Repo conventions live in `AGENTS.md` files and `.claude/rules/`, and they are enforced by `tests/repo`, a workspace package of repo-level tests.

**Tech Stack:** Node 26.11.1, pnpm 12.9.1, TypeScript 7.0.2 (`tsc`) with the TypeScript 6.0 API alongside for tooling, ESLint 10 + typescript-eslint 8.71 (strict-type-checked), Prettier 3.9, Vitest 5, knip 6, zod 4.6, Hono 4.13, Drizzle 0.45 + better-sqlite3 13, React 19.3, Mantine 9.7, TanStack Router 1.170 and Query 5.104, Vite 8.3, Tauri 2.12, Rust 1.99.0. Repo governance: mise 2026.10.10, lefthook 2.2, commitlint 21.2, gitleaks 8.30, actionlint 1.7, zizmor 1.30, cargo-deny 0.20, release-please, Renovate.

**Specs:**
- `docs/superpowers/specs/2026-10-13-10db-factory-loop-design.md` (§11 repo baseline; §3 architecture; §12 testing). Read §11 before starting.
- `docs/superpowers/specs/2026-10-14-10db-repo-governance-design.md` (decisions G1–G11: commits, hooks, CI, releases, GitHub settings). Read §2–§4 and §6 before starting.

**Plan series:** `00-spikes` (run first), **`01-m0-scaffold` (this file)**, `02-m1a-engine-core`, `03-m1b-sessions-and-ui`, `04-go-public`, `05-release`. Spec spike 11 (the Rust toolchain and the first Tauri window) is folded into Task 11 here. This plan creates the GitHub settings files and the script that applies them, but never runs that script and never pushes. Task 16 merges M0 into local `main`; `04-go-public` then creates the repo, pushes `main`, applies the settings and opens the first PR, which is where CI first runs.

Verified tool behaviour this plan relies on:
- **pnpm 12.9.1:** `minimumReleaseAge` is in minutes. `allowBuilds` is a map of package name to `true`/`false`. `strictDepBuilds` defaults to `true`, so an unlisted dependency with an install script fails `pnpm install` with `ERR_PNPM_IGNORED_BUILDS`. A probe install of every M0 dependency found exactly two packages with install scripts: `esbuild` (needed) and `lefthook` (its postinstall installs hooks, which the root `prepare` script already does). `better-sqlite3` 13 ships prebuilt addons in the package and has no install script.
- **gitleaks 8.30.1:** `gitleaks git --pre-commit --staged` scans the index. `gitleaks git --log-opts=<range>` scans commits. It **exits 0 when git can't resolve the range**, so `scripts/policy.sh` resolves both ends first.
- **lefthook 2.2.2:** `lefthook validate`, `lefthook dump --format json` and `lefthook run <hook> --job <name>` exist. `glob: '*.ts'` matches at any depth. `use_stdin: true` passes git's pre-push ref lines to the job.
- **cargo-deny 0.20.2:** `--manifest-path` and `--config` are top-level options, so the order is `cargo deny --manifest-path … --config … check`. A trial run on the M0 crate (tauri 2.12.3, 407 packages) passed all four checks with the licence list in Task 13.
- **zizmor 1.30.1 and actionlint 1.7.12:** both report no findings on the workflows in Task 13.
- **Codex 0.154:** `codex execpolicy check --rules <file> -- <command…>` judges a command against a rules file. Task 3's test uses it when `codex` is installed. Its rules are prefix-only: `git commit -m x --no-verify` and `LEFTHOOK_EXCLUDE=x git commit` match nothing.
- **git 2.50:** long options accept any unambiguous prefix, so `git commit --no-verif` skips the hooks (`--no-v` is ambiguous with `--no-verbose` and errors). `core.hooksPath` can also be set by `git config`, `--config-env` and the `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_n`/`GIT_CONFIG_PARAMETERS` variables.
- **lefthook 2.2.2 environment:** the docs list `LEFTHOOK` (`0`/`false` skips every hook), `LEFTHOOK_EXCLUDE` (skips named jobs or tags), `LEFTHOOK_CONFIG` (another config file), `LEFTHOOK_BIN` (another binary), `LEFTHOOK_OUTPUT` and `LEFTHOOK_VERBOSE`. The 2.2.2 binary reads exactly these. Task 3's guard denies the first four.
- **GitHub Actions app id `15368`:** `gh api apps/github-actions --jq .id` prints `15368`. Task 15 pins each required check's `integration_id` to it, so only a check run from GitHub Actions satisfies it.
- **Tag rulesets:** GitHub's "Restrict creations", "Restrict updates" and "Restrict deletions" rules let only the ruleset's bypass actors create, update or delete a matching tag, and a bypass covers every rule in its ruleset. Task 15 therefore splits creation from update and deletion.

## Global Constraints

- Node `26.11.1` exactly, pinned in `mise.toml` and in the root `engines`. Node 26 enters LTS on 2026-10-28; Node 24 enters maintenance on 2026-10-20. Recorded as decision 22.
- pnpm `12.9.1`, pinned in `mise.toml` and in `packageManager`. Installs run with `--frozen-lockfile` in CI.
- **mise** (`mise.toml` plus `mise.lock`, which holds checksums) pins every tool that isn't an npm package: Node, pnpm, Rust, gitleaks, actionlint, zizmor and cargo-deny (G6). Local setup and CI install from the same file, and there is no `.node-version`. The builder needs mise 2026.10.10 or later, activated in the shell, so that the git hooks find the tools on `PATH`.
- pnpm supply chain (`pnpm-workspace.yaml`): `minimumReleaseAge: 1440`, which holds any version published less than a day ago; `strictDepBuilds: true`; and an explicit `allowBuilds` map. A new dependency with an install script fails `pnpm install` until it gets an `allowBuilds` entry: `true` only if the package needs its script to work.
- Every dependency is pinned exactly: `1.2.3`, `npm:<name>@1.2.3` or `workspace:*`. No `^`, no `~`. A held-back pin carries a comment in `docs/architecture/decisions.md`. Cargo dependencies use `=x.y.z`.
- TypeScript: `typescript` resolves to `npm:@typescript/typescript6@6.0.2`, which is the API that ESLint and knip load, and `@typescript/native` resolves to `npm:typescript@7.0.2`, which provides `tsc`. Never call `tsc6` in scripts. Recorded as decision 21.
- tsconfig: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`, `erasableSyntaxOnly`, `module: preserve`, `moduleResolution: bundler`, `target: es2024`. Nothing deprecated in 6.0 or removed in 7.0.
- ESM everywhere (`"type": "module"`). Internal packages export TypeScript source (`"exports": { ".": "./src/index.ts" }`). They are never built on their own.
- Imports between workspace packages go through the package entry point only (`@10db/db`, never `@10db/db/src/...`).
- `AGENTS.md` everywhere, never `CLAUDE.md`. A test fails if any `CLAUDE.md` exists in the repo.
- No `utils.ts`, `helpers.ts`, `misc.ts` or `common.ts` files.
- Comments say what and why, timelessly: no "per D-12", no "Session 7", no dates.
- Constants are `as const` objects with derived types. TypeScript `enum`s are banned, and `erasableSyntaxOnly` enforces the ban. `erasableSyntaxOnly` also rejects constructor parameter properties (`constructor(readonly x: T)`, TS1294): declare the field and assign it in the constructor.
- Tests use real objects and mock only at process and network boundaries. Each new test is run red before the code that makes it pass.
- Every code block in this plan is already Prettier-formatted (print width 100). Each task from Task 6 on runs `pnpm format` before its checks and `pnpm format:check` among them.
- **Commit messages** are Conventional Commits (G2), enforced by commitlint from Task 5 on: `type(scope): subject`. The scope is required and comes from the fixed list `daemon`, `desktop`, `contracts`, `db`, `harness`, `repo`, `ci`, `docs`, `deps`. The subject starts lowercase, and the header is at most 100 characters. Trailers such as `Co-Authored-By:` are allowed.
- **Commits name their paths, in one command:** `git add <path> <path> && git commit -m '...'`. A commit run in its own Bash call names its paths after `--`: `git commit -m '...' -- <path> <path>`. The git guard denies an unqualified commit when anything outside the command's own `git add` is staged. Never `git add -A`, `git add .` or `git commit -a`. Use single quotes for `-m`.
- **Hooks run on every commit from Task 5 on:** gitleaks, Prettier, ESLint, `cargo fmt` and a hygiene check before the commit; commitlint on the message; `make check` before a push. A failed hook aborts the commit and leaves the paths staged. Fix the cause and rerun the same command. Agents never pass `--no-verify` (or a prefix of it, or `commit -n`), never set `LEFTHOOK=0` or another `LEFTHOOK_*` switch, and never override `core.hooksPath` (`-c`, `--config-env`, `git config` or `GIT_CONFIG_*`); the Claude guard denies all of these. The Codex rules are prefix-only, so they catch these forms only when they lead the command; CI's required checks are the backstop.
- Branch: `feat/m0-scaffold`, cut from `spec/factory-loop`. Task 16 fast-forwards local `main` to it. Nothing in this plan pushes; `04-go-public` publishes the repo.
- The env var prefix is `TENDB_`, because names can't start with a digit. Package scope is `@10db/`.
- Data directory default: `~/Library/Application Support/10db/` (spec §3).

## Review Focus

These are the input classes M0's own tests would otherwise miss. Each has a test in the owning task.
1. **A fresh clone with no Rust installed, and a CI runner with cargo but no Tauri system libraries.** `make gate` must report `rust skipped` in both cases: when cargo is missing, and when `GATE_SKIP_RUST=1` is set even though cargo is on `PATH`. It must not fail and must not hang. The test is in Task 12.
2. **A malformed or unexpected hook payload** (non-JSON stdin, a non-Bash tool, a missing `command`, a `cwd` outside any git repo). The git guard must allow the call silently (fail-open) and never crash the session. The test is in Task 3.
3. **A backtick in a single-quoted `-m` is fine; one in a double-quoted `-m` is denied.** The guard must not block legitimate single-quoted messages. The test is in Task 3.
4. **A commit while another session's work is already staged.** An unqualified `git add a && git commit` would sweep that work in, so the guard denies it. A pathspec commit (`-- a`) or a retry that re-adds the same staged paths is allowed. The test is in Task 3.
5. **Bad input to the git hooks:** a commit message without a listed scope, a planted token, a staged `scratch/` file, a conflict marker, a file over 1 MB and a case-only path collision. Each is rejected before it reaches a commit. The test is in Task 5.
6. **A data directory path with a space** (`Application Support`). The database opens and migrates there. The test is in Task 7.
7. **An env value that looks like a secret, inside an invalid variable.** The `EnvError` message names the variable and the problem, never the value. An empty value (`TENDB_PORT=`) means unset. The test is in Task 9.
8. **Staged generated files.** `git add <generated> && pnpm drift` passes, while an unstaged edit, a deletion or an untracked file under a generated path fails. The test is in Task 6.

# Code style

- **Comments say what and why, timelessly.** No decision numbers, session numbers, dates or
  "new"/"old". A comment that only restates the code is deleted.
- **Constants are `as const` objects** with the type derived from them:
  `export const WorkstreamState = { Queued: 'QUEUED', ... } as const;`
  `export type WorkstreamState = (typeof WorkstreamState)[keyof typeof WorkstreamState];`
  No TypeScript `enum`s (`erasableSyntaxOnly` rejects them).
- **No constructor parameter properties** (`constructor(readonly id: string)`);
  `erasableSyntaxOnly` rejects them too. Declare the field, then assign it in the constructor.
- **No versions in names.** Not `parseV2`, not `schema-new.ts`.
- **No cross-module private imports.** Import another package or module through its entry point.
- **No grab-bags.** No `utils.ts`, `helpers.ts`, `misc.ts` or `common.ts`; name a module after
  what it does.
- **zod at every boundary**: HTTP bodies, MCP inputs, env vars, files read from disk, SDK
  messages, child-process output. Inside a boundary, trust the types.
- **Branded IDs.** A `TaskId` is not a `string`; construct IDs only through the ID module.
- **Typed errors.** Throw subclasses of `Error` with a `name`; never throw strings. A boundary
  converts unknown errors into typed ones.
- **No `any`, no non-null `!`, no `as` casts except at a validated boundary**, with a comment.
- **Small files with one job.** Files that change together live together.
- **Exhaustive switches** over unions; the linter checks.

**Interfaces:**
- Produces: a Claude Code `PreToolUse` command hook. It reads the hook JSON on stdin, including `cwd`, and writes either nothing (allow) or `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny"|"ask","permissionDecisionReason":string}}`. A warning-only rule writes `additionalContext` with no decision. When several rules fire, the most severe decision wins (deny over ask over warn), and the reasons are joined.
- Produces: `.codex/rules/default.rules`, the Codex twin. Its prefix rules forbid what the guard denies and prompt for what it asks, when the form leads the command. A prefix rule can't see a flag after the message or an env assignment with an arbitrary value, so Codex also prompts on every `git -c` and every `gh pr merge`, and CI's required checks are the backstop.
- Rules, all from AGENTS.md:
  - **deny:** bulk adds; `commit -a`; a double-quoted `-m` with a backtick; `--no-verify` and every prefix of it down to `--no-v`, which git also accepts (and `commit -n`); `LEFTHOOK=0`/`false` and `LEFTHOOK_EXCLUDE`/`_CONFIG`/`_BIN` assignments; any `GIT_CONFIG_*` assignment except `GIT_CONFIG_NOSYSTEM`; `core.hooksPath` set through `-c`, `--config-env` or `git config` (reading it is fine); an unqualified commit when the index holds anything the same command didn't add. A commit in its own call must name its paths after `--`.
  - **ask:** `commit --amend`, `stash` (except `list` and `show`), `reset --hard/--keep/--merge`, `rebase`, `clean -f`, `checkout -- .`, `restore` (unless `--staged`), `branch -D`, `filter-branch`, `filter-repo` (except `--version`), `tag -d`, force and deleting pushes, and pushes to `main` (an explicit `main` refspec, or a bare `git push` while on `main`). Also anything that writes under `.git/hooks` or runs `lefthook uninstall`, and the GitHub-settings commands: `gh pr merge --admin`, a `gh api` write (an explicit non-GET method, or a field or `--input`, which implies POST) to `rulesets`, `environments`, `secrets` or `actions/permissions`, `gh secret set/delete`, and `make github-settings`.
  - **nested:** the command inside `bash -c`, `sh -c`, `zsh -c` or `eval` is judged by the same rules.
  - **kill switch:** only `TENDB_GIT_GUARD=off` in the environment Claude Code starts with. A Bash command can't set that for the hook, and there is no kill-switch file, because an agent could create one.
  - **warn:** `git add <directory>`; test output piped to `tail`/`head` or followed by `; echo $?`.

This guard protects the bootstrap repo while people and plain Claude Code build 10db. It is *not* the managed-session guard; that one is daemon code in M1a.

#!/usr/bin/env node
// PreToolUse guard for Bash commands in this repository. It enforces the git rules in AGENTS.md.
// Fail-open: any parse problem or internal error allows the command, because a broken guard must
// never wedge a session. Kill switch: TENDB_GIT_GUARD=off in the environment Claude Code starts
// with. A Bash command can't set it for the hook, and there is no kill-switch file an agent could
// write.
import { execFileSync } from 'node:child_process';
import { existsSync, readFileSync, statSync } from 'node:fs';
import { join, posix } from 'node:path';

/**
 * Splits a shell command into segments at unquoted `&&`, `||`, `;`, `|` and newlines, and each
 * segment into words with quotes removed. `raw` keeps the segment text for quote-aware checks.
 * @param {string} command
 * @returns {{ raw: string, words: string[], separator: string }[]}
 */
function segments(command) {
  /** @type {{ raw: string, words: string[], separator: string }[]} */
  const out = [];
  let raw = '';
  let word = '';
  /** @type {string[]} */
  let words = [];
  /** @type {string | null} */
  let quote = null;
  const flushWord = () => {
    if (word !== '') words.push(word);
    word = '';
  };
  const flushSegment = (/** @type {string} */ separator) => {
    flushWord();
    if (raw.trim() !== '') out.push({ raw: raw.trim(), words, separator });
    raw = '';
    words = [];
  };
  for (let i = 0; i < command.length; i += 1) {
    const ch = command[i];
    const next = command[i + 1];
    if (quote) {
      raw += ch;
      if (ch === quote) quote = null;
      else word += ch;
      continue;
    }
    if (ch === "'" || ch === '"') {
      quote = ch;
      raw += ch;
      continue;
    }
    if ((ch === '&' && next === '&') || (ch === '|' && next === '|')) {
      flushSegment(ch + next);
      i += 1;
      continue;
    }
    if (ch === ';' || ch === '|' || ch === '\n') {
      flushSegment(ch);
      continue;
    }
    raw += ch;
    if (ch === ' ' || ch === '\t') flushWord();
    else word += ch;
  }
  flushSegment('');
  return out;
}

const ENV_ASSIGNMENT = /^[A-Za-z_][A-Za-z0-9_]*=/;

/** Index of the first word after leading `VAR=value` words and `env`. @param {string[]} words */
function commandStart(words) {
  let i = 0;
  while (i < words.length && (ENV_ASSIGNMENT.test(words[i]) || words[i] === 'env')) i += 1;
  return i;
}

/**
 * The git verb and its arguments, skipping leading `VAR=value` words, `env`, and git's global
 * options. `config` collects every `-c key=value` and `--config-env key=VAR` passed to git itself.
 * @param {string[]} words
 */
function gitSubcommand(words) {
  let i = commandStart(words);
  if (words[i] !== 'git') return null;
  i += 1;
  /** @type {string[]} */
  const config = [];
  while (i < words.length && words[i].startsWith('-')) {
    const word = words[i];
    const takesValue = word === '-C' || word === '-c' || word === '--config-env';
    if (word === '-c' || word === '--config-env') config.push(words[i + 1] ?? '');
    if (word.startsWith('--config-env=')) config.push(word.slice('--config-env='.length));
    i += takesValue ? 2 : 1;
  }
  return { verb: words[i] ?? '', args: words.slice(i + 1), config };
}

/**
 * The command a `bash -c`, `sh -c`, `zsh -c` or `eval` segment runs, so it can be judged too.
 * @param {string[]} words
 * @returns {string | null}
 */
function nestedCommand(words) {
  const i = commandStart(words);
  if (words[i] === 'eval') return words.slice(i + 1).join(' ');
  if (!['bash', 'sh', 'zsh'].includes(words[i] ?? '')) return null;
  const flag = words.findIndex((w, j) => j > i && /^-[a-z]*c$/.test(w));
  return flag >= 0 ? (words[flag + 1] ?? null) : null;
}

/** @param {string} cwd @param {string[]} args */
function gitOutput(cwd, args) {
  return execFileSync('git', args, { cwd, encoding: 'utf8', stdio: ['ignore', 'pipe', 'ignore'] });
}

/** Paths staged right now, relative to the repository root. @param {string} cwd */
function stagedPaths(cwd) {
  return gitOutput(cwd, ['diff', '--cached', '--name-only', '-z']).split('\0').filter(Boolean);
}

/** The checked-out branch, or '' when HEAD is detached or unreadable. @param {string} cwd */
function currentBranch(cwd) {
  try {
    return gitOutput(cwd, ['symbolic-ref', '--short', '-q', 'HEAD']).trim();
  } catch {
    return '';
  }
}

/** Turns a cwd-relative pathspec into a repository-relative one. @param {string} cwd @param {string} path */
function repoRelative(cwd, path) {
  const prefix = gitOutput(cwd, ['rev-parse', '--show-prefix']).trim();
  return posix.normalize(posix.join(prefix, path)).replace(/\/$/, '');
}

const TEST_RUNNER = /\b(vitest|pnpm (-s )?(test|gate)|make (gate|check)|cargo test|playwright)\b/;
const BULK_ADD = ['-A', '--all', '.', '-u', '--update', ':/', ':/.', '*'];
// Environment assignments that skip or reroute the git hooks: lefthook's own switches
// (LEFTHOOK=0, LEFTHOOK_EXCLUDE, LEFTHOOK_CONFIG, LEFTHOOK_BIN) and git's config-by-environment
// variables, which can set core.hooksPath. LEFTHOOK=1 and GIT_CONFIG_NOSYSTEM are harmless.
const HOOK_SKIP = /^(LEFTHOOK(_EXCLUDE|_CONFIG|_BIN)?|GIT_CONFIG(_[A-Z0-9_]+)?)=\S*$/;
const HOOK_SKIP_HARMLESS = /^(LEFTHOOK=(1|true)|GIT_CONFIG_NOSYSTEM=\S*)$/;
// Git accepts any unambiguous prefix of a long option, so --no-verif skips hooks too.
const isNoVerify = (/** @type {string} */ x) => x.length >= 6 && '--no-verify'.startsWith(x);
const HOOKS_DIR = /(^|\/)\.git\/hooks(\/|$)/;
const READ_ONLY = ['ls', 'cat', 'head', 'tail', 'stat', 'file', 'grep', 'rg', 'find'];
const CONFIG_READ = ['--get', '--get-all', '--get-regexp', '--list', '-l', 'get', 'list'];
const GH_SETTINGS_PATH = /(^|\/)(rulesets|environments|secrets|actions\/permissions)(\/|$)/;
const MAIN_REFSPEC = /^(\+?(HEAD|[\w./-]+):)?(refs\/heads\/)?main$/;
const SEVERITY = { warn: 1, ask: 2, deny: 3 };

/**
 * @typedef {{ decision: 'deny' | 'ask' | 'warn', reason: string }} Verdict
 * @param {string} command
 * @param {string} cwd
 * @returns {Verdict | null} the most severe verdict any segment earns
 */
function judge(command, cwd) {
  const segs = segments(command);
  /** @type {Verdict[]} */
  const verdicts = [];
  /** @type {string[]} */
  const addedPaths = [];
  for (const [index, seg] of segs.entries()) {
    const nested = nestedCommand(seg.words);
    const inner = nested === null ? null : judge(nested, cwd);
    if (inner) verdicts.push(inner);
    if (seg.words.some((w) => HOOK_SKIP.test(w) && !HOOK_SKIP_HARMLESS.test(w))) {
      verdicts.push({
        decision: 'deny',
        reason:
          'Agents never disable or reroute the git hooks (LEFTHOOK*, GIT_CONFIG*). Fix what the hook reports.',
      });
    }
    const start = commandStart(seg.words);
    const program = seg.words[start] ?? '';
    const rest = seg.words.slice(start + 1);
    if (
      (seg.words.some((w) => HOOKS_DIR.test(w)) && !READ_ONLY.includes(program)) ||
      (seg.words.includes('lefthook') && seg.words.includes('uninstall'))
    ) {
      verdicts.push({
        decision: 'ask',
        reason: 'This changes the installed git hooks. Fix what the hook reports instead.',
      });
    }
    if (program === 'make' && rest.includes('github-settings')) {
      verdicts.push({
        decision: 'ask',
        reason: 'make github-settings rewrites the live rulesets and repo settings on GitHub.',
      });
    }
    if (program === 'gh') {
      const method = rest
        .flatMap((x, j) =>
          x === '-X' || x === '--method'
            ? [rest[j + 1] ?? '']
            : /^(-X|--method=)./.test(x)
              ? [x.replace(/^(-X|--method=)/, '')]
              : [],
        )
        .map((m) => m.toUpperCase())[0];
      const sendsBody = rest.some((x) => /^(-f|-F|--field|--raw-field|--input)(=|$)/.test(x));
      const writes = method === undefined ? sendsBody : method !== 'GET';
      const adminMerge = rest[0] === 'pr' && rest[1] === 'merge' && rest.includes('--admin');
      const settingsWrite =
        (rest[0] === 'api' && writes && rest.some((x) => GH_SETTINGS_PATH.test(x))) ||
        (rest[0] === 'secret' && ['set', 'delete', 'remove'].includes(rest[1] ?? ''));
      if (adminMerge || settingsWrite) {
        verdicts.push({
          decision: 'ask',
          reason: adminMerge
            ? '--admin bypasses the code-owner review. Read every .github/, hook and agent-rule change in the PR first.'
            : 'This changes rulesets, environments or secrets on GitHub.',
        });
      }
    }
    const git = gitSubcommand(seg.words);
    if (git) {
      const a = git.args;
      if (
        a.some(isNoVerify) ||
        (git.verb === 'commit' && a.some((x) => /^-[a-zA-Z]*n[a-zA-Z]*$/.test(x)))
      ) {
        verdicts.push({
          decision: 'deny',
          reason: 'Agents never skip git hooks (--no-verify). Fix what the hook reports.',
        });
      }
      const setsHooksPath =
        git.verb === 'config' &&
        a.some((x) => /^core\.hookspath(=|$)/i.test(x)) &&
        !a.some((x) => CONFIG_READ.includes(x));
      if (setsHooksPath || git.config.some((c) => /^core\.hookspath(=|$)/i.test(c))) {
        verdicts.push({
          decision: 'deny',
          reason: 'Agents never redirect core.hooksPath. Fix what the hook reports.',
        });
      }
      if (git.verb === 'add') {
        if (a.some((x) => BULK_ADD.includes(x))) {
          verdicts.push({
            decision: 'deny',
            reason: 'Name each path: git add <path> <path>. Bulk adds sweep in other work.',
          });
        }
        const paths = a.filter((x) => !x.startsWith('-'));
        addedPaths.push(...paths.map((p) => repoRelative(cwd, p)));
        const dirs = paths.filter(
          (p) =>
            !BULK_ADD.includes(p) &&
            existsSync(join(cwd, p)) &&
            statSync(join(cwd, p)).isDirectory(),
        );
        if (dirs.length > 0) {
          verdicts.push({
            decision: 'warn',
            reason: `git add ${dirs.join(' ')} stages every change under that directory. Check git diff --cached before committing.`,
          });
        }
      }
      if (git.verb === 'commit') {
        if (
          a.some(
            (x) =>
              x === '-a' || x === '--all' || (/^-[a-zA-Z]*a[a-zA-Z]*$/.test(x) && x !== '--amend'),
          )
        ) {
          verdicts.push({
            decision: 'deny',
            reason: 'git commit -a stages everything. Use git add <path> <path>, then commit.',
          });
        }
        if (/(?:-m|--message)\s*=?\s*"[^"]*`/.test(seg.raw)) {
          verdicts.push({
            decision: 'deny',
            reason: 'zsh runs backticks inside double quotes. Use single quotes for -m.',
          });
        }
        const dashDash = a.indexOf('--');
        const namesPaths = dashDash >= 0 && dashDash < a.length - 1;
        if (a.includes('--amend')) {
          verdicts.push({
            decision: 'ask',
            reason: 'Amending rewrites a commit. Make a new commit instead.',
          });
        } else if (!namesPaths) {
          // Without a pathspec, a commit takes the whole index. Allow it only when everything
          // staged was added by this same command, so another session's staged work is never swept in.
          const covered = (/** @type {string} */ p) =>
            addedPaths.some((added) => p === added || p.startsWith(`${added}/`));
          const foreign =
            addedPaths.length === 0
              ? ['(nothing added in this command)']
              : stagedPaths(cwd).filter((p) => !covered(p));
          if (foreign.length > 0) {
            verdicts.push({
              decision: 'deny',
              reason: `This commit would take the whole index, including ${foreign.slice(0, 3).join(', ')}. Name the paths: git commit -m '...' -- <path> <path>.`,
            });
          }
        }
      }
      const pushTargets = git.verb === 'push' ? a.filter((x) => !x.startsWith('-')).slice(1) : [];
      const pushesMain =
        git.verb === 'push' &&
        (pushTargets.some((t) => MAIN_REFSPEC.test(t)) ||
          (pushTargets.length === 0 && currentBranch(cwd) === 'main'));
      const irreversible =
        (git.verb === 'push' &&
          (pushesMain ||
            a.some(
              (x) =>
                x === '--force' ||
                x === '-f' ||
                x.startsWith('--force-with-lease') ||
                x === '--delete' ||
                x === '--mirror',
            ))) ||
        (git.verb === 'reset' && a.some((x) => ['--hard', '--keep', '--merge'].includes(x))) ||
        (git.verb === 'clean' && a.some((x) => /^-[a-z]*f/.test(x))) ||
        (git.verb === 'checkout' && (a.includes('--') || a.includes('.'))) ||
        (git.verb === 'restore' && !a.includes('--staged')) ||
        (git.verb === 'branch' && a.some((x) => x === '-D' || x === '--delete')) ||
        git.verb === 'rebase' ||
        git.verb === 'filter-branch' ||
        (git.verb === 'filter-repo' && !a.includes('--version')) ||
        (git.verb === 'stash' && !['list', 'show'].includes(a[0] ?? '')) ||
        (git.verb === 'tag' && a.includes('-d'));
      if (irreversible) {
        verdicts.push({
          decision: 'ask',
          reason: pushesMain
            ? 'main changes only through a pull request.'
            : `git ${git.verb} ${a.join(' ')} cannot be undone easily.`,
        });
      }
    }
    const next = segs[index + 1];
    if (TEST_RUNNER.test(seg.raw) && next) {
      const pipedToTail = seg.separator === '|' && /^(tail|head)\b/.test(next.raw);
      const echoesStatus = seg.separator === ';' && /^echo \$\?/.test(next.raw);
      if (pipedToTail || echoesStatus) {
        verdicts.push({
          decision: 'warn',
          reason:
            'Run test commands plainly: piping to tail or echoing $? hides failures and exit codes.',
        });
      }
    }
  }
  if (verdicts.length === 0) return null;
  const worst = Math.max(...verdicts.map((v) => SEVERITY[v.decision]));
  const top = verdicts.filter((v) => SEVERITY[v.decision] === worst);
  return { decision: top[0].decision, reason: top.map((v) => v.reason).join(' ') };
}

function main() {
  if (process.env.TENDB_GIT_GUARD === 'off') return;
  const input = JSON.parse(readFileSync(0, 'utf8'));
  if (input?.tool_name !== 'Bash' || typeof input?.tool_input?.command !== 'string') return;
  const cwd = typeof input.cwd === 'string' ? input.cwd : process.cwd();
  const verdict = judge(input.tool_input.command, cwd);
  if (!verdict) return;
  const hookSpecificOutput =
    verdict.decision === 'warn'
      ? { hookEventName: 'PreToolUse', additionalContext: verdict.reason }
      : {
          hookEventName: 'PreToolUse',
          permissionDecision: verdict.decision,
          permissionDecisionReason: verdict.reason,
        };
  process.stdout.write(JSON.stringify({ hookSpecificOutput }));
}

try {
  main();
} catch {
  // Fail open: a guard bug must never block work.
}
process.exitCode = 0;

#!/usr/bin/env node
// Pre-commit hygiene for the staged snapshot: forbidden paths, merge conflict markers, files over
// 1 MB and paths that collide on a case-insensitive file system. It reads the index, not the
// working tree, so it judges exactly what the commit will contain. Prints every problem found.
import { execFileSync } from 'node:child_process';

const MAX_BYTES = 1024 * 1024;
const FORBIDDEN = [/^scratch\//, /^\.claude\/settings\.local\.json$/];
const CONFLICT_MARKER = /^(?:<{7} |={7}$|>{7} )/m;

/** @param {string[]} args */
const git = (...args) => execFileSync('git', args, { encoding: 'utf8', maxBuffer: 64 * MAX_BYTES });

/** @type {string[]} */
const problems = [];
for (const path of process.argv.slice(2)) {
  if (FORBIDDEN.some((pattern) => pattern.test(path))) {
    problems.push(`${path}: scratch/ and .claude/settings.local.json are never committed`);
    continue;
  }
  const size = Number(git('cat-file', '-s', `:${path}`).trim());
  if (size > MAX_BYTES) problems.push(`${path}: ${String(size)} bytes is over the 1 MB limit`);
  else if (CONFLICT_MARKER.test(git('show', `:${path}`)))
    problems.push(`${path}: has a merge conflict marker`);
}

/** @type {Map<string, string>} */
const byLowerCase = new Map();
for (const path of git('ls-files', '-z').split('\0').filter(Boolean)) {
  const other = byLowerCase.get(path.toLowerCase());
  if (other !== undefined)
    problems.push(`${path}: collides with ${other} on a case-insensitive file system`);
  else byLowerCase.set(path.toLowerCase(), path);
}

if (problems.length > 0) {
  console.error(`Commit refused:\n${problems.map((p) => `  ${p}`).join('\n')}`);
  process.exitCode = 1;
}
```

`scripts/hooks/pre-push.mjs`:
```js
#!/usr/bin/env node
// Refuses a push that updates or deletes main on the remote: changes reach main through a PR.
// Creating main (the remote has no main yet) is allowed, so a new repository can receive its
// first push. Git writes one line per ref to stdin: <local ref> <local sha> <remote ref> <remote sha>.
import { readFileSync } from 'node:fs';

const ZERO_SHA = /^0+$/;
const refused = readFileSync(0, 'utf8')
  .split('\n')
  .map((line) => line.trim().split(' '))
  .filter(
    ([, , remoteRef, remoteSha]) =>
      remoteRef === 'refs/heads/main' && !ZERO_SHA.test(remoteSha ?? ''),
  );

if (refused.length > 0) {
  console.error(
    'Push refused: main changes only through a pull request. Push a branch and open a PR.',
  );
  process.exitCode = 1;
}
```

#!/usr/bin/env bash
# Fails when generated paths differ from the index: unstaged edits or deletions, or untracked
# files. Staged changes pass, so `git add <generated> && pnpm drift` succeeds before the commit.
# Usage: scripts/check-clean.sh <path>... (paths relative to the repository root)
set -euo pipefail
cd "$(git rev-parse --show-toplevel)"
unstaged=$(git diff --name-status -- "$@")
untracked=$(git ls-files --others --exclude-standard -- "$@")
if [[ -n "$unstaged" || -n "$untracked" ]]; then

import { resolve } from 'node:path';
import Database from 'better-sqlite3';
import { drizzle, type BetterSQLite3Database } from 'drizzle-orm/better-sqlite3';
import { migrate } from 'drizzle-orm/better-sqlite3/migrator';
import * as schema from './schema';

export type TendbDatabase = BetterSQLite3Database<typeof schema> & { $client: Database.Database };

/** Migrations shipped with this package; a bundled daemon passes its own copy instead. */
export const DB_MIGRATIONS_DIR = resolve(import.meta.dirname, '../drizzle');

/** Opens (creating if needed) the database file with the pragmas every connection needs. */
export function openDatabase(path: string): TendbDatabase {
  const client = new Database(path);
  client.pragma('journal_mode = WAL');
  client.pragma('foreign_keys = ON');
  client.pragma('busy_timeout = 5000');
  client.pragma('synchronous = NORMAL');
  return drizzle({ client, schema });
}

/** Applies pending forward-only migrations; each runs in a transaction. */
export function migrateDatabase(
  db: TendbDatabase,
  migrationsDir: string = DB_MIGRATIONS_DIR,
): void {
  migrate(db, { migrationsFolder: migrationsDir });
}

import { z } from 'zod';

export const LogLevel = {
  Fatal: 'fatal',
  Error: 'error',
  Warn: 'warn',
  Info: 'info',
  Debug: 'debug',
  Trace: 'trace',
} as const;
export type LogLevel = (typeof LogLevel)[keyof typeof LogLevel];

const DaemonEnv = z.object({
  TENDB_DATA_DIR: z.string().min(1).optional(),
  TENDB_PORT: z.coerce.number().int().min(0).max(65535).default(4317),
  TENDB_LOG_LEVEL: z.enum(LogLevel).default(LogLevel.Info),
});
export type DaemonEnv = z.infer<typeof DaemonEnv>;

/** Invalid configuration. Lists variable names and problem codes only, never values. */
export class EnvError extends Error {
  override readonly name = 'EnvError';
  readonly issues: readonly string[];

  constructor(issues: readonly string[]) {
    super(`Invalid environment: ${issues.join('; ')}`);
    this.issues = issues;
  }
}

/** The only module in the daemon that parses environment variables; main passes `process.env`. */
export function loadEnv(source: Readonly<Record<string, string | undefined>>): DaemonEnv {
  // `VAR=` means unset: coercion would turn an empty port into 0 and fail an empty data dir.
  const present = Object.fromEntries(Object.entries(source).filter(([, value]) => value !== ''));
  const parsed = DaemonEnv.safeParse(present);
  if (!parsed.success) {
    throw new EnvError(
      parsed.error.issues.map((issue) => `${issue.path.join('.')}: ${issue.code}`),
    );
  }
  return parsed.data;
}

async function fetchHealth(): Promise<HealthResponse> {

export function DaemonStatus() {

  createRouter,

  type RouterHistory,
} from '@tanstack/react-router';
import { AppLayout } from './shell/app-layout';
import { FactoryView } from './views/factory-view';
import { InboxView } from './views/inbox-view';
import { TasksView } from './views/tasks-view';

const rootRoute = createRootRoute({ component: AppLayout });

const indexRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/',
  beforeLoad: () => {
    // TanStack Router's redirect is thrown by design.
    // eslint-disable-next-line @typescript-eslint/only-throw-error
    throw redirect({ to: '/factory' });
  },
});
const factoryRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/factory',
  component: FactoryView,
});
const inboxRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/inbox',
  component: InboxView,
});
const tasksRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/tasks',
  component: TasksView,
});

const routeTree = rootRoute.addChildren([indexRoute, factoryRoute, inboxRoute, tasksRoute]);

export function createAppRouter(history?: RouterHistory) {
  return createRouter({ routeTree, defaultPreload: 'intent', ...(history ? { history } : {}) });
}

export type AppRouter = ReturnType<typeof createAppRouter>;

declare module '@tanstack/react-router' {

`scripts/gate.sh`:
```bash
#!/usr/bin/env bash
# Runs every repository check and prints one summary line. Each step's output goes to .gate/<step>.log.
# GATE_STEPS="lint test" limits the run (used by tests and for quick reruns). GATE_SKIP_RUST=1
# reports rust as skipped even when cargo is installed (the Ubuntu CI job: no Tauri system libraries).
set -uo pipefail
cd "$(dirname "$0")/.."
mkdir -p .gate

ALL_STEPS=(format lint typecheck test build drift knip rust)
read -r -a steps <<< "${GATE_STEPS:-${ALL_STEPS[*]}}"
start=$SECONDS
passed=()
failed=()

run_step() {
  local name=$1
  shift
  if "$@" > ".gate/$name.log" 2>&1; then passed+=("$name"); else failed+=("$name"); fi
}

for step in "${steps[@]}"; do
  case "$step" in
    format) run_step format pnpm -s format:check ;;
    lint) run_step lint pnpm -s lint ;;
    typecheck) run_step typecheck pnpm -s typecheck ;;
    test) run_step test pnpm -s test ;;
    build) run_step build pnpm -s build ;;
    drift) run_step drift pnpm -s drift ;;
    knip) run_step knip pnpm -s knip ;;
    rust)
      if [[ -z "${GATE_SKIP_RUST:-}" ]] && command -v cargo > /dev/null 2>&1; then
        run_step rust make -s rust-check
      else
        passed+=("rust skipped")
      fi
      ;;
    fail-probe) run_step fail-probe false ;;
    *) failed+=("unknown-step:$step") ;;
  esac
done

elapsed=$((SECONDS - start))
if ((${#failed[@]} == 0)); then
  echo "GATE PASS ${passed[*]} (${elapsed}s)"
else
  echo "GATE FAIL: ${failed[*]} — logs in .gate/ (${elapsed}s)"
  exit 1
fi
```

#!/usr/bin/env bash
# Fast focused check: typecheck everything (TypeScript 7 is fast), then lint and test only what
# changed against HEAD, including untracked files. Runs on macOS /bin/bash 3.2: no mapfile.
set -euo pipefail
cd "$(dirname "$0")/.."
pnpm -s typecheck
changed=()
while IFS= read -r file; do
  changed+=("$file")
done < <({ git diff --name-only --diff-filter=d HEAD; git ls-files --others --exclude-standard; } | grep -E '\.(ts|tsx|js|mjs|cjs)$' | sort -u || true)
if ((${#changed[@]} > 0)); then
  # Changed files can match an ESLint ignore (fixtures, spikes); skip them instead of warning.
  pnpm -s exec eslint --cache --max-warnings=0 --no-warn-ignored "${changed[@]}"
fi
pnpm -s exec vitest run --changed HEAD
echo "CHECK PASS"
```

### Task 13: CI workflows and supply-chain checks

**Files:**
- Create: `.github/workflows/ci.yml`, `.github/workflows/codeql.yml`, `.github/workflows/scorecard.yml`, `.github/workflows/pnpm-audit.yml`
- Create: `deny.toml`, `scripts/policy.sh`
- Test: `tests/repo/src/ci.test.ts`
- Modify: `Makefile` (`deny` target), `tests/repo/package.json` (`yaml`)

**Interfaces:**
- Produces the five required checks, as the jobs of `ci.yml`, in this order. The names are exact, because Task 15's `main-protection` ruleset requires them:
  - `gate` (Ubuntu): `bash scripts/gate.sh` with `GATE_SKIP_RUST: '1'` set on the job;
  - `desktop` (macOS): `make rust-check`, then `tauri build --no-bundle`;
  - `policy` (Ubuntu): commitlint on the PR title, `scripts/policy.sh` over the pushed commits, then Prettier, ESLint and `cargo fmt` over the whole tree;
  - `dependency-review` (PRs only): fails on new dependencies with high or critical advisories, or under GPL-family licences;
  - `cargo-deny` (Ubuntu): `make deny`.
- Produces advisory workflows, which branch protection doesn't require: `codeql` (JavaScript/TypeScript and Actions, on push, PR and weekly), `scorecard` (OpenSSF, on push to `main` and weekly; it publishes the README badge's data) and `pnpm-audit` (weekly). The weekly audit replaces the old per-PR advisory `audit` job.
- Produces `scripts/policy.sh <base-sha> <head-sha>`, the CI twin of the local hooks. An empty or all-zero base scans all of head's history.
- Produces `make deny`.
- Hardening, which `ci.test.ts` enforces on every workflow:
  - every `uses:` is pinned to a full SHA with a `# vX.Y.Z` comment;
  - top-level `permissions: {}`, and every job declares its own;
  - `persist-credentials: false` on every checkout;
  - no `pull_request_target` and no `paths` filters;
  - secrets only in jobs bound to an `environment`.
- `ci.yml` runs on `pull_request` types `opened`, `synchronize`, `reopened` and `edited`. Squash merge makes the PR title the commit on `main`, so a renamed title must re-run `policy`'s title lint. Every job runs on every event: a job skipped on `edited` would report success and replace an earlier red result for the same commit. The cost is a full re-run, macOS included, when a title or body is edited, and `cancel-in-progress` drops the run it replaces. `edited` adds no zizmor or actionlint finding; `ci.test.ts` pins the types and that no job conditions on `github.event.action`.
- The `gate` job keeps the lines `- run: pnpm install --frozen-lockfile` and `- run: bash scripts/gate.sh`. M1b inserts a Playwright install between them and tests for that text.

Every job installs its tools from `mise.toml` with `jdx/mise-action`, which adds `--locked` because `mise.lock` exists. `install_args` limits each job to the tools it needs.

`scripts/policy.sh`:
```bash
#!/usr/bin/env bash
# CI twin of the local git hooks, for a range of commits: gitleaks over the range, the staged-file
# hygiene check over the files it changed, then actionlint and zizmor over the workflows.
# Usage: scripts/policy.sh <base-sha> <head-sha>. An empty or all-zero base (a branch's first push)
# scans all of head's history. Run from the repository root.
set -euo pipefail
here=$(cd "$(dirname "$0")" && pwd)
base=${1:-}
head=${2:?usage: scripts/policy.sh <base-sha> <head-sha>}

# gitleaks exits 0 on a range git can't resolve, so resolve both ends first.
git rev-parse --verify --quiet "$head^{commit}" > /dev/null || { echo "policy: unknown head commit $head"; exit 1; }
if [[ -z "$base" || "$base" =~ ^0+$ ]]; then
  range=$head
  from=$(git hash-object -t tree /dev/null)
else
  git rev-parse --verify --quiet "$base^{commit}" > /dev/null || { echo "policy: unknown base commit $base; fetch full history"; exit 1; }
  range="$base..$head"
  from=$base
fi

gitleaks git --no-banner --redact --log-opts="$range" .
git diff -z --name-only --diff-filter=ACMR "$from" "$head" | xargs -0 -r node "$here/hooks/hygiene.mjs"
actionlint
zizmor --offline .github/workflows
echo "POLICY PASS"

# Contributing to 10db

Thanks for helping. The rules below bind everyone equally: people, Claude Code and Codex. The
working rules for code are in [AGENTS.md](AGENTS.md).

## Set up

1. Install [mise](https://mise.jdx.dev) (for example `brew install mise`) and
   [activate it](https://mise.jdx.dev/getting-started.html) in your shell.
2. From the repository root:

   mise install && pnpm install
   ```
   `mise.toml` pins Node, pnpm, Rust, gitleaks, actionlint, zizmor and cargo-deny, and
   `mise.lock` holds their checksums. `pnpm install` also installs the git hooks (lefthook).
3. `make gate` runs every check and prints one line. `make check` is the fast version for what
   you changed.

## Commits

Commits follow [Conventional Commits](https://www.conventionalcommits.org): `type(scope): subject`,
with a lowercase subject, for example `fix(daemon): close the database on shutdown`. The
`commit-msg` hook runs commitlint, and CI checks the pull request title the same way.

The scope is required and comes from this list:

| Scope       | Covers                                                      |
| ----------- | ----------------------------------------------------------- |
| `daemon`    | `apps/daemon`                                               |
| `desktop`   | `apps/desktop`, including the Tauri shell                   |
| `contracts` | `packages/contracts`                                        |
| `db`        | `packages/db`                                               |
| `harness`   | `packages/harness`                                          |
| `repo`      | root config, tooling, scripts, agent rules and `tests/repo` |
| `ci`        | `.github/` workflows and settings                           |

| `deps`      | dependency updates                                          |

## Pull requests

- Branch from `main` and open a pull request. Nobody pushes to `main`.
- Pull requests are squash-merged. The title becomes the commit on `main`, so it must be a valid
  Conventional Commit.
- Keep the squash dialog's commit subject as it is. GitHub fills it in from the title, which CI
  has checked, and lets whoever merges edit it; no rule can stop an edit there.
- Every required check must pass: `gate`, `desktop`, `policy`, `dependency-review` and
  `cargo-deny`. Resolve every conversation before merging. Nobody can bypass these, the
  maintainer included.
- A pull request also needs an approval from a code owner (`.github/CODEOWNERS`). The maintainer
  may merge his own pull requests without one, but only once every check passes.
- The checks run from the pull request's own workflows, so a change to `.github/`, the hook and
  commit configs, `mise.toml` or the agent rules can change what is checked. The code-owner
  review covers that for everyone else, and the maintainer reads those diffs in his own pull
  requests before merging.

## Signed commits

GitHub signs the squash merge on `main`, so signing your branch commits is optional but
encouraged. To sign with the SSH key you already use for GitHub:

```bash
git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub
git config --global commit.gpgsign true
```

Then add the same public key on GitHub as a **Signing key** (Settings, SSH and GPG keys).

Credit the tool with a trailer if you like, e.g. `Co-Authored-By:`.

The `integration_id` 15368 on each required check is the GitHub Actions App (`gh api apps/github-actions --jq .id`), so only a check run from a workflow satisfies it, never a commit status posted through the API. `scripts/github-settings.mjs`:
```js
#!/usr/bin/env node
// Applies .github/repo-settings.json and every .github/rulesets/*.json to this checkout's GitHub
// repository through the gh CLI: main-protection, main-review, tags-create and tags-immutable.
// Idempotent: rulesets are matched by name and replaced, and each setting is a PUT or PATCH of the
// whole value, so a second run changes nothing. Run it by hand (`make github-settings`) with admin
// rights; CI never runs it.
import { execFileSync } from 'node:child_process';
import { readdirSync, readFileSync } from 'node:fs';
import { join, resolve } from 'node:path';

const root = resolve(import.meta.dirname, '..');

/** @param {string} path */
const readJson = (path) => JSON.parse(readFileSync(join(root, path), 'utf8'));

/**
 * Calls `gh api` and returns the parsed response, or null when the body is empty.
 * @param {'GET' | 'POST' | 'PUT' | 'PATCH'} method
 * @param {string} path
 * @param {unknown} [body]
 */
function api(method, path, body) {
  const args = ['api', '--method', method, path];
  if (body !== undefined) args.push('--input', '-');
  const out = execFileSync('gh', args, {
    input: body === undefined ? '' : JSON.stringify(body),
    encoding: 'utf8',
  });
  return out.trim() === '' ? null : JSON.parse(out);
}

const repo = execFileSync(
  'gh',
  ['repo', 'view', '--json', 'nameWithOwner', '--jq', '.nameWithOwner'],
  {
    encoding: 'utf8',
  },
).trim();
const settings = readJson('.github/repo-settings.json');

api('PATCH', `repos/${repo}`, settings.repository);
if (settings.vulnerabilityAlerts) api('PUT', `repos/${repo}/vulnerability-alerts`);
if (settings.privateVulnerabilityReporting)
  api('PUT', `repos/${repo}/private-vulnerability-reporting`);
api('PUT', `repos/${repo}/actions/permissions/workflow`, settings.workflowPermissions);
api(
  'PUT',
  `repos/${repo}/actions/permissions/fork-pr-contributor-approval`,
  settings.forkPullRequestApproval,
);
console.log(`${repo}: repository, security and Actions settings applied`);

/** @type {{ id: number, name: string }[]} */
const live = api('GET', `repos/${repo}/rulesets`) ?? [];
for (const file of readdirSync(join(root, '.github/rulesets'))
  .filter((f) => f.endsWith('.json'))
  .sort()) {
  const ruleset = readJson(`.github/rulesets/${file}`);
  const id = live.find((r) => r.name === ruleset.name)?.id;
  if (id === undefined) api('POST', `repos/${repo}/rulesets`, ruleset);
  else api('PUT', `repos/${repo}/rulesets/${String(id)}`, ruleset);
  console.log(`${repo}: ruleset "${ruleset.name}" ${id === undefined ? 'created' : 'updated'}`);
}
```
