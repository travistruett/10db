# Focuses S1: show, For You, and the reasons

**Size: Feature.** One implementer builds it end to end, then one code review that blocks only on bugs. Spec:
`docs/superpowers/specs/2026-11-25-focuses-design.md`, which is the source for every shape named here.

## Brief

**What changes for you.**
- Settings › Focuses lists your focuses and this project's, starting from six starters: Migrations, Contracts
  and API, Prompts, Evals, Agent instructions and Dependencies.
- When a task's diff hits a focus, its drawer opens with **For You**: only those hunks, each file with the agent's
  reason and the reviewer's check. Its PR body gets a **For you** section.
- Loudness is **show** only in S1. Ask arrives in S2, and Hold in S5.

**What could go wrong, and how we'd know.**
- *A broken focus row stops a task.* Its detail is read with `safeParse` and degrades to "skipped".
- *Main's files show as this task's.* The base is read again after the gate; the e2e's diff would show it.
- *Agents ignore `focusNotes`.* The folds then show hunks with no Agent line, and nothing else breaks.

**Needed from you:** nothing beyond the spec's brief.

## Parts, in build order

1. **Contracts** (`packages/contracts/src/focuses.ts`, exported from the entry point):
   - `FocusLoudness`, `Focus`, `ProjectFocusEntry` (a `Focus` or `{ key, off: true }`), and `STARTER_FOCUSES`.
     Migrations and Dependencies reuse the stock hazards' globs, imported rather than copied.
   - `effectiveFocuses()`, `FocusNote`, `FocusDetail`, the `FocusHitsDto` route shape, and `EvidenceKind.Focus`.
   - `detail` moves out of `EvidenceBase` into each `EvidenceDto` branch.
   - `focusNotes` is optional on the `commit` and `complete_step` inputs and on `StepResult`. The commit tool's
     output echoes it.
2. **Storage** (`packages/db`):
   - `insertEvidence` stores `detail` for Focus as it does for Acceptance.
   - The Focus branch's `detail` schema is `FocusDetail.catch(...)`, so a bad row reads as
     `skipped: 'unreadable'` and never makes `parseRow` throw.
   - The focus settings accessors use the keys `focuses.you` and `focuses.<projectId>`, read through zod.
   - Project removal deletes the project's key.
   - No migration.
3. **Daemon matching** (`apps/daemon/src/focuses/`, with an `AGENTS.md` note):
   - `split-patch.ts`: unified diff → per-file `{ path, status, patch, clipped }`.
   - `match.ts`: the pure `matchFocuses(files, focuses)`, using `areaMatches`.
   - `hits-after.ts`: `focusHitsAfter(...)`. It re-reads `baseHead`, takes `diffOfRanges` at the focus caps,
     matches on numstat `files`, and gathers agent notes from the commit tool ops. Its sources are a
     `FocusHitSource[]` with one entry, the Evals hook.
4. **Runner wiring** (`runner.ts`):
   - Call `focusHitsAfter` in `verify` beside `acceptanceAfter`, and in `finishWithoutGate`.
   - Insert the row in the write that moves the run on, not on acceptance send-back.
   - The commit handler and the `complete_step` handler (`mcp/tools.ts`) store `focusNotes`.
5. **Briefs** (`briefing/prompts.ts`):
   - The build brief gets the overlapping focuses, or all of them when the task has no areas, plus the
     `focusNotes` instruction.
   - The Review and QA brief gets a Focus section from the newest row, on its first round, as acceptance does.
6. **PR body** (`delivery/pr-text.ts`, `ship.ts`):
   - `prBody` takes an optional `focus` input and renders "For you".
   - `ship.ts` builds that input from the PR's tasks' newest rows. It wraps the section in
     `<!-- 10db:for-you -->` markers, and when a later task joins the PR it replaces only the text between them,
     through `prEditBody`.
7. **Routes** (`api/app.ts`, `daemon/services.ts`):
   - `GET`/`PUT /settings/focuses`.
   - `GET`/`PUT /projects/:id/focuses`; the `GET` returns the effective list with `from` tags.
   - `GET /workstreams/:id/focus-hits`, which returns the newest row's detail with notes joined: agent notes from
     the commit ops, reviewer notes from the steps.
   - A glob-count endpoint, only if the hazard drawer's counter can't be reused.
8. **Desktop**:
   - Settings: `SettingsSectionKey.Focuses` under Planning after Areas and Hazards, with `focuses-section.tsx`
     (a DataTable in two groups, with a segmented loudness control where Ask and Hold are disabled) and
     `focus-drawer.tsx`, both modelled on the hazard section and drawer.
   - `views/board/task-for-you.tsx`: the first item in the Overview. It fetches the hits itself, as `TaskSkips`
     does, and refetches on `evidence.recorded`. It holds the folds, `HunkDiff` over `parseChanges(patch)`, the
     notes, and "Open the whole diff".
   - Match mock-ups 1, 1b and 2. A cheap layout choice is the implementer's call.
9. **Docs:**
   - `docs/architecture/db-storage.md` notes the new setting keys and the evidence kind.
   - An `AGENTS.md` sits beside `focuses/`.
   - The For You section is named in the drawer's `AGENTS.md`, if it has one.
