# 10db Go Public Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish 10db as the public GitHub repo `travistruett/10db`, with clean history, Conventional Commit messages from the first commit, every ruleset and repo setting applied, Renovate and the `10db-release-bot` App installed, and a first PR that passes every required check (spec §7 item 2).

**Architecture:** Each step is a local check or a one-way change to GitHub, run in a fixed order: scan the history, rewrite the history, create the repo and push `main` once, apply the rulesets, then install the two Apps. The rulesets have to come after the first push, because the `main-protection` ruleset blocks direct pushes. Every outward-facing step is gated: the agent stops, asks Travis the stated question, and continues only after a literal "yes". The plan adds no product code. Its one repo change is the `tags-create` ruleset's bypass actor, which lands through the first PR.

**Tech Stack:** git 2.50, git-filter-repo 2.47.0, gitleaks 8.30 (pinned in `mise.toml`), gh 2.83, jq, GitHub REST API (rulesets, environments, Actions secrets), Renovate (Mend GitHub App), GitHub Apps.

**Spec:** `docs/superpowers/specs/2026-10-14-10db-repo-governance-design.md` (§6 GitHub settings and community files; §5 the release bot and tags; §7 items 2 and 4; decision G11). Read §5–§7 before starting.

**Plan series:** `00-spikes`, `01-m0-scaffold`, `02-m1a-engine-core`, `03-m1b-sessions-and-ui`, **`04-go-public` (this file)**, `05-release`. Run this file after M0 has merged into local `main`, and before any branch is pushed anywhere.

## Review Focus

These are six failure modes that no automated test in this plan exercises, though a person going public would hit them. Each one has a check in the task that owns it.
1. **A stale branch still points at the old history after the rewrite**, e.g. `spec/factory-loop` or `feat/m0-scaffold`, and later gets pushed with the pre-rewrite commits. Every local ref must point into the rewritten history. The check is in Task 2, Step 6.
2. **The push is rejected with GH007 because the commit email is private.** GitHub's "Block command line pushes that expose my email" setting does this. The email in history must be one Travis has chosen to publish, and Task 1 Step 4 makes him choose before the push. The check is in Task 1, Step 4, and its remedy is in Task 2, Step 4.
3. **The ruleset's required check names don't match the check runs CI produces** (e.g. `ci / gate` against `gate`). PRs would then wait forever on "Expected" checks. The check is in Task 7, Step 3.
4. **`make github-settings` isn't idempotent.** A second run must change nothing. The check is in Task 4, Step 3.
5. **The tag rulesets don't do what they say.** A tag push from Travis must be rejected, because only `tags-create`'s bypass actor may create a `v*` tag. Once the bot is that actor, it must be able to create a `v*` tag, and neither the bot nor Travis may move or delete one: the bot's bypass is on `tags-create` only, and `tags-immutable` has none. The checks are in Task 4 Step 5 and Task 6 Step 7.
6. **The admin bypass also skips the required checks.** A bypass skips every rule in its ruleset, so only the split into `main-protection` (no bypass) and `main-review` (admin bypass) keeps the checks binding. A red PR whose workflows are unchanged must stay unmergeable even with `--admin`, and a green PR must merge with `--admin` and no approval. The checks are in Task 7, Steps 4 and 5. The residual is stated, not tested: a PR's checks run from the PR's own workflows, so a PR that edits `.github/workflows/` can turn its own checks green. The `integration_id` pin stops a hand-posted commit status from standing in for a check, and CODEOWNERS makes `.github/` and the hook and agent configs need Travis's review on anyone else's PR. On his own PRs (and agents', which use his `gh` login) Travis reads those diffs before an `--admin` merge, and the git guard asks before every `--admin` merge. A user-owned repo has no required-workflow or file-path rules that would close this fully.

- [ ] **Step 3: Grep the history for home paths, tokens, private repo details and forbidden files**

The repo stays project-agnostic: it never names Travis's private projects and repos. **[Travis]** First writes `~/10db-go-public/private-names.txt` with one private project or repo name per line, including any distinctive name built from one, such as a profile or tool name. That file is the only place the names are written. It stays outside the repo and never goes into a chat or transcript.

People other than Travis don't go in that file: a first name is often a common word, and every line there matches case-insensitively as a substring. If old commits name a person, **[Travis]** finds the exact phrases with `git grep -w` in a terminal, outside the agent's session, and writes them, one per line and in their exact case, to `~/10db-go-public/private-phrases.txt`, such as `for <Name>`. That file is optional; without it, no phrase is scrubbed.

Then write the filter that keeps the names and phrases out of everything the agent prints. It replaces each phrase, in exact case and longest first, with `<private phrase>`, then each name, in any case and longest first, with `<private name>`. It fails if the names file is missing or empty:
```bash
cat > ~/10db-go-public/redact.pl <<'EOF'
# Prints stdin with every private name (any case) and personal phrase (exact case) replaced.
sub patterns {
  my ($file, $required) = @_;
  open my $f, '<', "$ENV{HOME}/10db-go-public/$file" or do { die "no $file\n" if $required; return () };
  return map { chomp; quotemeta } grep { /\S/ } <$f>;
}
sub alternation { join '|', sort { length $b <=> length $a } @_ }
my @names = patterns('private-names.txt', 1);
die "private-names.txt is empty\n" unless @names;
my @phrases = patterns('private-phrases.txt', 0);
my $names = alternation(@names);
my $phrases = @phrases ? alternation(@phrases) : undef;
while (<STDIN>) {
  s/$phrases/<private phrase>/g if defined $phrases;
  s/$names/<private name>/gi;
  print;
}
EOF
touch ~/10db-go-public/private-phrases.txt
echo check | perl ~/10db-go-public/redact.pl
cat ~/10db-go-public/private-names.txt ~/10db-go-public/private-phrases.txt \
  | grep -c -E $'\r|^[[:space:]]|[[:space:]]$' || true
```
Expected: `check`, then `0`. Anything else means the names file is missing or empty, or a file has CRLF endings or stray spaces, which the filter and the greps would miss; stop until Travis has fixed it.

Each command searches every blob in every commit and prints `path:line:text`, de-duplicated. `scan.txt` holds the raw output for Travis; the agent only ever prints it through the filter:
```bash
cd ~/Projects/10db
{
echo '== home paths'
git grep -I -n -E '/(Users|home)/[A-Za-z][A-Za-z0-9._-]+' $(git rev-list --all) -- . \
  | cut -d: -f2- | grep -v -E '/home/runner/' | sort -u
echo '== tokens'
git grep -I -n -E 'sk-ant-[A-Za-z0-9_-]{8,}|gh[pousr]_[A-Za-z0-9]{20,}|github_pat_[A-Za-z0-9_]{20,}|AKIA[0-9A-Z]{16}|xox[abposr]-[A-Za-z0-9-]{10,}|-----BEGIN [A-Z ]*PRIVATE KEY-----|eyJ[A-Za-z0-9_-]{10,}\.eyJ[A-Za-z0-9_-]{10,}' \
  $(git rev-list --all) -- . | cut -d: -f2- | sort -u
echo '== private accounts'
git grep -I -n -i -E 'AWS_PROFILE|sso_start_url|arn:aws:|\b[0-9]{12}\b' $(git rev-list --all) -- . \
  | cut -d: -f2- | sort -u
echo '== private names, in history'
git grep -I -n -i -F -f ~/10db-go-public/private-names.txt $(git rev-list --all) -- . | wc -l
echo '== private names, in commit messages'
git log --all --format=%B | grep -c -i -F -f ~/10db-go-public/private-names.txt
echo '== personal phrases, in history and commit messages'
if [ -s ~/10db-go-public/private-phrases.txt ]; then
  git grep -I -n -F -f ~/10db-go-public/private-phrases.txt $(git rev-list --all) -- . | wc -l
  git log --all --format=%B | grep -c -F -f ~/10db-go-public/private-phrases.txt
else
  echo 0; echo 0
fi
echo '== private names, in the main tree'
git grep -I -n -i -F -f ~/10db-go-public/private-names.txt main -- .
echo '== emails'
git grep -I -h -o -E '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}' $(git rev-list --all) -- . \
  | grep -v -E '@10db\.invalid$|^noreply@anthropic\.com$|@users\.noreply\.github\.com$|@example\.(com|org|net)$|@[0-9]+x\.png$' \
  | sort | uniq -c | sort -rn
echo '== files that must never be committed'
git log --all --format= --name-only | sort -u | grep -E '^(scratch/|\.claude/settings\.local\.json$|\.env)'
} > ~/10db-go-public/scan.txt 2>&1
perl ~/10db-go-public/redact.pl < ~/10db-go-public/scan.txt
```
Pass criteria, per section:
- **home paths:** no lines. Test fixtures such as `/Users/x` and `/Users/b` don't match, because the pattern needs at least two characters. Any line that does print gets scrubbed in Task 2 Step 3. A hit from the spikes plan or the governance spec §7 item 4 is expected if M0 committed them unscrubbed.
- **tokens:** no lines. A hit is handled like a gitleaks finding (Step 2).
- **private accounts:** every value assigned to `AWS_PROFILE` is a placeholder such as `x`, `dev` or `example-profile`. Lines that only mention the variable, such as this plan's own grep, pass. Old lines that print `<private name>` are counted in the next section and scrubbed in Task 2. A line fails if it carries a real account detail: an AWS account or profile name, an SSO start URL, an ARN, or an internal hostname. Twelve-digit numbers are failures only if they are AWS account IDs.
- **private names, in history:** a count, not the lines. Any count above zero means old commits still name a private project, and Task 2 Step 3 scrubs them.
- **private names, in commit messages:** `0`. A non-zero count means a message names a private project; Task 2 Step 4 variant 2 scrubs messages too.
- **personal phrases, in history and commit messages:** two counts. Any count above zero is scrubbed in Task 2 Step 3, in exact case.
- **private names, in the main tree:** no lines. The tree on `main` is already agnostic, so a hit there is a new leak to fix before going public.
- **emails:** no lines. Each remaining address is either removed or added to the allowed list in this step, after Travis approves it.
- **files that must never be committed:** no lines.
