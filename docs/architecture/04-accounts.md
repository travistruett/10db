# 04 Accounts

- **Status:** Locked
- **Scope:** Who pays for each project's sessions: accounts, how a session proves it runs on its account, per-account concurrency, pauses and monthly caps, usage, moving a project between accounts with work in flight, and how agents are kept from credentials.
- **Summary:** The design is `docs/superpowers/specs/2026-10-17-10db-accounts-design.md`, with spike 12's findings in `docs/architecture/research/spike-12-accounts.md`; its decisions and the plan's are rows 105–118 of `decisions.md`. Changes are new rows that name what they supersede.

## Invariants

- An account keeps no model map. The models it can run are its own list (what its agent reports) joined to the catalogue, and its settings hold `tierOverrides` (a model ID per tier, absent for Automatic) and nothing else about models. The drawer shows one dropdown per tier from the account's list, or a text field per tier for a gateway that reports none; an override the list lacks or has marked unusable gives way to the tier's automatic choice. The launcher sets no variable that names a model. The decision is `decisions/2026-11-07-models-come-from-a-catalogue.md`.
- A session sends its prompt only after `accountInfo()` matched the account's identity and credential kind; a mismatch pauses the account with a card and sends nothing. A model mismatch fails the workstream, not the account.
- The default account runs on the builder's own login (the login shell's `CLAUDE_CONFIG_DIR`, else Claude Code's default directory); every other account, keyed kinds included, runs on its own config directory under the data directory.
- An unready account (no confirmed identity, no secret) is prepared, never refused: its work waits `QUEUED`.
- A keyed account's secret is read from the Keychain at every start and must match the fingerprint 10db recorded; it is never in the database, a log, an event, a card or a response.
- An account's lanes, usage limits and monthly cap apply only to that account; a capped or refused account lets running sessions finish.
- The gate and the repo's MCP servers never get an account's credentials.
- Nothing billing-related comes from the login shell.
- On a subscription account, sessions start one at a time until the refresh question in `open-questions.md` is answered.
- A project is on exactly one account at a time. A move applies at each lane's next session; no lane resumes a conversation from another account's config directory, it starts fresh from its latest handoff.
- Nothing moves a project without the builder except its own fallback, which must be ready, and capped when metered; a project with no work in flight never moves on its own; the way back is always the builder's choice.
- A `codex_signin` account is not metered (`costUsd` stays null, no monthly cap). Its home is `<dataDir>/accounts/<id>/codex`, mode 700, with a login Codex wrote and 10db never reads, copies or stores. Its identity is the email and the workspace together, so a sign-in to another workspace on the same email is refused. A sign-in whose usage read names no workspace matches nothing: at Confirm the probe fails and the account shows a sign-in card, and a session start refuses it (`account_refused`, an identity mismatch with no identity seen), never matching it on the email alone.
- A Codex session sends its prompt only after the start checks passed: the checkout pinned `untrusted` in the home before `thread/start`, the account and workspace matched, no project config layer, the guard hook trusted and enabled at a timeout no shorter than 10db's, and the `lane` profile and model confirmed. Any failure ends it with `sandbox_refused` or `account_refused`, except an account that can't be read: the usage read is asked up to three times, 2 s apart, after no answer or a server error, and an account still unread ends the start with `error`, which the runner recovers from, unless `codex login status` says the home is signed out, which waits for its sign-in.
- A Codex launch strips `OPENAI_API_KEY`, `CODEX_API_KEY`, `OPENAI_BASE_URL`, `CODEX_ACCESS_TOKEN` and `CODEX_HOME`, and the home forces `forced_login_method = "chatgpt"`.
- Connect signs an account that signs in with a login (`claude_subscription` or `codex_signin`) in from the drawer (`POST /accounts/:accountId/connect` answers `{accountId, authUrl}`; `DELETE` cancels). Both kinds share one daemon-wide slot, the same `account.login_ended` event and the same Cancel; the routed adapter's `startLogin` picks the agent by account kind. The agent writes the login into the account's own directory; 10db never reads, copies or stores it and sees only whether the sign-in finished. The end reaches the UI as an `account.login_ended` event (`accountId`, `ok` and a fixed message, never what the agent printed), and the UI then runs the identity check itself, so Confirm is the next step. The Terminal command stays as a fallback behind "Sign in from Terminal instead". Neither an address nor anything the agent printed is logged. A second start, of either kind, is a conflict naming the account already connecting, and `GET /accounts/connecting` reads the slot (`{accountId, label}` or null), so any drawer, a later one and one after a daemon restart included, shows which account is connecting and offers its Cancel; screens are refused that read. A sign-in replaces the login sessions run on, so Connect is refused while a lane runs on the account (a lane counts on the account of its live session, so one still running after its project moved holds the account it started on), the scheduler starts nothing on an account whose sign-in is under way, and the drawer asks for a confirming click before it replaces the default account's login. A cancel that arrives while the agent is still starting is kept and honoured the moment it has started. The sign-in's end event says whether the builder asked for it (`cancelled`), which the UI does not show as an error. The daemon's shutdown tells a sign-in under way to end at once, in step with the lanes, and waits for its process before the database closes; the builder is told it was cut short, not that they cancelled. Each agent process is stopped with SIGTERM and the slot is freed only after it has exited, or after 2 s and a SIGKILL, so the next sign-in finds the callback port and the login files free.
  - **Codex.** The daemon starts `codex app-server` with the account's launch environment (the one the identity check uses: the account's `CODEX_HOME`, API keys stripped), sends `account/login/start` with `{type: 'chatgpt'}` and answers the `authUrl`, accepted only as `https` on `auth.openai.com` (the desktop opener allows that host, GitHub and Artificial Analysis's site, nothing else). The app-server stays up until `account/login/completed` names the same `loginId`, a cancel, the process exiting or ten minutes on the injected clock, and is stopped on every end. Codex listens for its callback on fixed local port 1455, which is why only one sign-in runs; a port-in-use failure is a readable conflict. Built and tested against a fake app-server. A live Codex 0.154.0 confirmed that `account/login/completed` carries the `loginId` the start returned, and that a cancel frees port 1455 within 500 ms; it ends a cancelled login with a completion of its own (success false), which the daemon ignores in favour of the cancel. The exact text of a port-in-use error has not been observed.
  - **Claude.** The daemon runs `claude auth login --claudeai` (the `claude` the daemon resolved, never the login shell's `PATH`) on the account's launch environment, with no stdin and its output dropped. That CLI opens the browser itself and names no page, so `authUrl` is null and the UI only shows the waiting state. Exit 0 is a finished sign-in, any other end a failure; Cancel kills the child and so does the ten minute deadline. The default account's environment leaves `CLAUDE_CONFIG_DIR` unset, as its sign-in command does. Built and tested against a fake process; how `claude auth login` behaves with no terminal and no stdin (it may wait for a pasted code) has not been observed, so a hang ends at the deadline or on Cancel, and the Terminal fallback remains.
- Brainstorm chat is refused while a project's account is a ChatGPT account. The decisions are `decisions/2026-11-05-chatgpt-plan-through-the-codex-app-server.md` and `decisions/2026-11-05-codex-lanes-use-codex-sandbox-and-hooks.md`.

## Known and accepted

- Right after a move, the old account's lane count drops while its sessions still run, so another project can briefly run more lanes there than its `laneCap`, until those sessions end.
- Claude Code reports usage short of the limit only for subscription accounts, so the usage threshold moves a project early only from a subscription; a keyed account moves its projects at the hard limit.
- A lane that moves starts fresh from its latest handoff: context that was neither committed nor handed off stays behind (open question: carrying the conversation across accounts).
- A paused revise or uncommitted session that moves to another account, or resumes after a failed resume, loses its instruction; the review notes still appear under Earlier steps.
- A move-back card answered Later is asked again after a restart. When a reset time was reported and it has passed, the move back fires at restore; when none was reported, each restart restarts the move-back wait.
- Three records live in memory, so a restart can repeat a card once: the projects an account's current pause has carded (a project can be carded once more), the usage threshold crossings already acted on (the builder can be asked once more) and the projects given a cap card (a dismissed cap card returns once).
- A high usage report whose reset time is already past, from clock skew near a window boundary, counts as a new crossing until the window rolls.
- What a session can and cannot reach, and what keeps it from other accounts' credentials, is `03-trust-boundaries.md`. The lane sandbox is built and the guard's Keychain, environment and shell-text path rules are gone (`decisions/2026-11-01-guard-drops-shell-text-credential-rules.md`). The parked Task 7 findings are recorded there: Task 7R fixed some, and the rest are moot.
